# PvP 匹配与对战验收

日期：2026-10-28。

## 环境与范围

使用真实游戏代码、HTTP 接口、匹配器及战斗引擎；运行在本机 8082 的独立 H2 内存库，关闭世界经济 Tick、机器人与邮件发送。页面通过 8085 的临时代理访问；代理仅调整验收页面的 API/WebSocket 入口，没有修改正式前端的大区配置。

创建 pvp_alpha、pvp_bravo、pvp_charlie、pvp_delta 四个达标账号和 pvp_locked 低声望账号。达标账号声望均为 10000，步兵均为 1000，初始化资源、科技和军衔一致。城市通过游戏初始化逻辑分配，不写死重叠坐标。账号仅存在本轮内存库，不修改原 wargame 数据库。

## 发现并修复

1. **服务端未校验声望准入。** 页面要求声望 10000，原接口允许声望 0 的账号直接入队。编队保存和匹配接口现返回 HTTP 403 / PVP_PRESTIGE_REQUIRED；大厅仍可预览，已入队账号仍可查询与取消。
2. **入场确认失败后不再补报。** 原页面每个会话仅尝试一次 loaded；短暂请求失败可能耗尽 20 秒入场窗口。现在加载阶段保留状态轮询，按轮询间隔查询并补报，未确认的写入仍保留原请求人工确认机制，避免即时重试循环。
3. **填满上限漏分配余数。** 原算法把舍入余数留给最后一个兵种，最后兵种无库存时无法填满。现复用比例分配和余数补齐逻辑，同时更新输入框。

## 实战结果

HTTP 全流程共 20 项通过，详见 http-summary.json / http-acceptance.log：

- 单人排队不会生成虚假对手；可正常取消。
- 相同阵容实力估值一致；双方进入同一待确认场次。
- 确认前不能读取对手阵容；非参战账号不能读取战场。
- 对手拒绝时，已接受方重新排队并保留最初等待起点。
- 单方不加载时按真实 20 秒期限作废，不计胜负。
- 双方加载后统一倒计时；双方自己的底线都显示在左侧。
- 草稿版本递增；单方锁定不推进；相同请求重放保持幂等。
- 人工指挥完成 24 回合，保存交火事件，回合无重复结算，双方胜负相符。
- 默认托管完成 24 回合；认输判负，对手判胜，重复提交不重复结算。
- 对比资源、兵力、军官、建筑、道具、声望、军衔和人口均不变。军衔面板 serverTime 是响应时间，比较时排除；没有发现真实扣兵或扣资源。

浏览器双账号另完成：大厅编队 → 匹配 → 双方确认 → 自动加载 → 手动待命/锁定 → 刷新恢复 → 默认托管 → 24 回合平局 → 双方复盘。初始双方各 1000 步兵和 1 卡车，实际兵力损失 0；截图为 browser-report.png。验收时一次托管操作跨过回合截止，接口正确拒绝旧回合，重新同步后正常启用。
