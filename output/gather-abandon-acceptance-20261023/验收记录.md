# 手动废弃野地验收

日期：2026-10-23。结论：采集中及已收获但未下达回城命令时，服务端均拒绝废弃，不会丢失部队、货物或野地归属；驻军与独立采集队的前端入口不一致，已收获状态的错误提示不准确。本轮未修改业务代码。

## 实测方式

使用当前前端源码、当前编译后端和真实 HTTP/WebSocket，在独立本机 H2 库准备虚构玩家与两块已占领资源野地。前端 8083，后端 8082，仅监听本机，不访问原游戏数据库。通过正常派遣接口创建 100 名步兵进驻炼铁厂 (12,10)、2 辆卡车采集粮田 (13,10)，保留正常行军和采集计时。

## 接口回归

运行 `MAVEN_OPTS='-Dfile.encoding=UTF-8' mvn -f backend/pom.xml -Dtest=WildAbandonTest test`，6 项全部通过。

- 驻军与独立采集队在未采满、收获后待命时均返回 HTTP 400，错误信息如上。
- 拒绝前后的野地、驻军、行军、军官与库存序列化快照完全一致。
- 独立采集队在去程中同样阻止废弃；切换城市无法绕过拦截。
- 已下达回城命令且资源已经结清的返程允许手动废弃，军队、货物正常抵达并准确入库；历史未结清返程仍阻止释放。
- 另一块野地上的采集任务不会阻止废弃当前空地。

## 发现的交互问题

1. 两类采集流程入口不一致：驻军隐藏放弃，独立采集队仍显示可点击的放弃按钮，用户确认后才得到错误提示。
2. 已收获并待回城时仍提示“有部队正在采集”，与实际状态不符。此时真正的限制是尚未下达回城命令。
3. 废弃确认框使用通用提示，仅称恢复中立；通用函数在有驻军时还会补充“驻扎的部队将自动撤回主城”。当前驻军采集及已收获页面不会打开这个确认框，因此不能把该文案当成这两个阶段实际可执行的行为。

仓库余额同时受正常生产和粮耗影响，页面验收不将不同时刻的余额差直接等同于收获量；准确入库由接口回归的关闭调度场景断言。

验收收尾：独立测试后端、前端及状态采样进程均已停止，8082、8083 均无监听进程；测试页面已关闭。
