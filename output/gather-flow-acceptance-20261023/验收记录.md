# 手动采集完整流程验收

验收日期：2026-10-23。结论：当前代码在独立本机 H2 环境中，两条采集流程均可走通；本轮未修改业务代码。

## 环境与方式

使用项目当前编译代码、当前前端源码、真实 HTTP/WebSocket 和实际页面按钮，创建虚构验收账号。隔离后端为本机 8082，前端为 8083；前端仅将 API/WebSocket 端口指向验收后端。未修改现有游戏账号或游戏数据库，未缩短行军或采集计时。

## 浏览器实测

| 场景 | 实际操作及结果 |
| --- | --- |
| 新资源野地 | 选择未占领的粮田 (13,10)，资源 10000；派出 100 名步兵征服，并选择原地驻守。实际行军后成功占领，部队留守，没有自动开启采集。 |
| 驻军采集入口 | 野地详情展示剩余资源 10000、驻军和“采集”按钮。点击后出现手动采集确认，确认后才开始。 |
| 驻军采满 | 本队负重 1000，30 秒采满后数量停止增长；仍显示“收获”，没有自动收获或回城。 |
| 驻军收获 | 手动点击“收获”，当前弹窗立即展示“已收获 1000、剩余资源 9000”，进度条隐藏，按钮切换为“部队回城”。 |
| 驻军回城 | 点击“部队回城”并确认撤回，部队原路返城；抵达后归还 100 名步兵并结算货物，野地仍归本人、余量 9000。 |
| 派兵采集 | 在独立重置的正常测试数据中，从余量 9000 的己方粮田派出 2 辆卡车，负重 1000，单程 14 秒；页面确认出发后抵达采集。 |
| 派兵采满 | 实际等待 60 秒采满，并额外等待多次后台结算，任务仍为采集中、进度 100%、未返程，等待玩家点击收获。 |
| 派兵收获 | 手动收获后，弹窗立即展示“已收获 1000、剩余资源 8000”，按钮切为“部队回城”。等待期间任务仍原地留守，货物不增长、不提前入库。 |
| 派兵返城 | 玩家手动点击“部队回城”；军情显示原路 (13,10)→(10,10)、2 兵力、携带 1000 粮食。抵达后卡车从 8 恢复至 10、行军任务清空、资源入库，野地仍为本人占领且余量保持 8000。 |

页面与接口状态互相核对。仓库余额同时受正常粮耗影响，因此不将两个不同时间点的仓库余额差直接当作收获量；精确入库数量另由后端回归测试验证。
