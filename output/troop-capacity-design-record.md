## 二、攻击与迎战公式

设基础上限为 B、当前城市围墙奖励为 W、该城已任命指挥官的三军统帅等级为 L：

~~~text
攻击出兵上限 A = floor((B + W) × (1 + 0.04 × L))
各类加成合计 = A - B
出城迎战上限 S = 1.5 × B + (A - B) = A + B / 2
~~~

- 只有当前城市围墙达到满级 Lv.10 时，W 才为 100,000；Lv.0—9 为 0。
- 三军统帅最高 Lv.5，即对「基础上限 + 围墙奖励」提供 20% 加成；未任命指挥官时不计该加成，历史 supply 技能继续兼容。
- 迎战的 1.5 倍仅作用于军衔基础，围墙和三军统帅加成不再乘以 1.5。
- 市政厅、参谋部、指挥官等级与军官后勤属性不直接增加容量。
- 攻击按出发城市计算；迎战按被攻击城市计算，不能借用另一座城市的围墙或指挥官加成。
- 实际派兵还受各兵种当前可用驻军数量限制，服务端负责校验。

| 列兵，无加成 | 25,000 | 0 | 0 | 25,000 | 37,500 |
| 少校，无加成 | 300,000 | 0 | 0 | 300,000 | 450,000 |

| 上将，满级加成 | 600,000 | 100,000 | 5 | 840,000 | 1,140,000 |

## 三、战术页面迎战编队

1. 战术页将每个兵种的驻军、迎战数量滑动条与数字输入、出城行动和守城行动合并展示，只显示一份兵种列表。桌面同一行排列，窄屏在同一兵种内依次排列兵种信息、迎战数量及并排的攻守行动；顶部集中显示当前城市迎战上限、自动选兵开关、配置总量与剩余额度。详细规则默认折叠，点击展开查看。关闭自动选兵后可手动编辑数量，统一点击「保存默认战术」后持久化。
2. 默认开启自动选兵，在战斗开始时按驻军比例分配兵力，不超过迎战上限。开关下方直接展示简例：城内有步兵 6 万、坦克 4 万，迎战上限 5 万时，派步兵 3 万、坦克 2 万，其余留城；驻军未超过上限时全部迎战。
3. 手动配置中未填写的兵种视为 0；全部设为 0 时不派野战部队，仅现有工事参加防守。
4. 配置为账号级，由各城共用。开战时先按各兵种的实际驻军截断；若因换城、加成变化等原因仍超限，再按比例缩减，整数余数按兵种 ID 顺序分配。
5. 保存时拒绝未知兵种、负数、小数、无效数值及超过当前城市迎战上限的配置。
6. 迎战部队使用守城默认行动；主动出征仍在出征页面选择部队。在线指挥和离线防守共用迎战配置。
7. 工事不占迎战名额。战损只扣除实际参战损失，未参战驻军与战斗期间新增的驻军、工事保留。
8. 已开始的战斗沿用开战快照，修改迎战编队从下一场战斗生效。

### 滑动选兵与总量联动

- 单兵种可选上限 = min(该兵种当前驻军, 当前城市迎战上限 − 其他已选兵种数量合计)。滑动条和数字输入使用同一规则，数字输入超额时立即截断，非法数字恢复上一有效值。
- 拖动或输入时，两种控件的数量、其他兵种上限、总量与剩余额度即时同步，不重新渲染整页。减少某兵种数量后释放额度；无驻军或无剩余额度且未选兵的兵种滑动条禁用。
- 滑动条复用军队 Tab 的 recruit-slider-wrap / recruit-slider 共用样式，轨道、圆形滑块、描边、悬停与禁用状态随系统主题保持一致；已选进度随数量和可选上限实时更新。
- 例如城内步兵 600,000、火箭 400,000，共 1,000,000，当前防守迎战上限为 400,000：选择步兵 300,000 后，火箭最多选择 100,000；如果步兵改为 200,000，火箭最多可选 200,000。未参战的 600,000 留在城内，不因本场迎战战损被扣除。400,000 仅为示例，上限仍按军衔和城市加成动态计算。
- 打开账号预设或驻军、城市上限变化时，先按该城驻军截断，再按比例缩减超额编队；整数余数按兵种 ID 顺序分配，原本为 0 的兵种仍为 0。界面提示草稿已调整，只有点击保存才覆盖账号预设。
- 如果保存前才发现驻军或上限下降，则先同步调整表单，并在同一次点击中保存当前可见的迎战数量和攻守行动；服务端继续校验总量，开战时再次按被攻击城市实时驻军和上限选兵。

## 四、接口与数据兼容

- GET /api/game/army/battle-defaults 返回 outgoing、defending、sortieArmy、sortieCap。
- POST /api/game/army/battle-defaults 同时保存完整攻守战术与迎战编队。
- 老版后端只接受 outgoing、defending 两个字段，拒绝新增 sortieArmy 时会提示「请同时提交出城和守城的默认战术」。本机 8080 后端已于 2026-09-27 重启并执行 V51–V55 迁移，user2 当前表单（手动迎战步兵 50）已一次保存成功，刷新后仍回显 50。新版接口经 GET→修改整表→POST→GET 回读测试验证通过。
- sortieArmy 为 null 表示自动选兵；空对象表示手动配置但不派野战部队；其他对象按兵种 ID 保存数量。
- [V55 迁移](../backend/src/main/resources/db/migration/V55__sortie_army_preferences.sql) 为 players 新增 nullable TEXT 字段 sortie_army。老玩家默认自动选兵，不重置驻军及攻守战术。
- 军衔基础数值来自代码常量，不需要额外修改玩家军衔数据。其他环境部署后端时仍需执行 V55，并刷新前端资源。
