# 山河战友与隐私设置

更新于 2026-10-17。本文描述“聊天”页内山河战友功能、好友关系、分组、黑名单和防骚扰设置的当前实现。

## 功能范围

“山河战友”作为聊天页的独立入口，提供好友列表、好友申请、玩家搜索、玩家资料弹窗、自定义分组、好友关系管理和账号隐私设置。资料弹窗从好友列表、申请列表和搜索结果进入，并根据当前关系显示可用操作：添加好友、删除好友、发起聊天、清空会话内容、拉黑或解除拉黑，以及移动好友分组。

好友、分组、申请和隐私设置均以当前登录账号为主体。客户端只提交目标玩家 ID 或分组 ID，服务端从登录会话取得操作人，并校验目标账号和资源归属。

## 数据模型

| 数据 | 说明 |
| --- | --- |
| `friend_contacts` | 每个账号对每个玩家最多一条联系人记录，分别保存是否为好友、所属分组和当前账号的拉黑状态 |
| `friend_groups` | 仅保存自定义分组；固定分组“我的好友”不建行 |
| `friend_requests` | 保存待处理好友申请；处理、拒绝或撤回后删除 |
| `players.friend_request_policy` | 接收方好友申请权限，取 `APPROVAL`、`ANYONE` 或 `NONE` |
| `players.block_stranger_messages` | 是否屏蔽陌生人私信 |

好友双方各有一条联系人记录，分组和拉黑状态互不共享。`group_id = NULL` 表示“我的好友”。自定义分组名称为 1 至 20 个可见字符，每个账号最多 20 个，不能使用“我的好友”或“黑名单”名称。

## 好友申请状态流转

1. 玩家搜索目标并从资料弹窗发起申请。
2. 接收方为 `NONE` 时直接拒绝；为 `ANYONE` 时立即建立双方好友关系；为 `APPROVAL` 时保存待处理申请。
3. 接收方可以同意或拒绝，发送方可以撤回。只有申请接收方可以同意，申请当事人可以拒绝或撤回。
4. 同意后双方各生成一条好友联系人记录，发送方指定的分组生效，申请记录删除。
5. 申请按双方和按发送方设置冷却，避免短时间重复申请骚扰；黑名单会取消双方待处理申请。

好友删除会同时解除双方好友关系，但保留联系人可见的黑名单状态和已有私聊历史。拉黑不会删除好友关系；解除拉黑后，原好友关系仍可用。非好友也可以先拉黑，解除后无好友关系的空联系人记录会清理。

## 隐私设置与私聊权限

玩家可在“隐私设置”中自主设置：

- **好友申请权限**：需要同意申请（默认）、允许直接添加、拒绝好友申请。
- **屏蔽陌生人私信**：打开后只允许好友发送私聊。

任一方拉黑都会阻止双方私聊发送。陌生人私信开关只影响私聊发送，不影响世界聊天、军团频道和系统消息。设置按账号保存，服务端在好友申请和私聊发送时再次校验，不能只依赖前端开关。

## API

路径前缀：`/api/game/friends`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/` | 当前账号的分组、联系人、好友申请和隐私设置 |
| GET | `/search?query=…` | 按完整玩家名或玩家 ID 搜索玩家 |
| GET | `/{peerId}` | 查看玩家资料及当前关系状态 |
| POST | `/{peerId}` | 添加好友或提交申请，正文可带 `{groupId}` |
| DELETE | `/{peerId}` | 删除好友关系 |
| PUT | `/{peerId}/group` | 移动好友到指定自定义分组或默认分组 |
| POST | `/{peerId}/block` | 拉黑 |
| DELETE | `/{peerId}/block` | 解除拉黑 |
| POST | `/groups` | 新建自定义分组 |
| PUT | `/groups/{id}` | 重命名自定义分组 |
| DELETE | `/groups/{id}` | 删除自定义分组 |
| POST | `/requests/{id}/accept` | 同意好友申请 |
| DELETE | `/requests/{id}` | 拒绝或撤回好友申请 |
| PUT | `/settings` | 保存好友申请权限和陌生人私信屏蔽开关 |

私聊的发起、发送、删除和清空接口仍归 `/api/game/chat/private`，详见 [玩家私聊设计](PRIVATE_CHAT_DESIGN.md)。好友资料弹窗中的“发起聊天”和“清空会话内容”调用对应私聊接口。

## 前端交互

好友页默认展开“我的好友”，另列出自定义分组、好友申请和黑名单。点击玩家条目打开资料弹窗；资料弹窗根据关系状态禁用不可用操作，并在删除、拉黑、清空和分组修改后刷新好友与私聊列表。好友搜索支持玩家名和 ID，申请提交后显示待处理状态。隐私设置保存后重新打开仍读取服务端值。

## 迁移与验证

`V100__friends_and_chat_clear.sql` 创建 `friend_groups`、`friend_contacts` 和 `friend_requests`，为 `players` 增加 `friend_request_policy` 与 `block_stranger_messages`，并为 `private_chat_conversations` 增加 `cleared_through`。默认值分别为 `APPROVAL`、`FALSE` 和 `0`，已有账号升级后不建立虚假的好友关系。

专项验证覆盖好友列表与默认分组、自定义分组、申请同意／拒绝／撤回、资料弹窗、添加和删除好友、黑名单、隐私设置、陌生人私信拦截，以及清空会话只影响当前账号的历史边界。部署时由 Flyway 执行迁移；后端运行实例需要重启后加载新增好友接口和迁移。
