# 核心计算统一到服务端

日期：2026-10-31。对应修复前的 [前端计算审计](FRONTEND_CALCULATION_AUDIT_20261031.md)。

## 权威边界

前端提交对象 ID、数量、选择及操作意图；目录、费用、收益、属性、效果、资格、容量和工期来自后端。正式操作在事务内读取当前数据库并重新校验、计算与结算，不能提交预览中的费用、奖励或 `allowed` 改变资产。

完整状态的 `gameplay` 由 `GameplayViewService` 提供，含规则版本、城市范围、目录和预览。周期状态只推送随时间、余额和人口变化的数据；建筑、科技、任命等结构变化后刷新完整状态，客户端保留服务端目录。前端 `gameplay-rules.js` 统一读取快照及请求预览，缺失数据不重建业务公式。

## 覆盖范围

| 能力 | 当前数据来源 |
| --- | --- |
| 资源、粮耗、人口、税率、安抚、人口令 | 经济、粮账与人口服务；状态包含容量、速率、税率档位及道具收益 |
| 建筑、拆除、科研、施工队与区域名额、前置条件 | 建造、科研与前置服务；报价复用正式费用和工期函数，包含 VIP 加速和队列限制 |
| 招兵、训练通道、队列、人口成本、最大可招数 | 军队服务；训练速度使用原始通道计算，数量预览读取服务端 |
| 城防、城墙、伤兵、战俘 | 城防、战斗、医疗和战俘服务；报价包含费用、有效容量与可处理数量 |
| 军官经验、培养、加点、招募、赏赐、技能学习、岗位效果 | 军官与经验规则；状态返回所需经验、允许加点空间、费用及资格 |
| 军官装备、套装、换装净收益 | 后端装备目录和属性计算器；前端只选择装备方案 |
| 带兵上限、同时行军上限、动员 | 军队、行军与动员服务；前端读取有效上限及构成 |
| 随队军官与默认战术锁定 | 统一后端资格规则；快照提供 `officers[].dispatch` 与 `gameplay.battleDefaultsLocked` |
| 行军路线、时间、油耗、负重、拦截部署、加速与计谋 | 路线和行军服务；加速快照、预览和正式执行共用资格及截止时间 |
| 野地采集 | 后端返回采集量、负重和剩余资源；前端倒计时不增加已得资源 |
| 交易、商城、限购、护盾与限时道具 | 市场、商城、道具服务统一目录、报价与有效限制 |
| 战斗射程、速度、技能窗口、胜负、伤亡归因 | 战斗快照与持久化战报；历史缺失数据标记未记录，不从日志反推战果 |
| VIP、聊天及晋升领取资格 | 后端有效状态与领取记录；前端只展示和提交领取意图 |

旧战役没有服务端执行或进度存储接口，现按后端状态显示为浏览资料，实际战斗通过世界地图派遣。旧野地页不再展示不存在的“20×等级/小时”自动收入，只显示后端剩余资源并说明需派兵采集。

已删除客户端扣资源、加经验、随机成长、加声望以及本地创建拦截行军的旧结算分支。前端保留数字格式化、筛选排序、选择数量、进度条、服务器截止时间倒计时、地图投影、路线动画和伤害显示精度处理。

## 预览契约

`POST /api/game/preview` 受现有账号认证和城市所有权校验保护。

```json
{"action":"recruit","id":"infantry","count":10}
```

支持 `recruit`、`heal`、`prisoner`、`experience`、`equipment`、`timedItem`、`mobilization`、`exchange`、`shop`、`warTiming`。行军路线和行军道具沿用专用预览接口。

预览响应包含 `rulesVersion`、`serverTime`、`cityId`、`citySlot` 和输入摘要；接口不扣费、不改库存。对象预览校验账号及城市归属，数量拒绝负值、越界值、小数和整数溢出。浏览器合并同一意图的在途请求；状态更新后清除缓存，切城、切服或换号后拒绝旧响应。

所有迁移脚本使用统一缓存版本，防止旧前端公式与新后端协议混用。原有页面测试改用后端真实导出的固定快照，不在测试工具中另建业务计算器。
