# 手机二维战略地图实施方案

状态：实施前归档。

## 目标
将 200×200 世界地图升级为可单指拖动、惯性移动、双指缩放的二维平面地图。保留蓝白界面、坐标搜索、目标筛选、回主城和现有出征流程。

## 展示与架构
- PixiJS 渲染地图、图标和行军路径；HTML 呈现搜索、筛选、详情和操作。资源随项目本地交付，避免运行时依赖第三方 CDN。
- 镜头坐标仅为本地浏览状态，不能调用移动接口或改变实际出征起点。
- 底部详情卡按稳定的目标类型 + ID 绑定；接入侦察、征服、掠夺、采集。保留列表模式。
- 视野裁剪：只绘制屏幕附近目标；缩小时减少名称、等级标签。

## 数据加载
- 固定区域块（首版 16×16 格），屏幕区域优先，外围一圈预取。
- 限制并发，去重请求；缓存按账号和城市隔离，设置过期与 LRU 容量。
- 拖动立即更新镜头，不等待网络；失败保留已有画面并提供重试。
- 区域接口只返回公开摘要；详情和行动按 ID 获取，不依赖会变化的列表下标。未侦察情报由服务器约束。
- 实时状态按需失效/局部更新，地图容器不因常规刷新销毁。

## 实施阶段
1. 可用地图：拖动、缩放、坐标搜索、筛选、回主城、分块加载与缓存、目标详情、现有出征流程与列表切换。
2. 基础战略表现：行军路线、敌我与占领状态、资源点和城市图标。
3. 后续扩展：全图聚合概览、收藏坐标、军团集结标记（本轮不新增规则或协作业务）。

## 验收
- 拖动不调用真实移动接口，移动中不卡等待网络。
- 缩放锚点稳定；手势结束不误触目标；镜头限制在地图边界。
- 请求去重、缓存淘汰、失败重试和账号/城市切换无旧数据污染。
- 点击目标与出征绑定同一 ID；侦察权限、宣战约束与出征默认设置不变。
- 后端接口测试、前端逻辑测试、浏览器视觉与交互检查。60 帧为优化目标，不在真机测量前承诺。

## 实施记录（2026-09-13）
- 新增 `WorldMapService` 与 `/api/game/world/map/chunk`、`/target` 两个鉴权读取接口，区域摘要不包含敌方兵力、资源或侦察数据。
- PixiJS 7.4.3 legacy 版本与 MIT 许可证已本地保存，仅进入地图时加载；支持 WebGL 及 Canvas 回退。
- 镜头与缓存分别实现为可单测模块。首版比例为每格 16–88 像素，超宽屏会提高最小比例以限制同时可见区域。
- 16×16 区域块；3 个并发请求；96 块缓存上限（保留当前视口及预取区）；30 秒有效期；失败退避 10 秒。地图请求 10 秒超时自动取消。
- 新增地图/列表切换、展开地图、坐标定位、类型筛选、主城定位、目标详情与行军路线。普通刷新保持画布与镜头；离开地图清理渲染器、事件及定时器。
- 原出征流程按最新目标 ID 接入。修复原野地出征描述提前引用未初始化变量的问题。
- 为请求超时额外保留了实施前 `api-client.js`：`docs/archive/map-before-api-client.js`。

首版未新增全图聚合概览、收藏坐标或军团集结标记；这些仍是后续阶段。移动端性能在浏览器中验证，真实手机 60 帧表现仍需设备测试。
