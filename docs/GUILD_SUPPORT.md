# 同军团物资运输与驻防

更新于 2026-10-24，描述工作区当前规则；新版协防采用 `joint-defense-v1-20261024`。总设计见 [当前项目设计](DESIGN.md)，城市隔离见 [多城市经营](MULTI_CITY.md)。

## 动作与资产归属

| 动作 | 可选目标 | 抵达后的物资 | 抵达后的部队与军官 |
| --- | --- | --- | --- |
| 运输 `transport` | 自己的另一座城市，或同军团其他成员的城市 | 全额入目标城 | 卡车／运输机及随行军官返回出发城 |
| 调遣 `rebase` | 自己的另一座城市 | 全额入目标城 | 部队入目标城库存，军官驻地转到目标城并恢复闲置 |
| 驻防 `reinforce` | 同军团其他成员的城市 | 全额入目标城，可不携带物资 | 编队独立驻扎，归原派兵人和原出发城 |

目标必须是已建成、具有真实玩家城主的可管理城市，接收账号不能已到注销清理时间。自己的当前城不能成为运输／调遣目标，自己的城市使用调遣而非军团驻防。支援不要求成员在线，也不要求宣战；不同军团的外交友好关系不授予支援权限。

## 操作入口

军团「成员」页可对其他成员选择「运输」或「驻防」，再选择其已建成主城或分城。战略地图及世界列表中的同军团城市也提供这两个入口，直接选中目标城市。兵力、资源、随行军官均从当前出发城市扣除。

运输只派卡车、运输机，支持粮食、钢铁、石油、稀矿、黄金。到达后物资全额入目标城，后勤部队和军官原路返城。驻防支持可按既有海陆空路线抵达的兵种，也可在运力允许范围内携带物资。

运输至少选择一支后勤部队和一种正数量物资，驻防至少选择一种兵种。钻石不属于可运输物资。出发前服务端校验当前城库存、编队带兵上限、路线和携带总负重；运输及驻防均预扣往返行军油耗，与携带石油合并检查，调遣预扣单程油耗。抵达入库不按生产容量丢弃货物，权限失效而返程的未交付货物也全额归还。切换当前城市不改变已发出任务的资产来源。

可选择出发城的闲置军官随行。市长、指挥官须先解除任命，已有行军任务的军官不能重复派出；驻防军官保持原玩家及原城市归属、行军职务，不能转为接收方的市长或指挥官。表单展示负重及路线预览，数量输入即时更新路线，关闭或更换弹窗后忽略旧目标城市查询结果。

## 行军状态与返回

| 当前状态 | 触发条件 | 后续状态与资产处理 |
| --- | --- | --- |
| 在途运输 | 抵达且权限有效 | 物资交付一次，清空行军货物，后勤编队返程 |
| 在途驻防 | 抵达且权限有效、城市允许接收并能补给 | 物资交付一次，清空行军货物，设置 `stationed=true` |
| 在途支援 | 抵达时身份失效、目标失效或原城主改变 | 保留未交付货物并返程，即使新城主仍属同军团也不交付 |
| 在途支援 | 派兵人主动撤回 | 从当前行进位置掉头，返程耗时等于已行进时间，至少 1 秒 |
| 已驻防 | 派兵人撤回或接收城主遣返，本编队未被活动战斗锁定 | 改为返程，按原单程耗时返回，至少 1 秒 |
| 已驻防 | 后台发现退团、换团、接收城主改变或目标失效 | 未参战者自动返程；实际参战者等本场结算结束 |
| 返程 | 抵达原出发城 | 幸存部队归队，未交付货物归还，军官恢复闲置，删除行军记录 |

驻防没有固定结束时间，也不因原抵达时间已过而重复交付或归队。退团／换团在抵达及后台驻防检查时生效，不保证在身份变更瞬间返回。已交付物资归接收城所有，后续撤回、遣返或退团不收回物资，已预扣行军油耗不退还。

派兵人从原出发城的「我军行军」查看、定位和撤回自己的驻军；接收城主从实际接收城的「本城军团驻军」查看派兵人、兵力并遣返。第三方和接收方其他城市没有遣返权限。支援不出现在敌军来袭列表，不触发敌军告警，也不能通过行军战斗接口开启进攻战术会话；地图在途为蓝色光带，抵达后展示驻扎状态，撤回后恢复返程表现。

## 驻防规则

- 驻军始终归派兵人所有，作为独立编队保存，不并入城主可出征的库存。随行军官仍属于原玩家和原城市，驻防期间保持行军状态。
- 城主统一指挥守城；本城先按迎战预设和上限选兵，再全量追加开战时已到达且有效的援军。援军不受本城迎战勾选或上限裁剪；同兵种也保留各来源，军官只加成自己的编队，无将不借用。
- 开战冻结实际参战编队及其将领、兵种配装与公共科技；普通城市战损失按各来源实际受击结算。战斗期间新到的援军及未参加迎战的部队不承受该场损失。战报统计守方合计损失、入营伤兵及按损失加权的回收率，伤兵分别回到各自派兵城市。
- 侦查情报包含全部有效驻军，沿用侦察技术等级控制情报深度，不受城主战术迎战预设限制；驻防侦察机拦截空中侦查，驻防侦查装甲车拦截地面侦查，两种方式分别结算。损失和伤兵仍归原派兵人，分城派出的援军伤兵回原分城。
- 派兵人在原出发城的「军情」中撤回，城主可在目标城「军情」中遣返。实际参战的来源交战期间不能撤回或遣返，迟到未参战驻军可以正常离驻；幸存者返原玩家合法城市。
- 出发和抵达均检查同军团身份及原接收城主。途中退团、换团或城权变更，抵达时取消交付，部队带原物资返城。已驻防部队在身份或城权失效后自动返城；正在交战的编队按开战快照结算完毕再返程。
- 不同军团之间的外交友好关系不授予运输或驻防权限。自己的城市继续使用既有运输和调遣，调遣会转移部队与军官驻地。

普通城市战将领周期按来源行军独立起算，同一行军内多个兵种共用起点；同兵种统一接收城主命令并同步机动，射程／有效速度相同的编队同批结算。攻击先统一提交伤害，再由仍存活的合法受击者反击，幸存攻击者使用按存活比例缩减的剩余预算继续余伤。同来源同兵种每技能回合最多一次反击，不因配装拆组增加次数。独立侦察仍使用既有领域、配置组及损失分摊规则。

科技及城市司令官使用实际被攻击城市快照，不叠加派兵城配置；将领装备、共鸣、整备与技能保留来源独立性。伤兵回收在终局、军官释放或转籍前使用各原玩家医疗科技与该队随行军官，保存回收采样，治疗后补回合法归属城。战报按编队记录参战、有效伤害、损失、伤兵和幸存；贡献只用于复盘。

驻防粮耗由实际接收城市支付，采用接收城主军需科技及该城市长减耗；抵达、生产／研发完成、伤亡及离驻按游戏时刻切分，小数按城累计，不转扣派兵城。接收城粮食耗尽且产粮不足时拒收新驻军，未参战者按粮耗降序、同值最新优先整队返程；参战者打完本场，先复核补给和遣返再开始下一场。短缺记账不形成负债，不自动花钻石。

每城在城市管理提供“允许接收军团驻军”开关，新增及迁移后的旧城市默认关闭；关闭不驱逐已有有效驻军。旧驻军只从 V126 迁移时的游戏时间开始新计费，旧战斗继续旧版本。原派兵城失守时保留参战来源至终局，幸存者和伤兵始终归原玩家；无合法目的地时保留待安置资产，可由军情选择合法自有城市，恢复后真实返程。详细计算、日志模板与边界见 [协防设计第16～17节](GUILD_GARRISON_JOINT_DEFENSE_DESIGN_20261024.md)。

## 接口与数据

| 接口 | 参数与作用 |
| --- | --- |
| `GET /api/game/world/support/cities` | `playerId` 为成员 ID；返回可接收支援的城市 ID、名称、城主、坐标及建成时间 |
| `POST /api/game/world/route` | 与出征共用 `targetKind`、`targetId`、`action`、`army`，重验目标权限并返回路线、耗时及运力 |
| `POST /api/game/world/dispatch` | `targetKind="player"`，`action="transport"` 或 `"reinforce"`，携带 `army`、可选 `carryRes` 和 `commanderId` |
| `POST /api/game/world/cancel-march` | `{"marchId":行军ID}`；派兵人在原出发城撤回在途或驻防编队 |
| `POST /api/game/cities/garrison` | `{"cityId":城市ID,"allowed":true或false}`；城主修改该城接收开关 |
| `POST /api/game/world/support/recover` | `{"marchId":行军ID,"cityId":城市ID}`；原玩家恢复失守驻军的合法返程 |
| `POST /api/game/world/support/dismiss` | `{"marchId":行军ID}`；接收城主在实际接收城遣返驻军 |

所有请求沿用 JWT 登录身份与 `X-City-Id` 校验。目标 `playerId` 只用于选择成员，不能指定发送者或替其他玩家操作。路线预览不扣库存，正式出发重新校验；创建任务、扣兵力、扣资源和设置军官行军职务在同一事务完成。抵达交付、驻防状态转换及战损结算分别随各自业务事务提交，重复 Tick 不重复交付。

V78 为 `marches` 增加 `stationed`、原城主 `support_owner_id` 和索引，为 `battle_sessions` 增加 `defender_support` 参战快照。状态接口通过 `world.marches[].stationed` 展示己方驻军，并通过 `world.reinforcements` 展示当前城收到的驻军；`support_update` 推送触发刷新。

`defender_support` 按援军行军 ID 保存各兵种实际参战数量，城主参战数量从守方总快照中扣除援军得到。旧行军默认 `stationed=false`；旧战斗缺少援军快照时沿用原守方结算。自动返程和主动撤回与开战操作共用接收城主锁，取得锁后重读驻军记录，避免旧兵力覆盖战斗幸存者。WebSocket 在事务提交后通知；后台 Tick 同步己方行军及当前城收到的驻军。

V126 增加来源快照、城市接收及粮账字段、行军计费游标和待安置状态。新接口不返回内部来源快照，分享只使用公开历史字段；不新增实时主城坐标或对手军官配置。
