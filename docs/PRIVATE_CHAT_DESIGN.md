# 玩家私聊

更新于 2026-10-06。本文描述已实现功能，主设计入口见 [当前项目设计](DESIGN.md#聊天与玩家私聊)。

## 使用流程

聊天页的「私聊」频道默认进入会话列表。列表可同时保存多个玩家的对话，每项显示头像、对方名称、在线状态、最近消息摘要和未读数；私聊未读数合计以与邮件相同的红色数字角标显示在主导航「聊天」Tab；登录、重连、收到消息及对话已读后同步更新，归零后隐藏。点击后进入独立的单人对话界面。对话标题展示对方名称和在线／离线状态，提供返回私聊列表按钮；列表项头像固定在统帅名称左侧。移动端可对列表项左滑显示“删除”，删除只隐藏当前玩家的会话，不删除消息，对方不受影响；收到新消息后该会话可重新出现。账号不可用时显示对应状态并禁用发送。

输入完整玩家名可发起会话。在世界或军团频道点击其他玩家的头像（也支持昵称入口），直接打开对应私聊对话，并将会话保存到发起者列表；尚未发送消息时也保留空会话，摘要显示「还没有消息，点击开始聊天」，不向对方发送空消息或创建通知。头像入口优先使用稳定玩家 ID，避免历史昵称改名导致找不到玩家。

最近会话最多展示 50 个，按最近消息或主动打开时间排序；消息区显示双方最近 50 条记录。切换或返回列表保存各自草稿，旧会话异步响应不会覆盖当前对话。在线状态依据服务端 WebSocket 活跃连接判断，私聊面板可见时每 15 秒刷新，也随消息和重连刷新。
消息存入数据库，离线玩家再次进入会话可以读取。在线消息通过 `private_chat` WebSocket 事件只推送给双方；隐藏私聊频道时收到消息给出提示。进入可见的单人对话后推进已读到当前加载的最新消息 ID，停留会话列表、论坛、其他频道和离开聊天页时不推进已读。重连重新拉取会话和历史。

## 规则与权限

发送者和历史查询主体由登录身份决定，客户端只能指定对方 ID，不能指定他人的会话主体。禁止向自己、不存在或非活跃账号发送消息；既有历史仍允许参与者查看。私聊无声望或军团门槛，消息最多 80 字，过滤控制字符及现有敏感词，每位发送者 5 秒冷却，跨会话共享冷却。

已读接口只更新登录玩家作为收件人的记录，不会修改第三方消息。WebSocketPushService 在事务提交后投递，回滚不会推送。

## 接口

路径前缀：`/api/game/chat/private`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/player?username=…` | 解析完整玩家名，返回公开昵称、ID 和头像 |
| POST | `/{peerId}/open` | 为登录玩家保存会话，返回对方名称、头像、在线及账号可用状态 |
| GET | `/conversations` | 当前玩家最近会话及未读数 |
| GET | `/{peerId}/history` | 当前玩家与对方最近 50 条消息，按时间顺序展示 |
| POST | `/send` | `{recipientId, content}`，返回已持久化消息 |
| POST | `/{peerId}/read` | `{throughId}`，推进已读边界 |

数据库迁移：`V70__private_chat.sql` 新增消息表；`V71__private_chat_conversations.sql` 新增主动打开的会话表，以所有者与对方 ID 唯一约束防止重复，并保存打开时间。消息历史自动并入列表，已有消息无需回填会话表。打开会话只影响发起者列表，对方列表在实际收到消息后出现会话。部署时由 Flyway 执行。历史分页、屏蔽名单和更多会话管理可后续扩展。

## 验证

前端测试覆盖隐藏会话保持未读、可见会话确认已读、草稿保留和过期历史响应隔离，回归世界及军团聊天。后端测试覆盖双方定向投递、低声望可发送、输入/账号检查、发送冷却、参与者查询隔离和已读边界。

本次验证覆盖列表与对话切换、多玩家空会话、头像直接进入、标题状态及发送期间返回列表的草稿保留。

数据库迁移 `V72__private_chat_delete.sql` 保存每个会话所有者的删除边界。
