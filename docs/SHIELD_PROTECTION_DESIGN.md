# 护盾叠加与来袭保护设计

日期：2026-10-06

## 目标

每个护盾增加当前城市 8 小时免受玩家攻击的时间。保护在使用成功时生效，允许玩家在敌军抵达前开盾；已经开始或结算的战斗不受随后开盾影响。

## 规则

| 时机 | 行为 |
| --- | --- |
| 敌军尚未出发 | 护盾生效的城市不能被发起征服或掠夺；请求在扣兵、扣资源前被拒绝 |
| 敌军已出发，尚未开战 | 抵达处理时检查目标城市护盾；生效则取消本次攻击并开始正常返程 |
| 战斗已经开始 | 当前战斗会话继续推进并按原规则结算；护盾拦截其他尚未开战的攻击 |
| 战斗已经结算 | 不撤销伤亡、掠夺、战报或已有归属结果 |

保护针对玩家所属的目标城市，以 ownerId 和 citySlot 查询，其他城市不共享该护盾。敌对军团不享有绕过护盾的例外。征服、掠夺均受保护；侦查、运输、调遣、NPC 与野地作战沿用现有规则。本次不扩展战后和平保护 peaceUntil，也不改变既有城市归属结算规则。

## 时间与边界

使用成功后的截止时间：

```text
shieldUntil = max(原 shieldUntil, 当前时间) + 8 小时
```

未启用或已过期时从当前时间起算；未过期时保留剩余时间并增加 8 小时。每次成功使用消耗一个道具，库存不足不修改时间。护盾仅在 shieldUntil > 检查时间 时有效，等于截止时间时已失效。

开盾不主动撤回在途敌军，敌军在抵达处理时才再次判断。若护盾在抵达前过期，则攻击按现有战争与外交规则继续。已抵达但尚未获得战斗会话的排队部队同样属于尚未开战的攻击。

## 服务端流程

1. 使用护盾：锁定玩家行，消耗库存，读取当前城市状态，顺延截止时间并保存。
2. 创建攻击行军：锁定目标玩家后校验城市护盾，再校验战争与外交权限；护盾有效时返回“目标城市护盾生效，无法发起攻击”。
3. 行军抵达：已有 battleId 的部队交由战斗调度器推进，不再应用护盾拦截。尚未开战的部队在锁定目标玩家后读取目标城市护盾。
4. 护盾拦截：调用现有 startReturnMarch，保留部队、随军物资、军官与行军记录；交换起终点并反转既有路线，返程耗时为原出征耗时（最低 1 秒），从本次抵达处理时间起算。
5. 返城抵达：沿用现有返城结算，部队归队、随军物资入库；不生成战斗、伤亡、掠夺或奖励。

护盾拦截与外交失效使用不同分支，外交失效的既有处理未改变。玩家锁与出征/抵达检查共用，开盾先获得锁并提交则后续检查能应用保护；战斗先创建会话则随后开盾不终止本场战斗。重复开盾也由该锁串行处理，避免并发续盾覆盖。

## 客户端表现

护盾道具说明明确“每次使用增加8小时免受玩家攻击时间，可叠加”。护盾拦截后向进攻方发送 shieldBlocked 行军事件，显示“目标城市护盾生效，部队正在返程”，并刷新行军状态；向守方发送来袭取消通知。返程地图与计时沿用现有展示。拦截不产生虚假战报。

## 实现位置

- backend/src/main/java/com/wargame/service/DepotService.java：护盾叠加与玩家锁。
- backend/src/main/java/com/wargame/service/MarchService.java：目标城市护盾判断、出征拒绝、抵达返程。
- frontend/js/ws-handlers.js：护盾拦截提示。
- backend/src/test/java/com/wargame/ShieldDurationTest.java：叠加、过期/未启用、库存不足。
- backend/src/test/java/com/wargame/MarchServiceTest.java：出征、抵达、返城、开战后护盾、边界与城市范围。

## 验证

护盾专项测试覆盖连续使用、已过期/未启用、库存不足；征服与掠夺的出征拒绝和抵达返程；返程时兵力与物资保留、返城后归还；已开战后护盾不终止战斗、不重复结算；到期时间边界与其他城市隔离。既有守方指挥和玩家城市排队战斗也纳入定向回归。

完整 ShieldDurationTest 与 MarchServiceTest 首轮共 55 项，54 项通过；testWildGatherFlow 失败（采集量预期 500，实际 1000），不属于本次护盾变更范围。护盾专项与守方指挥、排队战斗定向回归共 11 项，全部通过；客户端脚本语法与本次变更的 diff 空白检查通过。

无需数据库迁移。后端代码需重启或部署后生效；客户端需加载更新后的脚本。尚未进行真实浏览器内的地图返程视觉验收。
