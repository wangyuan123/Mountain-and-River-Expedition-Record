# 护盾叠加与来袭保护设计

初版日期：2026-10-06；更新日期：2026-10-20。当前规则包含多城服务端开盾、抵达免战邮件及守方可见的敌军返程路线；分日期章节保留各阶段验证记录。源码尚未部署。

## 目标

每个护盾增加当前城市 8 小时免受玩家攻击的时间。保护在使用成功时生效，允许玩家在敌军抵达前开盾；已经开始或结算的战斗不受随后开盾影响。

## 规则

| 时机 | 行为 |
| --- | --- |
| 敌军尚未出发 | 护盾生效的城市不能被发起侦查、征服或掠夺；请求在扣兵、扣资源前被拒绝，宣战也受限 |
| 敌军已出发，尚未开战 | 抵达处理及手动打开战场、创建战斗会话前重新检查目标城市护盾；生效则取消本次行动并原路返程，向双方各发一封免战邮件，守方地图继续显示敌军返程路线 |
| 战斗已经开始 | 当前战斗会话继续推进并按原规则结算；护盾拦截其他尚未开战的攻击 |
| 战斗已经结算 | 不撤销伤亡、掠夺、战报或已有归属结果 |

保护针对玩家所属的目标城市，以 ownerId 和 citySlot 查询，其他城市不共享该护盾。敌对军团不享有绕过护盾的例外。侦查及玩家城进攻均受抵达免战保护，包括征服、掠夺、佯攻、骚扰、游击及战术攻击；不生成侦查情报或战报。出发城主动军事交互限制见2026-10-12章节，自有城运输调遣、NPC与野地规则按该节边界执行。本次不扩展战后和平保护 peaceUntil，也不改变既有城市归属结算规则。

## 时间与边界

2026-10-20时间口径：护盾截止及抵达检查使用持久化游戏时间 `GameClock.now()`。全服停服时护盾、在途行军及战斗同时暂停；服务器恢复后继续剩余时长，不因真实停机跨过原日历截止时刻而失效。玩家离线且服务器正常时仍持续计时，详见[停服暂停与恢复设计](SERVER_GAME_CLOCK.md)。

使用成功后的截止时间：

```text
shieldUntil = max(原 shieldUntil, GameClock.now()) + 8 小时
```

未启用或已过期时从当前游戏时间起算；未过期时保留剩余时间并增加 8 小时。仓库使用护盾道具时每次消耗一个，库存不足不修改时间；军情界面的钻石开盾使用下述独立接口，按去重城市数扣钻，不消耗仓库护盾。护盾仅在 shieldUntil > 检查时间 时有效，等于截止时间时已失效。

开盾不主动撤回在途敌军，敌军在抵达处理时才再次判断。若护盾在抵达前过期，则攻击按现有战争与外交规则继续。已抵达但尚未获得战斗会话的排队部队同样属于尚未开战的攻击。

## 服务端流程

1. 使用护盾：锁定玩家行；道具入口消耗库存并顺延当前城市护盾，军情入口校验全部所选城市、按去重数量扣钻并分别续期，同一事务提交。
2. 创建攻击行军：锁定目标玩家后校验城市护盾，再校验战争与外交权限；护盾有效时返回“目标城市护盾生效，无法发起攻击”。
3. 行军抵达或手动打开战场：已有 battleId 的部队交由战斗调度器推进，不再应用护盾拦截。尚未开战的部队在锁定目标玩家后读取目标城市护盾，必须在创建会话前完成检查；手动战场入口不能绕过保护。
4. 护盾拦截：调用现有 startReturnMarch，保留完整部队、随军物资、军官与行军记录；交换起终点并反转既有路线，返程耗时为原出征耗时（最低 1 秒），从本次抵达处理游戏时间起算。保存 returnReason=shield，移出来袭列表，向攻守双方各发送一次系统邮件。已返程记录不重复拦截或寄信。
5. 返城抵达：沿用现有返城结算，部队归队、随军物资入库；不生成战斗、伤亡、掠夺或奖励。

护盾拦截与外交失效使用不同分支，外交失效的既有处理未改变。玩家锁与出征/抵达检查共用，开盾先获得锁并提交则后续检查能应用保护；战斗先创建会话则随后开盾不终止本场战斗。重复开盾也由该锁串行处理，避免并发续盾覆盖。

## 客户端表现

护盾道具说明明确“每次使用增加8小时免受玩家攻击时间，可叠加”。军情开盾收到服务端成功响应后才应用护盾时间和钻石余额；失败保留原状态，重复点击复用当前请求。护盾拦截后向进攻方发送 shieldBlocked 行军事件，显示“目标城市护盾生效，部队正在返程”，并向守方发送来袭取消通知。手动战场入口收到护盾取消结果时停止进入战斗并刷新状态。

双方系统邮件均包含“护盾期间不可发生交火”，说明本次行动取消、未发生战斗、伤亡或资源掠夺。攻方邮件标题为“护盾免战：部队原路返程”，告知携带原有物资返回出发城；守方标题为“护盾免战：来袭已拦截”，告知敌军已原路返回。邮件不附带战利品，不以战斗或侦查报告替代免战通知。

### 军情开盾接口

- `POST /api/game/cities/shield`，请求体为 `{ "cityIds": [城市ID, ...] }`；身份以当前登录玩家为准。
- 服务端按城市ID去重，校验全部城市归属、可用状态及钻石余额；空选择、非法城市或余额不足时不扣款、不部分开盾。
- 按每城200钻石扣款，逐城执行 `max(原 shieldUntil, GameClock.now()) + 8小时`；返回 `success`、`count`、`cost`、`remainingDiamond`、所选城市名称 `cities` 及最新 `state`。
- 扣钻、续期与状态返回处于同一事务；复用玩家锁串行处理，不以本地修改余额或护盾时间代替服务端提交。

### 守方地图中的敌军返程

守方能够继续看到因本城护盾拦截而返程的敌军路线、返回方向与行进进度，无额外雷达等级门槛。路线沿用蓝色 `0x69b7ee`，从受保护城市指向敌军原出发城市；攻方继续从自己的普通行军列表查看返程。

完整世界状态与 Tick 均提供 `returningEnemyMarches`，前端保存为 `world.returningEnemyMarches`；重连或刷新后由服务端恢复，不依赖一次性提示。仅返回原目标城市当前归属该守方、`returning=true`、`returnReason=shield`、无战斗会话且尚未返城的敌军行军，不向其他玩家公开普通撤军。该叠层不重新计入 `incoming` 或敌袭数量，不提供迎战入口。

每项只投影 `id`（`return-march-{marchId}`）、`marchId`、`targetKind=player`、`fromX/fromY`、`targetX/targetY`、`startAt/arriveAt`、`action` 与 `returning=true`。不包含敌军数量、装备或将领；守方路线按当前起终点绘制，与攻方行军记录中保存并反转的完整路线数据区分。客户端按游戏时间插值位置与方向，收到空列表或返程到达时清除路线，不触发己方抵达提醒。

## 2026-10-10 多城地图显示修复

地图与城市列表中的 selfCity 仅代表归属玩家，不能用来将当前城市护盾状态套用到所有分城。只有目标坐标与当前 cityPos 一致时读取本地 getCityStatus，其他城市使用服务端提供的各自 shieldUntil / cityState。主城开盾不会保护未开盾的分城；切换到分城后，主城仍按其独立护盾截止时间展示。回归覆盖其他自有城市误显示、切城后真实护盾保留、当前城市本地状态优先及过期护盾隐藏。

## 2026-10-12 独立城市免战与侦查限制

本节在2026-10-12将侦查纳入城市护盾限制，当前总则已同步。每座城市独立使用、累计护盾时长，野地不受城市护盾保护。护盾生效时，目标城市不能被玩家侦查、征服、掠夺或宣战；敌对军团同样受限。已出发的侦查与攻击在抵达时校验目标护盾，生效则原路返程，不生成情报或战报。已建立的战斗会话继续结算，不撤销既有结果。

开盾城市不能作为出发城向其他真实玩家城市发起军事交互，包括侦查、征服、掠夺、运输、增援和宣战；野地、寇的出征与侦查保持可用，自有城之间的运输调遣不受此限制。聊天、邮件、军团管理不属于本节城市军事交互。其他未开盾的城市不继承该限制。开盾前已发出的行军不因出发城随后开盾而撤回，仍在抵达时按目标城市状态处理。

宣战在写入战争关系之前校验发起城市与目标城市的护盾；地图与直接 API 请求共用服务端检查。保护按城市槽位读取，不因同账号其他城市开盾而扩散，也不扩展到野地目标。

本次定向验证：ShieldDurationTest 与 MarchServiceTest#shield* 共 13 项全部通过，覆盖侦查出征/抵达拦截、主动军事交互限制、双向宣战限制及开盾后野地出征可用。

## 2026-10-20 军情界面多城独立护盾选择与钻石消耗机制

### 背景与定位
原版军情界面仅有一个笼统的“开启护盾”按钮，既未区分玩家当前拥有的多个城市（主城与分城），也未建立清晰的钻石扣减与时间叠加交互。本次对军情页面的开盾机制进行了规范化重构：

### 核心规则
1. **单城独立保护原则**：护盾严格针对单座城市（`ownerId` + `citySlot`）生效。
2. **多城选择面板**：点击敌袭卡片或军情界面的 `[开罩]` 按钮，唤起城防护盾调配弹窗，罗列玩家当前拥有的全部城市列表（含主城与各分城名称、坐标、当前护盾剩余时间）。
3. **单选与全选**：
   - 玩家可单独勾选某一个或多个城市，已有护盾的城市也可选择续期；
   - 提供 `[全选所有城市]` 快捷选项。
4. **钻石消耗与计算**：
   - 每座城市开启 8 小时护盾固定消耗 **200 钻石**；
   - 消耗钻石总额 = 勾选城市数 × 200；
   - 扣减前严格校验玩家钻石储量，钻石不足时阻断并明确提示当前差额。
5. **时间顺延叠加**：
   - 若某所选城市当前已有护盾在生效中，再次开启将在原有截止时间上顺延 8 小时（`shieldUntil = max(原 shieldUntil, 当前时间) + 8 小时`），支持多层叠加。
6. **自动化回归**：
   - 相关逻辑纳入 `frontend/tests/alerts-terminal-slg.test.cjs`，测试模拟服务端开盾响应；最新定向验证范围见下节，不表示全仓库测试通过。

## 2026-10-20 抵达免战、返程可见性与实施验证

本轮补齐军情服务端开盾、自动抵达与手动战场入口的统一护盾检查、双方免战系统邮件，以及守方可见的敌军返程路线。倒计时归零并不代表可以开战，必须通过服务端护盾检查；护盾有效时不创建战斗会话。当前交付规则为守方继续看到该次敌军返程，普通撤军不会因此公开。战场前排禁止交叉和贴近图标边缘总间距至少15px的规则见 [战术指挥设计](BATTLE_COMMAND_AND_DISTANCE_DESIGN.md)。

### 数据迁移与部署

`V108__shield_return_visibility.sql` 执行 `ALTER TABLE marches ADD COLUMN return_reason VARCHAR(30) NULL;`。护盾拦截返程写入 `shield`，历史记录保留空值，不能根据普通返程状态推断为护盾拦截或补公开路线。V108与求援快照V107用途独立；部署时按既有Flyway顺序执行所需迁移，同步更新后端与前端资源。

源码尚未部署，未执行线上迁移或真实多人联网验收。V108验证使用H2的MySQL兼容模式，不能据此宣称已完成真实MySQL升级验证。
