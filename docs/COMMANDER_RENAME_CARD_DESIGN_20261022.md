# 统帅改名卡设计与实施口径

## 规则
- 统帅改名卡独立 ID `commanderRenameCard`，不复用军官、城市改名卡，不加入前后端商城白名单。
- 新玩家在角色初始化时收到1张卡的系统邮件；已初始化的非机器人、未删除老玩家在迁移时各补发1张。未初始化的历史账号在初始化时发放，账号永久发放标记保证总计一份。
- 邮件附件受保护，领取前不过期；领取后卡入仓，重复领取不能重复入库。玩家互寄邮件不能创造或转移此道具。
- 仓库与资料页共用改名弹窗；所有玩家改名接口共用后端事务，每次成功必须消耗1张卡，不支持金币、钻石或免费接口替代。
- 首次使用卡不限注册/领取时间；此后从上次成功改名时刻起至少30×24小时，使用现实时间，不随停服冻结。
- 上线前没有可靠的统帅改名时间记录，不伪造历史时间；新老玩家均从本机制首次成功用卡开始记录次数和冷却。
- 原名称校验保持NFC规范化、首尾普通空格清理、最多8个Unicode码点、拒绝不可见字符；重名以NFC+首尾空格清理+大小写不敏感的统帅展示名判定，不另占用登录用户名。
- 有效展示名为空时以登录名作为实际展示名参与唯一性；排除自己，新旧名称完全相同不扣卡。
- 重名固定提示：`名称不能重复请重新修改`。所有失败均不扣卡、不启动冷却、不推进改名任务。

## 实施
- 玩家记录保存唯一名称键、最后成功用卡真实时间、成功用卡次数、永久赠卡标记。
- 玩家行写锁串行化同一账号领取与用卡；卡扣减、改名、冷却和任务进度处于同一事务。
- 数据库唯一名称键兜底不同账号并发抢名；实体生命周期覆盖注册、默认名及后台修改，避免只约束一个入口。
- Flyway迁移在任何DDL前扫描历史有效展示名，发现重复先报出玩家ID并停止，保留原名，运营处理后重试；不静默重命名。
- 老玩家补卡与永久标记写入迁移；新账号邮件发放走角色初始化，不因重登、未读状态、邮件清理或重置角色重复发放。
- 邮件附件增加系统白名单 `{"type":"item","itemId":"commanderRenameCard","qty":1}`，入库与领取标记同事务。
- 前端展示持卡数、首次/冷却状态和再次可改名时间；不修改既有主题和组件样式。

## 验收
- 注册发卡/老玩家补发/重复初始化不增发；邮件重复领取、非本人领取、玩家伪造道具附件拦截。
- 缺卡、非法名称、重名、同名和冷却内失败均不扣卡；首次成功、30天边界允许、成功后再次开启冷却。
- 同账号并发只成功一次；不同账号抢同名仅一方成功；唯一冲突回滚扣卡。
- 资料页、旧接口、仓库入口均无法绕过规则；登录名不变、任务事件保留、商城伪造购买被拒。
- 军官、城市改名及开箱广播功能保持不变。
