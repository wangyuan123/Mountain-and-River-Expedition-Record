# 军衔晋升钻石大礼包设计

设计日期：2026-10-28。状态：已按本文实现并完成专项及相关回归验证，尚未部署运行服务。

## 目标与原则

每次正式授衔成功后，向账号赠送一个对应新军衔的钻石大礼包。上等兵至中将的礼包钻石数，恰好覆盖下一阶晋升凭证的商城售价，形成“完成晋升 → 获得礼包 → 开启领取钻石 → 按需购买下一阶凭证”的连续成长流程。

礼包只包含普通钻石；购买和使用凭证继续遵循现有规则，声望、累计剿寇胜场、逐阶授衔和军事笔试门槛保持现行设计。礼包发放不依赖主线任务阶段、章节通关或任务奖励领取，避免玩家已经授衔却被前置任务卡住补给。

本方案以 [现行军衔设计](RANK_PROMOTION.md) 的 16 档商城售价为基准。列兵启动礼包与上将荣耀礼包为本设计新增建议，分别补齐首次晋升与最高军衔奖励。

## 发放与开启

1. 正式授衔事务成功时，自动发放“新军衔名称 + 晋升钻石大礼包”一份至账号仓库。仅声望达标、胜场达标、买到凭证或笔试合格均不发放。
2. 礼包归入仓库“资源道具”，玩家点击“开启礼包”后钻石进入账号共享余额。开包不直接购买凭证。
3. 礼包永久有效，不上架商城、不从 NPC 掉落、不进入其他宝箱、不支持交易或赠送。每账号每阶只发放一份，重复请求、刷新、重登或切城均不可重复领取。
4. 当前阶段和未来阶段凭证的购买仍由玩家决定；已持有下一阶凭证时照常获得本阶礼包，不扣减奖励或自动替换凭证。
5. 钻石为普通可支配余额。玩家将其用于其他商品后，不再补发；后续晋升仍须自行保证购买凭证所需余额。

## 经济影响

- 从列兵至上将的 16 张凭证按现价共需 10,950 钻石。
- 列兵启动礼包 20 钻石，加上上等兵至中将的 15 个晋升礼包共 10,930 钻石，正好覆盖整条凭证购买链。
- 上将荣耀奖励额外提供 5,000 钻石，新账号完整成长可获得本机制奖励合计 15,950 钻石。
- 若玩家将前序礼包的钻石完整用于后续凭证，则除最高军衔荣耀奖励外，补给与凭证消费相抵；通过其他渠道获得旧凭证或自行提前买过凭证的账号，可以保留相应奖励，这是既有投入获得的正常收益。
- 金额按发放时服务端配置生成并记录；后续调整商城售价时须同时评估已发礼包的购买力与补差规则，不应在开启时悄然改变已发礼包承诺的金额。

## 老玩家衔接建议

上线时不追溯发放全部历史军衔礼包，避免一次性投放大额钻石。默认对每个旧账号按“上线时已获得的当前军衔”补发一份对应礼包，仍受每账号每阶一次的发放记录约束：

- 旧列兵领取 20 钻石启动礼包。
- 旧上等兵至中将获得当前军衔对应的下一阶凭证资金。
- 旧上将获得一次 5,000 钻石荣耀礼包。
- 已持有下一阶凭证的旧账号同样补发，不删除已有凭证或扣减钻石。
- 上线补发和正式晋升共用账号锁与同一发放入口；晋升前先完成旧账号衔接判定，确保首次登录同时晋升时不会漏发或重复发放。

上线补发资格使用一次性标记保存。新账号不走旧账号补发，旧账号也不能通过反复登录触发其他历史军衔奖励。具体补发范围应随实施版本固定，不能以客户端上报军衔或注册时间判定。

## 服务端实施约束

### 发放记录

建议增加账号军衔奖励记录，以“账号 ID + 获得军衔阶数”为唯一约束，记录礼包 key、承诺钻石数量、发放来源、发放时间和开启时间。礼包 key 使用 rank_diamond_pack_1 至 rank_diamond_pack_17，与既有 rank_certificate_<tier> 和 stage_gift_<stage> 区分。

来源分为初始启程、正常授衔和上线补发，来源不作为唯一约束的一部分；同一军衔不能因不同来源而重复获得。发放记录永久保留，开启后不能通过零库存重新获得礼包。

### 事务与并发

- 正常授衔在现有账号锁内校验四项条件；同一事务完成扣凭证、升军衔、清理试卷、登记奖励、礼包入仓和主线事件。任何持久化步骤失败均回滚；通知在事务提交后发送。
- 开包使用同一账号锁，按最新库存与未开启记录核验，在同一事务内扣除一份礼包、增加账号主城账本的共享钻石并写入开启时间。不能将奖励写入当前分城独立资源后导致商城无法使用。
- 连点或跨城并发开启只允许一次成功；开包失败保留礼包且不增加钻石，不出现礼包已消耗但奖励未到账的状态。
- 钻石余额不足以容纳奖励时拒绝开启并保留礼包，避免整型溢出、负数余额或静默截断。
- 已持有下一阶凭证不影响礼包发放与开包；商城原有“已持有”禁购规则继续生效。
- 礼包金额由服务端读取发放记录决定，客户端不能指定奖励金额、替换档位或直接调用购买接口获取礼包。

### 页面与提示

- 晋升面板在授衔前显示“晋升奖励：对应礼包，内含 X 钻石，可购买下一阶凭证”。上将目标显示“荣耀奖励 5,000 钻石”。
- 授衔成功提示明确“礼包已入仓”，提供前往仓库入口，避免玩家误认为钻石已经到账。
- 仓库展示礼包名称、明确钻石数和对应凭证名称；开启后提供前往商城购买所需凭证入口。已持有对应凭证或已满级时，展示钻石到账结果即可。
- 页面复用现有组件与项目样式。礼包内容和价格来源以服务端响应为准，游戏状态返回未开启礼包数量与奖励信息。

## 验收范围

1. 逐阶验证全部 16 次晋升的礼包名称、军衔归属和金额；15 个中间档奖励恰好覆盖下一阶凭证，上将走独立终局奖励。
2. 新账号首次初始化仅发一份列兵启动礼包，第二次进入、刷新或重登均不重复。
3. 笔试通过但未正式授衔、授衔失败、购买凭证、主线领取或 NPC 胜利均不触发本机制奖励。
4. 晋升成功后礼包入仓，开包前钻石不变；开包后金额进入共享余额，可在任意城市按需购买对应凭证。
5. 覆盖重复授衔、并发授衔、并发开包、开包事务回滚、余额溢出、越阶/伪造 key 和缺失库存。
6. 老账号只补当前已获军衔一份；补发与首次登录晋升并发时不漏发、不重复，不重算旧军衔、声望、胜场或笔试。
7. 全链路按现价验证奖励总额 15,950、凭证支出 10,950；在无其他钻石消费或收入的条件下最终保留 5,000 钻石荣耀奖励。

## 实施与验证记录（2026-10-28）

### 实施结果

- `RankGiftDef` 从下一阶凭证售价推导列兵至中将礼包金额，上将独立奖励 5,000 钻石；道具 key 为 `rank_diamond_pack_1` 至 `rank_diamond_pack_17`，均归入资源道具，不进入商城价格表。
- Flyway `V139__rank_diamond_gifts.sql` 新增永久奖励表 `rank_gift_rewards`，以 `(player_id, rank_tier)` 唯一约束保存金额、来源与发放/开启时间。迁移同时固定已初始化旧账号的 `rank_gift_baseline_tier`；`rank_gifts_enrolled` 标记启程/上线衔接已处理，新账号默认快照为 0。
- `GET /api/game/state` 在首次进入时完成启程或旧账号补发；`POST /api/game/rank/promote` 在同一授衔事务中先处理衔接，再发新军衔礼包。发放与开包均使用账号行锁；授衔奖励入口强制要求已有事务，失败整体回滚。
- `POST /api/game/depot/use` 使用 `{ "itemId": "rank_diamond_pack_<tier>" }` 开包，按永久回执金额兑现，只写主城 `city_slot=0` 的共享钻石账本；缺库存、已开启、伪造 key、越阶与余额溢出均拒绝。
- 游戏状态新增 `rankDiamondGifts: { rewards, unopenedCount }`；奖励条目包含 `itemKey`、`tier`、`name`、`diamonds`、`desc`、`count`、`source`、`issuedAt`、`openedAt`，非最高军衔附带下一阶凭证信息。`rankInfo.promotionReward` 预告目标新军衔奖励，授衔响应的同名字段返回本次入仓奖励。
- 晋升面板展示奖励与仓库入口；仓库按服务端回执显示承诺金额，开启后显示共享钻石到账及对应商城入口。已持有凭证或已满级时只显示到账结果；已开启礼包不再显示旧入仓提示。
- 修正账号预读旧版本后再加锁的并发问题，改为直接带锁刷新；账号永久删除时清理相应奖励记录。
