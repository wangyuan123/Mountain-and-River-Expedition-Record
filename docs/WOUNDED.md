# 伤兵营规则

- 所有玩家参战部队适用，包括野地战斗、流寇/NPC/玩家城攻防、旧来袭任务和侦察机空战。城防设施不进入伤兵营。
- 实际损失 = 开战数量 − 战场幸存数量。幸存者保持原有返程/驻防流程，医疗不再自动返还部队，也不再额外扣减败战幸存者。
- 每个兵种可救治数量 = 向下取整（实际损失 × 回收率）。其余永久阵亡。
- 回收率 = 医疗技术等级 × 5% + 本次参战军官急救等级 × 3%。医疗技术最高 Lv.10、急救最高 Lv.5，因此合计最高 65%。没有基础回收率；两者均为 0 时不产生伤兵。闲置军官不会提供加成。
- 回收率在战斗结束时确定，后续升级科技或更换军官不会重新计算旧伤兵。
- 按玩家、城市和战斗批次保存。出征伤兵优先归属出发坐标对应的己方城市；从非城市位置出发则归主城。防守伤兵归被攻击城市。原玩家的伤兵不会随城市易主转移给占领者。
- 军队页面进入“伤兵营”，可切换城市、选择某批次的治疗数量。治愈后立即补回玩家正常军队，不消耗平民、不需要等待。
- 黄金单价 = 向上取整（该兵种制造资源总价 × 10%），至少 1 黄金。钻石费用 = 向上取整（所选数量的黄金费用 ÷ 100）。两种货币恢复数量一致，由玩家选择，不会自动混合扣费或自动消费钻石。
- 每批伤兵从受伤时间起保留 7 天。不论账户余额如何，未治疗部分到期全部消失，没有自然恢复；新伤兵入营和部分治疗均不会延长期限。
- 治疗接口在服务端核验归属、期限、数量和费用，资源扣减、兵力增加、伤兵扣减在同一事务提交。读取和治疗在到期时立即排除伤兵，后台每分钟清除过期记录。
- `V31__create_wounded_units.sql` 随后端启动由 Flyway 创建伤兵表。旧战斗不追溯补发伤兵。账号初始化、注销清理和存档导入时同步清除伤兵。

## 验证

`WoundedServiceTest` 覆盖回收率、分城分批到期、黄金/钻石治疗、金额与权限检查、并发重复治疗、实际战斗入营。
`WoundedMigrationTest` 在独立 H2 MySQL 模式数据库执行新表脚本，验证版本列和同城同兵种多批次。
前端 `wounded.test.cjs` 覆盖城市切换、费用、重复点击、失败保留伤兵及旧响应隔离。
