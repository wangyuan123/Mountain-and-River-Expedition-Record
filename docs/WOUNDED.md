# 伤兵营规则

- 所有玩家参战部队适用，包括野地战斗、流寇/NPC/玩家城攻防、旧来袭任务和侦察机空战。城防设施不进入伤兵营。
- 实际损失 = 开战数量 − 战场幸存数量。幸存者保持原有返程/驻防流程，医疗不再自动返还部队，也不再额外扣减败战幸存者。
- 每个兵种可救治数量 = 向下取整（实际损失 × 回收率）。其余永久阵亡。
- 回收率 = 医疗技术等级 × 5% + 本次参战军官急救等级 × 3%。医疗技术最高 Lv.10、急救最高 Lv.5，因此合计最高 65%。没有基础回收率；两者均为 0 时不产生伤兵。闲置军官不会提供加成。
- 医疗技术研发的配套建筑为本城战地医院，要求等级 `max(1,科技目标等级−2)`，Lv.10医疗技术需医院Lv.8。医院每城一座、最高Lv.10，占军事区卡槽，并提供现有伤兵营入口；完整建造及科研逐级表见 [战地医院与医疗科研设计](FIELD_HOSPITAL_DESIGN_20261012.md)。
- 医院等级用于后续科研前置，不增加床位、回收率、自然恢复或费用折扣；拆除医院不清空伤兵、不额外限制现有治疗、不撤销已完成医疗科技。旧医疗研发继续使用创建时的兵站前置快照，新队列使用医院前置并受拆除保护。
- 回收率在战斗结束时确定，后续升级科技或更换军官不会重新计算旧伤兵。
- 按玩家、城市和战斗批次保存。出征与援军伤兵按行军保存的城市槽归原派兵城，不依赖历史坐标或玩家当前选择的城市；旧行军未设置城市槽时归主城。防守伤兵归被攻击城市。原玩家的伤兵不会随城市易主转移给占领者。
- 同军团驻防先按实际参战编队分摊损失，再分别计算伤兵：城主伤兵留在被攻击城，援军伤兵回原派兵城市，按各自玩家医疗科技及随行军官急救技能计算回收率。驻防侦察机的拦截损失适用同一规则。未参战及战中迟到援军不产生本场伤兵；治疗后补回原派兵城市的正常库存，重新驻防需再次派遣。详见 [同军团物资运输与驻防](GUILD_SUPPORT.md)。
- 军队页面进入“伤兵营”，只查看和治疗当前城市的伤兵；通过“切换城市”切换全局城市后加载该城伤兵。批次历史坐标仅为快照，迁城后不会拆成多个城市选项。治愈后立即补回本城正常军队，不消耗平民、不需要等待。切城和重新打开页面会清除旧页面的治疗等待状态，旧响应不能覆盖新城列表或治疗状态。
- 首页“可用兵力”只统计本城正常驻军，待救治伤兵单独提示并与本城伤兵营数量一致。参战全灭且没有预备兵时可用兵力为 0；未参战的预备兵保留，不能把伤兵从正常驻军中再次扣除。黄金或钻石治疗成功后，仅已治疗数量归队。
- 黄金单价 = 向上取整（该兵种制造资源总价 × 10%），至少 1 黄金。钻石费用 = 向上取整（所选数量的黄金费用 ÷ 1000），即每 1000 黄金折算 1 颗钻石，不足 1 颗按 1 颗计。两种货币恢复数量一致，由玩家选择，不会自动混合扣费或自动消费钻石。
- 黄金余额与治疗扣款均限本城，不能使用其他城市黄金；钻石沿用账号共享钱包。伤兵营刷新同时返回对应余额，治疗按钮与实际扣款范围保持一致。请求城市与批次城市不符时拒绝治疗。
- 每批治疗数量支持滑块和数字输入框联动，范围为 0 至本批伤兵数，至少选择 1 名才能治疗。右侧各有黄金、钻石治疗按钮与对应 MAX；MAX 只设置数量，不提交治疗。黄金 MAX = `min(本批数量, floor(本城黄金 / 黄金单价))`，钻石 MAX = `min(本批数量, floor(floor(账号钻石) × 1000 / 黄金单价))`，与钻石费用向上取整规则一致。余额不足以治疗 1 名时 MAX 设置为 0，刷新保留 0。
- 所选数量超过某种货币的可治疗上限时，只禁用对应治疗按钮，滑块下方显示浅黄色余额不足提示。黄金或钻石单独不足时提示减少数量、使用对应 MAX 或改用另一货币；两者均不足时提示“黄金和钻石余额均不足，请减少治疗数量，或点击对应 MAX 选择当前可治疗的最大数量。”两种余额连 1 名也无法治疗时，明确提示补充黄金或钻石。数量、费用、MAX 与提示随最新余额更新，输入或拖动时保持焦点。
- 每批伤兵从受伤时间起保留 7 天。不论账户余额如何，未治疗部分到期全部消失，没有自然恢复；新伤兵入营和部分治疗均不会延长期限。
- 治疗接口在服务端核验归属、期限、数量和费用，资源扣减、兵力增加、伤兵扣减在同一事务提交。读取和治疗在到期时立即排除伤兵，后台每分钟清除过期记录。
- `V31__create_wounded_units.sql` 随后端启动由 Flyway 创建伤兵表。旧战斗不追溯补发伤兵。账号初始化、注销清理和存档导入时同步清除伤兵。

## 验证

`WoundedServiceTest` 覆盖回收率、分城分批到期、黄金/钻石治疗、金额与权限检查、并发重复治疗、实际战斗入营。
`WoundedMigrationTest` 在独立 H2 MySQL 模式数据库执行新表脚本，验证版本列和同城同兵种多批次。
`WoundedControllerTest` 通过 `X-City-Id` 验证逐城查看、跨城治疗拒绝、本城黄金与共享钻石扣款，以及治疗仅归队本城。
前端 `wounded.test.cjs` 覆盖历史坐标不拆城、城市余额、数量联动、MAX 上限与钻石取整、余额不足提示、切城重置等待状态、费用、重复点击、失败保留伤兵及旧响应隔离。

`GuildSupportTest` 另覆盖军团援军在守城及侦察机拦截后的伤兵归属，以及含援军的守方战报合计损失。
