# 派兵采集完成后自动废弃野地设计（已废止）

日期：2026-10-22。状态：2026-10-23 已废止。

当前规则已取消自动采集及自动废弃，统一为玩家手动收获、下令回城及放弃野地。升级使用 `V119__manual_gather_only.sql` 取消既有未执行自动指令，保留采集进度和返程货物。以[资源野地手动采集规则](GATHERING.md)为准；下文仅保存旧设计和历史验证记录，不作为现行行为。

## 1. 结论与范围

方案可行，可以减少自动采集结束后逐块释放领地名额的重复操作。

自动废弃属于“派兵采集”全自动任务的一次性指令，不是账号偏好，也不是野地永久属性。全自动是无人操作时的便利流程，不剥夺玩家在线手动收获/终止采集的能力；驻军自动采集同样允许在线手动收获。

原派兵采集在自动完成时开始返程，在返城抵达时才累计野地消耗并入库资源。本次将野地消耗提前到离场事务结算，资源仍须返城入库；不能直接在完成回调调用现有放弃接口。现有放弃接口还会处理驻军，自动废弃不能顺带撤回其他部队。

## 2. 出征配置

选择“采集全自动”时展示“采集完成后”单选配置：

- **保留野地（默认）**：自动采集完成后原路返城，保留野地归属，需玩家手动放弃。
- **自动废弃野地**：本次正常自动采集完成，部队开始原路返城时，满足安全条件则立即放弃归属、释放领地名额。不等待部队回到城市。

选择自动废弃时固定展示提示：

> 本次采集结束并开始返城时将自动放弃该野地，其他玩家可重新占领。采满指本次部队完成采集，不代表野地资源耗尽；野地仍有资源时也会放弃。有驻军或其他未完成任务时将保留野地并提示原因。

交互约束：

- 每次新打开出征准备默认保留，不沿用上次自动废弃的选择，避免误操作。
- 切换到全手动时隐藏此配置并清除自动废弃意图；切回全自动默认保留。
- 配置切换不清空已选兵力、随军军官和其他出征草稿。
- 提交后以服务端保存的配置为准，不提供行军中改选入口。
- 出征摘要、军情采集任务、地图详情和领地列表展示“完成后保留野地”或“完成后自动废弃”，不更改组件样式。
- 新手指引入口创建的采集草稿固定保留，不限制玩家选择全自动或全手动；普通派兵入口可自主设置自动废弃。引导入口限制不作为账号权限，后端始终执行相同的归属和安全校验。

## 3. 触发规则

必须同时满足以下条件才能自动废弃：

1. 本任务为派兵采集、全自动模式，并明确选择自动废弃。
2. 本次已成功开始采集并自然到达采集完成时间，不是取消、途中撤回、失败返程或玩家手动收获/终止。
3. 野地仍属于出征时确认的玩家、归属城市及同一归属批次。
4. 野地没有独立驻军、驻军采集或已收获待回城的驻军资源。
5. 排除本支即将返程的采集队后，没有其他尚未离场的本方采集任务、待命采集队、进驻任务及其他依赖本次归属的任务；检查覆盖该玩家所有城市，不只当前城市。
6. 没有尚未结清野地消耗的历史返程采集任务，以及会影响归属/驻军的未完成战斗或移交事务。

失败策略采用“保留优先”，不是延迟执行：

- 任一安全条件不满足，本次采集仍正常返城、正常带回收获，但不放弃野地。
- 记录具体原因，并在任务结果中提示，例如“仍有其他采集任务，已保留野地”。
- 对已选择自动废弃、但正常完成时受阻的任务，发送一封无附件系统邮件，标题为“采集完成，野地已保留”；在线同时展示 toast，军情返城任务展示具体原因。默认保留、撤回及未开始采集的失败返程不发送此类邮件。
- 本次自动废弃意图立即结束，不在之后驻军离开或其他任务完成时悄悄重试。
- 不因一支部队勾选自动废弃而强制撤回其他队伍；多队配置不设置优先级，也不由最后返回城市的旧任务触发放弃。

提交时已能确定存在上述冲突的，拒绝自动废弃配置并提示改选保留；执行时再次检查，以覆盖提交后出现的新驻军或新任务。前端提示不能替代后端检查。

## 4. 完成、返程与资源结算

推荐在同一服务端事务中执行：

1. 锁定并核对本次行军与野地有效归属。
2. 将本次最终采集量对野地的消耗结算一次，并持久化结算标记。
3. 部队按既有路线、时长进入返程，不提前归还兵力或释放军官。
4. 对明确配置自动废弃的任务执行安全检查；满足时释放本次归属，不满足时保存保留原因。
5. 保存任务结果、野地状态及持久化通知结果；事务提交后再推送前端。

资源与兵力的对外口径不变：

- 野地消耗与玩家资源入库分开处理；采集消耗可在离场时结清，玩家必须等部队实际返城才获得资源。
- 已结清消耗的返程队伍到城后，只入库资源、归还部队和释放军官，不再增加目标野地的已采量。
- 收获记在行军记录中，不依赖原野地是否仍存在、是否被其他玩家占领或是否已经刷新。
- 空资源、目标失效或未实际开始采集就折返，不触发自动废弃。
- 资源未耗尽也允许按玩家选择放弃；资源耗尽后的隐藏/异地刷新、未耗尽野地的重置均沿用现有放弃规则，不借本功能调整资源平衡。

结算应抽成可幂等的内部逻辑，覆盖自动完成及手动采集离场，避免同一字段在不同离场路径下含义不一致。手动模式仍只能手动放弃，不因结算逻辑共用而获得自动废弃能力。

## 5. 接口与数据设计

出征请求增加可选字段：

```json
{
  "targetKind": "wild_gather",
  "action": "gather",
  "gatherMode": "auto",
  "gatherAfterAction": "retain"
}
```

- `gatherAfterAction` 仅允许 `retain` / `abandon`，缺省为 `retain`。
- `abandon` 只允许全自动派兵采集，提交到手动模式或其他行动时后端明确拒绝。
- 非本人领地、归属城市不匹配、无效参数和伪造请求均不能触发放弃。
- 校验失败不扣除兵力、不占用军官、不创建任务。

建议持久化字段：

| 对象 | 字段 | 用途 |
| --- | --- | --- |
| March | gatherAfterAction | 本次完成后保留或废弃，默认 retain |
| March | gatherOccupationVersion、gatherOwnerCitySlot | 出征时确认的野地归属批次与归属城市快照 |
| March | gatherResourceSettled | 野地消耗是否已结清，防止返城重复扣减 |
| March | gatherAfterActionResult、gatherAfterActionReason | pending / abandoned / retained / cancelled 及原因，供离线结果回看 |
| WildTile | occupationVersion | 每次归属变更的单调递增批次，防止旧任务影响重新占领 |

归属批次不是单纯判断当前玩家ID：同一玩家放弃后重新占领也必须属于新批次。占领、手动/自动放弃、转移、重置和刷新等归属变更路径统一推进批次。

数据库迁移使用 `V117__gather_auto_abandon.sql`，旧任务统一保留，不自动开启废弃。迁移时冻结仍属原玩家的旧在途/采集中任务的归属批次和所属城市；已失效目标写入 `-1` 哨兵，之后不能绑定新占领。旧返程任务无法可靠还原原归属，迁移时标记消耗已处理，只保证既有货物和部队正常返城，不再追溯扣减当前野地。这一升级边界优先避免污染新归属；其旧版未记入的消耗不补扣。其他未结清的返程采集记录仍阻止自动废弃，已结清的返程队伍不依赖野地归属，不阻止释放。

运行时仅允许自动派兵采集设置 `abandon`，且必须从野地所属城市发起；其他城市仍可按既有规则采集，但应选择保留。

## 6. 并发、离线与展示

- 由后端既有采集推进流程执行，不依赖玩家在线或浏览器定时器。
- 沿用项目锁顺序，同一野地的归属检查、任务安全检查和释放操作串行化；派遣、重新占领及放弃入口共享归属保护，避免检查后又插入新任务。
- 派遣、采集推进及进驻到达先取得账号锁，再锁定并刷新野地；任务及战斗冲突使用数据库当前读，不依赖 MySQL 可重复读事务在等待账号锁前形成的旧快照。
- 完成推进、重试及并发Tick不重复结算、不重复放弃、不重复返还资源或兵力。
- 野地已被手动放弃、转移或重新占领时，旧任务的自动废弃指令失效；不能追溯删除新归属。
- 自动废弃成功后及时更新领地列表、地图归属、地图详情及所属城市领地名额；部队仍显示返程轨迹。
- 任务结果明确展示“已自动放弃野地，部队返城中”或“已保留野地：原因”。结果持久化，玩家离线后仍能回看；不写入世界系统广播。
- 受阻邮件与任务返程状态、采量结算及结果字段同事务保存；账号锁串行推进 Tick，事务回滚不留下邮件，提交后的重复 Tick 不再次发信。返城任务删除后不再保留军情卡，受阻原因仍可在系统邮件中回看，遵循既有邮件保留策略。

### 6.1 受阻通知示例

标题：采集完成，野地已保留

> 野地：粮田 Lv.1（15,15）
>
> 本次采集已完成，部队正在返城，资源将在部队抵达后入库。
>
> 未自动废弃原因：存在驻扎部队。
>
> 野地已保留，如需释放领地名额，请在其他任务完成后手动放弃野地。

邮件不附带资源或道具，不需要领取；资源只随原行军返城结算。原因包括驻军、驻军采集/待回城资源、其他采集/进驻/军事任务、归属批次或所属城市变化、目标不存在、未实际采到资源。存在多个冲突时说明本次首先命中的阻止原因。

## 7. 验收用例

- 自动 + 保留：正常完成、返城、入库，归属不变。
- 自动 + 废弃：完成并开始返城时释放归属，兵力和资源不提前入城。
- 部队采满但野地未耗尽：有明确风险提示，仍按所选配置执行。
- 手动、旧客户端、历史任务、新手指引：默认保留；伪造 abandon 请求被拒绝。
- 途中撤回、失败返程、未开始采集、手动终止：不触发自动废弃。
- 有独立驻军、驻军采集、其他城市派来的进驻/采集任务、手动待命队：保留并提示，不强制撤军。
- 多队同时完成、完成与进驻/手动放弃并发：没有误废弃、漏结算、重复资源或丢兵。
- 放弃后原地被他人或同一玩家重新占领：旧任务返城不修改新归属和新野地消耗。
- 放弃后野地耗尽刷新：返程照常入库，不依赖旧地图记录。
- 关闭页面、切换城市、重登、后端重复推进：配置及结果正确，领地名额只释放一次。

## 8. 实施边界

已接入出征界面、请求/状态数据、实体与迁移、后端采集完成/返城及归属保护流程，并增加前后端测试。全部由后端事务推进，不依赖前端倒计时，也不复用会处理其他驻军的手动放弃入口。

手动采集终止后仍原地待命，离场下达回城命令时结清采量；在线玩家手动终止全自动任务也走该路径，并将结果标记为取消，确保不触发自动废弃。驻军自动采集被手动收获后同样留守等待回城。自然自动完成时结清采量。多支队伍的结算量不超过同一归属下剩余储量，避免重复计入野地消耗。归属已变化时旧任务不能扣减新野地，已记录的既有收获仍可返城。

部署时应先停止旧版本的采集推进写入，备份数据库并执行 V117，再启动新服务和更新前端缓存版本；不支持新旧版本并行写同一采集状态。未改商城、世界广播或现有组件样式。
