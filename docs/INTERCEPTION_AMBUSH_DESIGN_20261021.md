# 出城拦截：伏击先手设计

日期：2026-10-21。状态：已按本方案实施并完成专项验收。5 秒部署时间作为首版规则落地；兵种模拟用于确认先手能改变战损，但不保证拦截方获胜。

## 1. 目标与现状

让提前占据交火位置的拦截部队获得一次明确的先手优势。普通敌袭拦截仍开放全部可用兵种；侦查拦截仍只允许空军和装甲车。

当前 `MarchService.resolveInterception` 将原来袭军队作为攻方、出城拦截军队作为守方，调用普通战斗结算。`BattleService.buildOrder` 按有效射程降序、有效速度降序排列，拦截方没有专属优先级；只增加速度不能越过射程优先级。当前相遇点按迎头相遇计算，也没有提前部署阶段。

建议同时调整行军部署、战场接敌距离和首次行动顺序。保留双方原有攻守身份，原来袭方仍为攻方，避免改变突围胜负、伤亡、战报视角与继续行军的含义。

## 2. 从出城到交火

| 状态 | 触发与行为 |
| --- | --- |
| 出城部署 | 服务端选择敌军尚未经过、己方可先到的路线交火点，部队向该点行军 |
| 设伏准备 | 己方到达交火点后停驻，准备 5 个游戏秒 |
| 伏击待发 | 准备完成后等待敌军进入交火点，不提前扣敌军兵力或生成战斗结果 |
| 发动伏击 | 敌军进入交火点，创建伏击战场，拦截方获得首次交火优先级 |
| 紧急迎击 | 无法完成提前部署，但仍可在敌军抵城前相遇时，允许普通拦截，不获得伏击先手 |

交火点必须位于敌军剩余有效路线，且满足：

`敌军到达交火点时间 ≥ 拦截部队到达交火点时间 + 5 秒`

为满足部署条件，交火点可以比原迎头相遇点更靠近我方城市。按实际路线、编队速度和游戏时间计算，不能信任客户端提交的交火坐标。接敌发生在敌军到达该点时，不在己方到达该点时提前结算。

无可用伏击点时，出征页明确显示“来不及完成设伏，可紧急迎击”。若连普通迎击也赶不上，则提示“敌军即将抵城，无法完成出城拦截”，转入既有城市迎战流程。同一时间已触发城市战斗的目标不再创建伏击。

敌军加速、减速、召回或路线改变时，服务端重算是否仍可相遇、是否完成部署；优势不能仅在派遣时确定。目标失效则取消拦截并按既有规则返城，不自动换成另一支敌军。所有倒计时使用游戏时间，停服期间暂停。

## 3. 伏击战场与首回合顺序

### 3.1 敌军进入拦截方火力范围时开战

伏击场景采用专属战场初始距离，不套用普通玩家战斗的“双方最大射程 + 1850”缓冲：

`伏击初始距离 = 拦截方能够攻击本次敌军的参战兵种的最大有效射程`

仅统计正数兵力、对至少一个敌方参战目标具备有效攻击能力、有效射程大于 0 的兵种；科技和装备按既有射程规则计算。不具备有效目标的兵种、零兵力与无射程后勤部队不参与距离计算。拦截方没有满足条件的兵种时，不凭空产生伏击伤害，转用既有交战规则。

这表示敌军进入预设火力区才触发战斗，而非从远处展开阵地。该距离只属于局部战场，不修改世界地图的行军路线、交火坐标和原目的地。

### 3.2 首回合为一次伏击交火

1. 开局不先进行双方机动，使用设伏时的战场位置结算首次交火。
2. 拦截方有合法射程内目标的兵种优先行动；同侧内部仍按有效射程、有效速度与稳定兵种顺序排列。
3. 每个兵种提前使用本回合原有攻击额度，包括既有火力密度、合法集火与余伤切换规则；同回合不得再获得一份普通攻击额度。
4. 仍在自身射程外的拦截兵种不能开火，不增加射程，也不为保证全军首发而强制双方贴脸。
5. 拦截方先发阶段结束后，敌方存活兵种使用剩余实际兵力执行本回合正常攻击；敌方同样遵守射程与目标规则。
6. 第二回合起恢复普通“双方机动 → 射程优先 → 速度其次”的流程，伏击不重复触发。

首回合无额外机动，因此短射程兵种可能要到后续回合接近后才能开火。混编仍有射程与站位取舍，不能通过混入一名短射程单位让全军免费贴近敌军。

“先手”只调整主动行动顺序，不给额外伤害、暴击、命中或防御倍率。将领属性、技能、装备、领域克制与伤亡规则沿用既有规则。满足条件的受击存活单位仍可触发“绝境反击”，不递归反击；反击与主动行动额度沿用既有规则，不改变伏击方首先主动开火的事实。

首次实际交火记为 E，八项战斗技能沿用 E、E+3、E+6…周期，伏击不额外触发一次技能。正常伏击开局有有效目标时 E=1。

### 3.3 例子

拦截方为纯步兵，有效射程 160；敌军为射程 1600 的火箭车。成功设伏后在距离 160 处开战，步兵先消耗本回合攻击额度；存活火箭车随后按实际兵力还击。第二回合恢复常规顺序。

拦截方为重坦与步兵，有效射程分别为 320、160，且二者均能攻击本次敌军：开局距离 320，重坦先发，步兵尚不能开火。敌军存活部队随后行动，步兵从第二回合起按指令机动接敌。

上述距离示例不含科技、装备与其他倍率，不代表战损或胜负预测。

## 4. 优势边界与反制

- 伏击只属于完成部署的城外拦截；紧急迎击、城市防守、普通进攻与独立侦查结算不因此改变先手。
- 不采用随机伏击成功率。部署是否完成由服务端时间和路线确定；成功设伏且能攻击有效目标时，确定获得先发。
- 每条敌军本次去程最多承受一次伏击先手，首次有效开火时才消耗该机会。取消、召回和未开火的失效拦截不消耗；撤回拦截队重新派遣、多个拦截队轮流上阵均不能刷新。
- 同时到达的多支拦截部队按服务端稳定顺序串行处理；第一场实际发动伏击后，其余拦截采用普通迎击。战后须重新检查目标是否仍有效。
- 敌军可依据已有野外粗略军情，在交火前召回或调整行军；加速可能令设伏来不及完成，但仍需经过服务端重算。交火后依靠幸存兵力和已有技能还击，不首发新增反伏击道具或堆叠额外倍率。
- 野外军情仍只展示既有粗略字段，不额外公开精确兵力、属性或科技。发现拦截部队并不自动取消其已建立的阵地优势，也不向敌军保证展示“伏击必定成功”。
- 拦截失败且来袭方突围获胜时，其幸存部队沿原目标、原路线继续行进；沿用现有行军时间处理，不因伏击自动返城。

## 5. 界面与双方战报

出征页按服务端计划展示：

- “伏击拦截：预计提前到位，部署 5 秒后伏击待发。首次交火我方优先，敌军存活部队同回合可还击。”
- “紧急迎击：无法提前完成部署，本次按常规顺序交战。”
- 部署到达时间与预计交火时间分别显示；地图中部队到位后停驻交火点，显示“设伏准备 / 伏击待发”，不继续向敌军出发城市移动。
- **大地图交汇点战斗图标（`interception-clash-icon`）**：
  - 点击出城拦截生成真实的相向行军路线，并在计算所得的迎面交汇点坐标 `[x_int, y_int]` 动态渲染专属战斗交汇标记；
  - 战斗标记包含：交锋双剑徽标（`⚔`）、战术准星高亮底盘、呼吸脉冲环以及实时剩余秒数铭牌（例如 `38s 遭遇`）；
  - 严禁点击出征即直接结算，双方未到达交汇点前保持行军状态，到达交汇点交火才产生胜负结算；
  - 攻方根据野外粗略急报亦可在地图直观看到该战斗交汇标记，拦截结束后标记自动清理。
- 战报结果仍使用“拦截成功 / 拦截失败”和“突围成功 / 突围失败”，另加“伏击先手”或“紧急迎击”战术标签。

双方使用同一条事实记录：

> 第 1 回合 · 伏击发动：拦截部队提前部署，在 [X,Y] 发动攻击，射程内拦截部队优先行动。
>
> 来袭部队完成应战，以幸存兵力还击。第 2 回合起恢复常规行动顺序。

攻方摘要可显示“遭遇伏击，敌方取得首次交火先手”；守方摘要可显示“设伏完成，我方取得首次交火先手”。具体战斗日志记录实际开火兵种、伤亡与反击，不能仅调整文字顺序伪装先手。

战报保存独立规则版本、部署是否完成、实际首次交火回合、先手方、伏击距离与是否消耗伏击机会。历史战报继续按自身快照解释，不给旧战报补上伏击标签。

## 6. 建议实现边界与验收

实现时在拦截行军中分开保存部署到达时间和预计交火时间；在战斗上下文中显式保存开局类型、伏击方、伏击已使用状态。只在伏击开局调整位置和首回合行动排序，不交换攻守双方，不用临时修改速度或射程来模拟优先级。

针对性验证应覆盖：

1. 成功部署时，敌方射程或速度更高仍由合法拦截单位首发；第二回合恢复常规排序。
2. 混编短射程单位不能越射程开火，首回合无重复攻击额度，也不意外触发贴脸倍率。
3. 敌军以伏击后的幸存兵力还击；合法的绝境反击、技能周期和余伤切换保持一致。
4. 5 秒边界、无法赶到、目标加减速、召回、已抵城、停服恢复与重复 Tick 均只有一个确定结果。
5. 同一来袭去程只获得一次伏击先手；未交火取消不消耗资格；多队同时拦截不重复触发。
6. 侦查拦截仅可派空军和装甲车，普通敌袭仍可派全部可用兵种。
7. 双方战报先手、伤亡与部队去向一致；来袭方突围获胜继续原行军，野外军情不泄露精确兵力。

- 已在战斗内核实现伏击专属初始距离和首回合行动顺序；拦截方合法攻击单位先行动，敌军存活单位随后按原攻击规则行动，第二回合恢复普通顺序。普通战斗和紧急迎击不获得该先手。
- 已实现部署阶段预览、部署/准备/待发状态、地图交火标记和双方基于战斗快照生成的伏击/紧急迎击战报；野外急报继续只返回粗略情报。
- 已为拦截结算增加相关账号锁顺序和目标抵达前结算，防止双方 Tick 重复处理同一场战斗；专项并发测试通过。
- 兵种模拟（1000 火箭车来袭）显示：对 1000 步兵时，普通交战进攻方幸存 1000，伏击时幸存 968；对 500 重坦加 1000 步兵时，普通交战进攻方幸存 1000，伏击时幸存 773。两组进攻方都获胜，符合“伏击改变战损、不保证胜利”的设计边界。
