# 军情监控终端、军团求援战报与战术防空拦截系统设计

日期：2026-10-20  
版本：`alerts-terminal-20261020-v2`  
状态：求援战报、服务端多城开盾、抵达免战与守方返程路线已实施，相关定向测试通过；源码尚未部署，不代表全量测试通过

## 1. 设计背景与定位

### 1.1 原版痛点
在传统的页游纯文本排版中，军情（情报）界面存在以下体验问题：
1. **排版缺乏节奏与层次**：单条军情卡片高度过高（>100px），多行信息杂乱堆叠，单屏仅能容纳 2~3 条，玩家必须频繁上下滚动翻页。
2. **缺乏字符级对比与视觉线索**：普通状态与高危警讯字重无差异，缺乏直观的状态指示与进度刻画。
3. **操作缺乏战术闭环**：侦查只会被动通知，在线玩家即便眼睁睁看着敌机飞临城上，也无法主动做出任何反制，极大地削弱了在线防守玩家的战术主动权与博弈乐趣。
4. **配色生硬脱节**：军情界面原先硬编码冷黑底色，与游戏主界面的蓝白/米白浅色沙盘主题产生割裂感。

### 1.2 现代极简主义终端（Modern Clean Text-SLG）
新版轻量文本排版借鉴现代极简主义终端（Terminal / Notion / 字符 UI 风格），保持零大图加载、极低耗电、秒开直达，纯靠高品质排版释放极高信息密度：

        [■■■■■■■□□□] 75% | 距: 48.2km | 兵力: ~15.2w
        目标: 主基地[342,681]      [开罩] [布阵] [呼叫救援]

[侦察]  极光要塞 · 影刃                 00:46 抵近

## 2. 界面与交互规范

### 2.1 极致信息密度与卡片排版
- **单行卡片高度**：严格控制在 38~44px，移动端与 PC 桌面单屏均可轻松容纳 6~8 条军情。
- **两行流式信息布局**：
  - **第 1 行（标题与时效）**：状态 Badge + 来源名称/军团 + 动态倒计时/状态标签。
  - **第 2 行（进度与战术操作）**：纯文本进度条 + 间距/坐标/兵力概要 + 点触即发操作按钮组。
- **纯文本微型进度条**：使用 10 阶字符块 `[■■■■■■■□□□]` 配合百分比（`75%`），直观反应行军/抵近完成度，无需加载任何 DOM 进度条图片或渐变 Canvas。
- **字符级状态 Badge**：
  - `[敌袭!]`：高危亮红（`#dc2626` / `var(--danger)`）
  - `[侦察]`：警示橙黄（`#d97706` / `var(--warn)`）
  - `[出征]`：战术行动绿（`#059669` / `var(--ok)`）
  - `[返航]`：机动蓝色（`#0284c7` / `var(--info)`）
  - `[驻防]`：友军靛青（`#818cf8` / `var(--station)`）

### 2.2 全域主题色适配
军情终端全面摒弃硬编码 `#0a0a0c` / `#000000` 背景，深度接入系统全局 CSS 变量体系：
- **晴空蓝白（默认）**：终端背景采用清晰冷白背景（`#ffffff`），边框与分割线采用柔和石板灰（`#cbd5e1`），高对比度深色文本（`#0f172a`），符合日间清爽风格。
- **沙盘米白**：复古纸面米白底（`#fbfaf6`），墨绿与青灰文字，温润护眼。
- **极简冷黑**：暗色模式采用太空黑底（`#0a0f1d` / `#0d131f`），荧光绿与警报红微光点缀。

### 2.3 经典键位与极速响应
针对老页游玩家和高阶指挥官的操作习惯，提供点触与键盘双模式快捷交互：
- `[0]`：一键秒退返回指挥大厅（`Game.go('home')`）。
- `[R]`：立即重查并刷新雷达信号（`Game.World.refreshAlerts()`）。
- `[S]`：紧急一键呼救（`Game.World.requestGuildAid()`）。
- `[1] ~ [4]`：快速分流切换过滤标签（`全部` / `敌袭` / `侦察` / `我军` / `驻防`）。
- 底部常态化展示自动轮询周期（`3s`）与雷达通信链路延迟（`响应: 12ms`）。

### 2.4 活动倒计时与进度（2026-10-20）

- 来袭、出征、返程、采集、战斗和护盾统一使用服务器游戏时间。`startAt`、`arriveAt`、回合截止和保护截止均在同一游戏时间轴，以 `G.gameNow()` 作为当前时刻；详见[停服暂停与恢复设计](SERVER_GAME_CLOCK.md)。
- 到达倒计时为 `max(0, ceil((arriveAt - gameNow) / 1000))`。移动进度按本段起止时间计算，优先取 `duration = arriveAt - startAt`；行军中显示0～99%，确认到达后显示100%。正常收到新服务器样本时，文本百分比、字符进度条和地图位置一起更新。
- 前端不按本机时间推演活动。全服停服或连接失联后保留最后样本；恢复连接后同步当前游戏时间。只有客户端断网时服务器活动仍可推进，重连可能看到实际进度变化。
- 预计真实到达时刻通过 `G.GameTime.toWallTime(arriveAt)` 换算；停服后顺延。轮询间隔、链路延迟和网络心跳仍用真实时间，不能据此推进活动进度。

## 3. 战术出城拦截系统（Tactical Interception）

### 3.1 机制设计背景
在传统 SLG 中，侦查机制往往是“必中”的单向情报获取，防守方在线除了眼睁睁等待情报被摸走外别无他法。  
出城拦截系统赋予在线防守玩家**战术主动权**：只要玩家保持在线警惕，就能调度驻城部队主动出城截击高空侦察机，在城外空域彻底粉碎敌方的情报企图。

### 3.2 截击出征界面规则（`mode-interception`）
点击侦查卡片下方的 **[出城拦截]** 按钮，系统无缝切换至出征界面，并开启拦截出征专用模式：
1. **防空对空专属兵种过滤**：
   - 仅显示具有有效对空拦截能力的兵种：
     - **空军战机**：野马战斗机（`fighter`）等所有属于 `cat === 'air'` 或 `branch === 'air'` 的制空机种；
     - **防空装甲车**：猎鹿犬防空型（`armored`，对空攻击力 64）、侦查装甲车（`recon_car`）等具备近地防空火力的机械化部队。
   - 步兵、重型坦克、后勤工程车等地面无对空能力单位被自动屏蔽，避免指挥官误派送死。
2. **动态防空战力与拦截成功率算法**：
   - 界面实时汇总当前选配部队的防空综合战力：
     $$\text{总防空火力} = \sum (\text{单位对空攻击力} \times \text{出征数量})$$
   - 依据总防空火力，动态计算对来袭高空侦察机的预估拦截成功率：
     - 基础拦截火力 $\ge 3000$：成功率 95%（极高）；
     - 基础拦截火力 $\ge 1500$：成功率 80%（高）；
     - 基础拦截火力 $\ge 500$：成功率 50%（中等）；
     - 基础拦截火力 $< 500$：成功率 20%（较低，存在漏网风险）。

### 3.3 相对运动迎头截击相遇方程与动态拦截点求解
截击编队并非瞬间传送或直接结算，而是根据**敌机当前位置、航速与我方拦截编队移速**建立相向迎面截击方程进行动态求解：

以下 $T_{\text{now}}$、$T_{\text{start}}$、$T_{\text{arrive}}$ 均为游戏时间，时长和速度按游戏运行时长计算；停服期间不更新位置或提前相遇。

1. **敌机航向与剩余航程推算**：
   - 敌方侦察机从坐标 $(E_{0x}, E_{0y})$ 飞向我方城池 $(C_x, C_y)$，总历时 $D_{\text{tot}}$，预计到达时间 $T_{\text{arrive}}$。
   - 当前时刻 $T_{\text{now}}$ 下，敌机已航行进度：
     $$p = \text{clamp}\left(\frac{T_{\text{now}} - T_{\text{start}}}{D_{\text{tot}}}, 0, 0.95\right)$$
   - 敌机当前瞬时坐标 $(E_x, E_y)$：
     $$E_x = E_{0x} + (C_x - E_{0x}) \cdot p, \quad E_y = E_{0y} + (C_y - E_{0y}) \cdot p$$
   - 敌机距我方基地剩余直线距离与航行秒数：
     $$D_{\text{rem}} = \text{hypot}(E_x - C_x, E_y - C_y), \quad \Delta t_{\text{rem}} = \frac{T_{\text{arrive}} - T_{\text{now}}}{1000}$$
   - 敌机向心航行速度：$V_{\text{enemy}} = \frac{D_{\text{rem}}}{\Delta t_{\text{rem}}}$（格/秒）。
2. **我方拦截编队航速计算**：
   - 根据选配兵种中移速最慢单位（战斗机基速 8、防空装甲车基速 5）及行军加速增益（+50%），计算编队截击移速：
     $$V_{\text{our}} = \frac{\text{slowestSpd} \times \text{speedMul}}{18} \quad (\text{格/秒})$$
3. **迎面相遇拦截时间与空域坐标**：
   - 双向相对速度为两者之和 $V_{\text{rel}} = V_{\text{our}} + V_{\text{enemy}}$，迎头相遇时间：
     $$t_{\text{meet}} = \frac{D_{\text{rem}}}{V_{\text{our}} + V_{\text{enemy}}}$$
   - 实际截击单程耗时：$\text{sec} = \max(3, \min(\lfloor \Delta t_{\text{rem}} \rfloor, \lceil t_{\text{meet}} \rceil))$。
   - 截击空域出击距离：$D_{\text{intercept}} = \min(D_{\text{rem}} \times 0.95, V_{\text{our}} \times \text{sec})$。
   - 最终截击相遇空域网格坐标：
     $$x_{\text{int}} = \text{round}\left(C_x + (E_x - C_x) \cdot \frac{D_{\text{intercept}}}{D_{\text{rem}}}\right), \quad y_{\text{int}} = \text{round}\left(C_y + (E_y - C_y) \cdot \frac{D_{\text{intercept}}}{D_{\text{rem}}}\right)$$

### 3.4 大地图真实行军生成与双向相向飞行
1. **拒绝点击即结算**：严禁在玩家点击出征按钮瞬间立即删除敌机并判定胜利。
2. **生成大地图行军记录（`March`）**：
   - 行动标记：`action = 'intercept_scout'`，目标：`[x_int, y_int]`，终点耗时：`durationMs = sec * 1000`。
   - 预扣资源与兵力：预扣往返燃油，城池驻军扣除截击出战兵力并转入行军中。
   - 敌方侦察机在 `incoming` 列表中持续保留，双方在大地图上相向对飞。
3. **战术青蓝航线与专属兵种渲染**：
   - 大地图 Canvas/WebGL 采用专属**防空战术青蓝色**（`#06b6d4` / `0x06b6d4`）绘制截击光带与机群动画，区别于普通行军的蓝色与敌军的红色。
   - 行军图标优先选用战斗机（`fighter`）或防空装甲车（`armored`）作为编队领航模型。
   - 自动跳转世界大地图，指挥官可直观观察迎面截击战局。

### 3.5 抵达拦截空域交火结算与返航闭环
1. **到达交火点判定（$T_{\text{now}} \ge T_{\text{arrive}}$）**：
   - 双方抵达相遇空域网格，触发空域对空截击交火。
   - 对空火力充足（含有战斗机或防空装甲车，或对空战力 $\ge 10$）判定**成功击落**。
   - 击落后，从雷达 `incoming` 列表中正式销毁该敌机记录，瓦解敌方侦查企图，弹出战报：`🎯【截击空战大捷】我方截击编队在 [X,Y] 空域成功击落敌方高空侦察机！敌方侦查企图彻底瓦解！`
2. **掉头返航与归建入库**：
   - 交火完成后，截击编队原地掉头返航（`returning = true`），终点指向出发城池。
   - 返航行军抵达基地后，幸存出征兵力自动归还城池仓库/驻军，出征队列释放，完成完整的截击全生命周期闭环。

## 4. 战情互通：一键呼叫军团救援（Guild Aid Broadcast）

### 4.1 操作触发方式
- **卡片快捷按钮**：敌袭或侦察卡片第 2 行右侧的 `[呼叫救援]`。
- **详情下置横幅**：展开侦查/敌袭情报卡片后的 `[一键呼叫军团救援]` 快捷横幅。
- **键盘盲操**：在军情界面直接按下键盘 `S` 键。

### 4.2 玩家交互与情报时效

1. 玩家在敌袭或侦察军情上点击“呼叫救援”，服务端读取该玩家在处理请求时可见的来袭详情，保存求援快照并发送到当前军团。客户端只提交来袭 ID，不拼接、截断或上传详情正文。
2. 军团聊天显示“📢 求援战报 · 查看来袭军情”按钮。在线成员通过既有 `guild_chat` 推送收到消息，之后进入军团频道的成员也可从聊天历史打开。消息只保存分享凭证，完整军情不受聊天 80 字限制。
3. 成员点击后在当前页面打开“求援战报 · 来袭军情”只读弹窗，不跳转个人战报页。弹窗和求援者展开来袭详情共用 `Game.World.renderIncomingIntelligence`，字段、雷达权限及未知值口径一致；以服务端处理求援请求时的投影为准，不复制可能过期的前端缓存。
4. 弹窗展示求援者、分享时间、雷达详情、分享时状态、分享时到达倒计时和预计到达时间。军情快照的 `sharedAt` 记录分享时游戏时间，不是运维审计的真实日历时间。关闭按钮、点击遮罩或按 `Escape` 可关闭，关闭后恢复原焦点；重复打开时只保留一个军情弹窗。
5. 情报明确标注“情报以分享时为准”。`arriveAt` 与 `sharedAt` 同属游戏时间轴，倒计时使用 `max(0, ceil((arriveAt - sharedAt) / 1000))`，表示分享时剩余时间，不持续更新；它和第2.4节实时军情进度分开处理。分享时状态依次按“交战中 / 候战中 / 已到达 / 行军中”判定。
6. 来袭结束、撤回或原来袭记录删除后，已分享的快照仍可读取。仅在 `arriveAt <= G.gameNow()` 时提示“已过，请确认最新战况”，不会因为真实停机跨过原日历时刻而判过期。预计真实到达时刻按当前剩余游戏时长换算，后续行军加速、雷达升级或战斗变化不会改写旧快照。需要更新信息时重新求援。
7. 接收者弹窗不显示“进入战斗”“出城拦截”“开罩”或再次求援等绑定本人来袭索引的操作，不代替军团成员实际派遣支援。

### 4.3 雷达字段与信息一致性

`WorldViewService.getIncoming` 复用 `IncomingIntelligenceService` 的服务端白名单；每级新增字段累进开放，接收者使用分享者的 `radarLevel`，不按自己的雷达等级补充或隐藏已授权信息。

| 雷达等级 | 本级新增可见详情 |
| --- | --- |
| 0 | 雷达等级、目标城市与坐标、已公开的抵达时间及状态；来源保持未知 |
| 1 | 来袭玩家、行动类型 |
| 2 | 出发地坐标 |
| 3 | 陆军、海军、空军等军种 |
| 4 | 固定兵力区间 |
| 5 | 兵种类型 |
| 6 | 总兵力 |
| 7 | 各兵种具体数量 |
| 8 | 统帅姓名、星级、等级 |
| 9 | 已探明的战斗科技、配装装备、情报来源；快照保留服务端公开的 `intelligenceAt` |
| 10 | 司令官及其军事、防御、后勤、学识信息 |

未探明或旧来袭缺失的字段沿用原详情的“未知”或缺省展示，不补算为 0，不从其他成员或敌军当前状态补取。带兵将领的有效属性和技能始终不公开。玩家名称及文本在弹窗中转义；分享读取沿用注销玩家名称脱敏。

### 4.4 接口与消息协议

| 操作 | 接口 | 请求与响应 |
| --- | --- | --- |
| 分享到本人军团 | `POST /api/game/incoming/{id}/share` | ID 支持真实行军 `march-{id}` 和旧数字来袭 ID；请求体为空对象。成功返回已持久化的 `GuildMessageResponse`，包含消息 ID、军团 ID、发送者、角色、内容、时间和头像 |
| 读取分享军情 | `GET /api/game/incoming/shared/{token}` | 返回 `{ incoming, sharedAt, ownerName }`；`incoming` 为分享时完整授权投影，`sharedAt` 为游戏时钟毫秒值 |

- 频道正文使用严格格式 `[军情:UUID]`，随机 UUID 长度 36，整条凭证长 41 字符。与已有 `[战报:UUID]` 战斗战报凭证区分，原战斗战报流程保留。
- `Game.Chat.shareIncoming` 调用 `Game.API.shareIncomingReport`，沿用军团聊天 5 秒冷却；服务端仍通过 `GuildChatService.send` 校验发言资格和冷却并广播。HTTP 返回的消息通过 `receiveGuild` 立即展示，按消息 ID 对 WebSocket 重复到达去重。
- 聊天渲染仅将严格 UUID 凭证识别为按钮；普通内容和伪造 HTML 按文本转义。关键词过滤器仅豁免完整凭证，附加普通文字时仍执行过滤。
- 聊天模块未加载时，求援入口可直接调用分享 API；只有接口确认成功才显示分享成功提示。

### 4.5 保存、事务与部署

新增 Flyway 迁移 `V107__shared_incoming_reports.sql`，建立独立分享快照表：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `token` | `VARCHAR(36)` 主键 | 随机分享凭证，不使用可枚举的来袭 ID 读取分享 |
| `owner_id` | `BIGINT NOT NULL` | 求援者，外键关联 `players.id` |
| `guild_id` | `BIGINT NOT NULL` | 分享发生时的军团，外键关联 `guilds.id` |
| `data` | `LONGTEXT NOT NULL` | 序列化的 `{ incoming, sharedAt, ownerName }` 快照 |

- 保存快照和发送军团消息处于同一事务；发言校验失败时不提交快照，不提示发送成功。
- 表不关联原来袭或行军记录，因此来袭结束不会删除快照。玩家或军团记录被物理删除时，按对应外键 `ON DELETE CASCADE` 清理。
- 求援记录不写入 `scout_reports`，不进入个人战报收件箱，不改变未读战报数量。
- 部署需通过既有 Flyway 流程执行 V107，并同步更新后端与前端资源；刷新页面后使用新消息识别和弹窗逻辑。旧文字求援不追溯转换为可点击战报。

### 4.6 身份、失败与快捷求援

- **分享权限**：服务端以当前登录玩家查找军团身份，并且只在该玩家的来袭列表中匹配指定 ID。无军团、他人来袭或已结束的来袭不能分享；不接受客户端指定目标军团或自报雷达等级、兵力。
- **读取权限**：每次读取都校验读者当前属于快照记录的原军团。其他军团、未入团或已离开原军团的玩家即使持有凭证也不能读取；求援者离团不会转移原快照的军团归属。
- **空窗防护**：没有外部威胁时提示“当前防空雷达未检测到来袭或侦查威胁，无需呼叫救援！”，不发送消息。
- **未指定军情**：快捷键 `S` 或底部入口遍历当前列表，取 `max(0, arriveAt - now) + 侦查权重` 最小项；侦查权重为 `1,000,000` 毫秒、其他为 0，用于提高敌袭优先级，不额外推断敌军战力。
- **失败提示**：失效来袭、权限不足、聊天冷却、网络异常等保留实际错误原因。读取失败只提示错误，不打开空白弹窗；发送失败不显示成功。

## 5. 城防护盾多城选择与钻石消耗机制（Multi-City Shield）

### 5.1 规则设计
- **城市独立隔离**：城防护盾以单个城市（`ownerId` + `citySlot`）为独立单位生效，主城开盾分城不共享，分城开盾亦不保护主城，彻底防范“单盾保全国”的不平衡漏洞。
- **单城与全城选择机制**：点击敌袭卡片上的 `[开罩]` 按钮，弹出专属的**城防护盾调配面板**：
  - 完整罗列当前玩家拥有的所有城市（主城与各分城）、坐标、以及各自实时的护盾状态（“保护中（剩余 3小时20分）”或“未开启”）。
  - 支持玩家自主勾选需要开盾的单座城市，或点击 `[全选所有城市]`。
- **钻石消耗标准**：
  $$\text{总消耗钻石} = \text{选中开启护盾的城市数量} \times 200 \text{ 钻石}$$
- **时间顺延叠加**：
  $$\text{shieldUntil} = \max(\text{原 shieldUntil}, \text{当前时间}) + 8 \text{ 小时}$$
  当前时间指服务器游戏时间。若所选城市已处在护盾保护中，再次开启将在原有截止时间基础上精准顺延 8 小时；停服期间不消耗保护时长。
- **钻石余额阻断**：提交时严格校验玩家当前钻石余额，若钻石不足以支付所选城市总额，立即阻断并清晰提示“钻石不足：开启当前 X 座城市护盾需 200×X 钻石，尚缺 Y 钻石”。

### 5.2 服务端开盾契约

| 项目 | 契约 |
| --- | --- |
| 接口 | `POST /api/game/cities/shield`，请求体 `{ "cityIds": [城市ID, ...] }`，使用当前登录身份 |
| 城市校验 | 按ID去重后校验全部城市归属与可用状态；空选择、非法城市、归降移交中的只读城市或余额不足均拒绝，不部分扣款或开盾 |
| 扣款与续期 | 每个去重城市200钻石、增加8小时，玩家锁串行处理，扣钻与各城续期在同一事务完成 |
| 成功响应 | `success`、`count`、`cost`、`remainingDiamond`、所选城市名称`cities`及最新`state` |
| 客户端更新 | 仅在成功响应后应用余额与护盾状态；失败保留原状态，重复点击共用当前请求，不产生本地假护盾 |

仓库护盾道具仍按道具库存消耗；军情钻石开盾是独立入口，两者共用单城续期规则，不同时扣钻与扣道具。

### 5.3 抵达免战、原路返程与双方邮件

敌军到达倒计时结束时，服务端在抵达处理及手动打开战场、创建会话前重新检查目标城市护盾。尚未开战且护盾有效时取消本次军事行动，不创建战斗会话，不能通过迎战入口绕过保护。侦查同样被拦截，不生成情报或战报；已有战斗会话继续按原规则结算，后开盾不回滚既有战斗。

拦截保留完整兵力、随军物资和军官，交换行军起终点、反转保存的路线，从处理时的游戏时间开始返程，耗时为原出征耗时且最低1秒。返城后按既有规则归队入库，不产生伤亡、掠夺或奖励。行军保存`returnReason=shield`，从来袭列表移除，重复处理不会再次拦截或寄信。

攻守双方各收到一次系统邮件，均明确“护盾期间不可发生交火”，说明行动取消、未发生战斗、伤亡或资源掠夺。攻方标题为“护盾免战：部队原路返程”，守方标题为“护盾免战：来袭已拦截”；邮件不附带战利品。`shieldBlocked`事件同步提示和行军状态，手动入口收到护盾取消结果时停止进入战斗并刷新状态。

### 5.4 守方可见的敌军返程路线

被本城护盾拦截的敌军返程时，守方地图继续显示蓝色`0x69b7ee`路线、返回方向与行进进度，无额外雷达等级门槛；攻方从自己的普通行军列表查看返程。完整状态与Tick均返回`returningEnemyMarches`，前端更新`world.returningEnemyMarches`，支持刷新和重连后恢复。

可见条件为原目标城市当前归属该守方、`returning=true`、`returnReason=shield`、无战斗会话且尚未返城。普通撤军、历史原因不明的返程和其他玩家的行军不会因此公开。该叠层不进入`incoming`、不增加敌袭数量、不提供迎战入口；返城到达或收到空列表后立即清除路线，不触发己方抵达提醒。

每项仅包含`id`（`return-march-{marchId}`）、`marchId`、`targetKind=player`、`fromX/fromY`、`targetX/targetY`、`startAt/arriveAt`、`action`及`returning=true`。不公开敌军数量、装备或将领。守方地图按当前起终点绘制返程路线，并用游戏时间插值位置和方向；完整反转路径仍保存在攻方行军记录中。

### 5.5 迁移、部署与关联设计

`V108__shield_return_visibility.sql`为`marches`新增可空的`return_reason VARCHAR(30)`，护盾拦截返程写入`shield`。旧记录保留空值，不补推返程原因或公开路线。V108是返程可见性迁移，与第4节求援快照V107独立，部署时按Flyway顺序执行所需版本并同步更新前后端资源。

源码尚未部署，未执行线上迁移或真实多人联网验收。完整城市保护范围、出发城限制及接口实现位置见 [护盾保护设计](SHIELD_PROTECTION_DESIGN.md)；双方不得越过敌方前排、图标边缘总空隙至少15px及守方坐标镜像见 [战术指挥设计](BATTLE_COMMAND_AND_DISTANCE_DESIGN.md)。

## 6. 系统健壮性与异常防护（Fault Tolerance）

在研发与修复过程中，针对以下高危运行时异常进行了全方位的健壮性加固：

1. **科技倍率空指针防护（`TypeError: Cannot read properties of undefined`）**：
   - 修复在科技数据未加载完成或离线预览模式下，`loadMul()`、`spdMul()`、`hpMul()`、`trainMul()`、`buildMul()`、`medicalMul()` 读取 `state.tech.xxx` 的崩溃问题。
   - 统一接入空对象安全回退：`var tech = (this.state && this.state.tech) || {};`。
2. **多层级兵力安全解析**：
   - 兼容标准兵力结构与营房嵌套结构：`var sArmy = (s && s.army) || (s && s.barracks && s.barracks.army) || {};`。
3. **出城拦截跨地块寻路豁免**：
   - 前端出征界面的 `bindRoutePreview` 增加 `!isInterception` 守卫，避免出城拦截发起跨地块寻路检查。
   - 后端 `MarchService.java` 的 `previewRoute` 接口增加 `targetKind == "incoming_scout"` 或 `action == "intercept_scout"` 的友好短路返回，彻底根治非法目标参数异常。
