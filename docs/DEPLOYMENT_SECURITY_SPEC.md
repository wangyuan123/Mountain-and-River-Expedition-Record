# 服务器部署安全与数据保护约定

入口为根目录 `./deploy.sh`，实际部署逻辑在 `scripts/deploy.py`。依赖 Python 3.9+、Docker Engine、Docker Compose V2；脚本不会自动安装软件、修改防火墙或执行远程安装脚本。

## 凭证连续性

- 首次部署、且目标命名卷及项目容器均不存在时，可以生成数据库密码、JWT 密钥和两项独立邮箱密钥。数据库密码为 48 位十六进制随机串；JWT 为 48 随机字节的 Base64；邮箱密钥各为 32 随机字节的 Base64。
- 已有数据时，原 `.env` 必须存在且凭证完整。脚本不会自动轮换原数据库密码、JWT 或邮箱密钥。弱密码必须另行在 MySQL 中轮换，并同步更新 `.env`。
- 恢复数据库必须配套恢复原 `.env`，尤其是邮箱数据/HMAC 密钥；生成新密钥不能恢复旧密文。
- `.env` 原子写入，权限为 `600`。临时配置目录为私有目录，结束时清理。凭证、备份均不得入库。
- `.env` 支持单行赋值、单引号值和 JSON 风格双引号值；拒绝重复键、多行值和隐式变量插值。含 `$` 的值必须用单引号包裹。
- 可在本机运行 `python3 scripts/export-mail-config.py`，仅导出 SMTP 七项设置到 `.private-deploy/mail-config.tar.gz`。服务器解压到项目根目录后，由部署入口自动导入 `.deploy-mail.env`。压缩包和成员权限为 `600`，都不得入库。导入只填补尚未完整配置的 SMTP；完整原配置保留，冲突则停止。导入不复制本机数据库密码或加密密钥，也不能替代已有数据库丢失的原 `.env`。`--check` 不落盘导入，需先运行 `--init-env` 或正式部署。

## 配置与网络

固定使用根目录 `docker-compose.yml`，不自动加载 override 文件，不接受外部导出的 `WARGAME_*`、`COMPOSE_*` 或 `MYSQL_DATABASE` 覆盖。配置写入 `.env`；项目名通过 `--project-name` 指定。

脚本让 Compose 解析最终配置，核对数据库密码、后端密钥和数据库地址，再生成私有临时配置。在该配置中移除 `db`、`backend` 全部宿主机端口映射，并拒绝它们使用 `network_mode` 或特权模式；不修改源码中的 Compose 文件。最终还会检查实际容器的端口绑定。任何查询失败都不能视为未暴露。

已有实例必须沿用原 Compose 项目名，避免因目录改名创建新卷。发现其他项目同类数据卷时默认阻止新建；确需另开独立实例才使用 `--new-instance`。此参数不能绕过目标已有数据库的凭证保护，也不改变大区数据库一致性校验。

## 升级与验收

1. 固定输入并校验配置、凭证、命名卷与项目归属。
2. 构建后端镜像；构建失败不替换运行容器。
3. 启动数据库，等待精确的 `healthy` 状态，再通过 TCP 执行实际 SQL 认证。
4. 已有实例在后端升级前备份数据库、原 `.env`、头像目录到 `backups/deploy/<UTC时间>/`。SQL 采用 `--single-transaction`，备份失败则停止升级；只有写入 `COMPLETE` 标记的目录才是完整备份。运行中的后端可能继续写入，因此该备份是数据库事务快照，不是停服后的最终数据点。
5. 更新后端，再重建 Nginx，重新解析后端容器地址。
6. 验证实际端口隔离、数据库状态，以及经 Nginx 的 `/api/auth/server`、大区 ID 和首页；全部通过才报告成功。SMTP 未配置时会明确提示注册/找回不可用，接口能力标志不代表真实邮件已送达。

升级期间会短暂停服。失败返回非零状态，不自动回滚数据库，不删除数据卷；应结合日志和配套备份人工恢复。脚本没有执行 `down`、删卷、清理镜像或自动清理备份的逻辑。

## 命令

```bash
./deploy.sh --init-env  # 准备首次配置，不启动容器
./deploy.sh --check     # 只检查配置与数据卷，不改凭证或启动服务
./deploy.sh             # 首次部署或已有实例升级
./deploy.sh --project-name <原项目名> --timeout 600
```

`--check` 会取得本地部署锁、读取 Docker 状态并创建自动清理的私有临时配置，不检查密码是否能登录实际数据库。旧 `scripts/security-preflight.py` 入口等价于 `--check`。

不要直接用 `docker compose up` 代替脚本：源码 Compose 文件包含开发用后端端口，直接启动会绕过临时部署配置。严禁执行 `docker compose down -v`。生产入口还需自行配置 HTTPS 和云安全组，仅向公网开放必要的网关端口；SSH 应限制来源。
