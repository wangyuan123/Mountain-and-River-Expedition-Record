# 山河远征录：公平策略与玩家体验改动大纲

版本：v1.0 · 2026-09-18。状态：实施路线已拟定。兵种独立数值推导、四类攻击及首轮自动化验证已落实，见 [当前兵种比例调整](BALANCE_RATIOS_20260918.md)；S01/S02 的完整场景与长期验证尚未完成，其余工作项仍为计划。

## 1. 产品目标与约束

核心承诺：**付费不买胜负，策略值得研究，失败还能再来，上线不必像上班。**

目标玩家是喜欢战争经营、侦察规划和小群体协作，接受文字战报与自动结算，但不愿靠付费或持续值守维持竞争力的人。首轮验证保留共享世界、城市经营和自动战斗，以小规模战区测试规则。

| 承诺 | 必须兑现的规则 | 验证方式 |
| --- | --- | --- |
| 付费不买胜负 | 付费不增加资源、成长速度、战力、出兵机会、情报、保护或恢复能力；赠品、会员、广告奖励和间接兑换适用相同边界 | 同初始状态、同操作、同随机种子，仅付费权益不同，经济与战斗结果一致 |
| 策略值得研究 | 侦察、编成、目标和时机能改变结果；成长有价值，但没有适合所有场景的唯一阵容 | 等成本场景对照、反制测试、玩家能解释自己的取舍 |
| 失败还能再来 | 战败有损失、有恢复路径，基础经营和再次参与能力受到保护 | 首败后恢复到可参与状态的时间、资源支出及回访行为 |
| 上线不必像上班 | 日常安排可批量完成；基础便利对所有人开放；关键对抗有明确时间边界 | 固定日程测试、必要操作时间、夜间被迫上线反馈 |

公平不等于所有账号始终一样强，也不等于弱者必胜。允许经营积累、信息判断与团队配合产生优势；需要限制付费、无上限重复劳动和不受约束的人数堆叠对这些优势的替代。

执行原则：先封住付费优势并验证核心体验，再扩展协作和商业内容；一次迭代解决一个可验收的问题。大型赛季重置、全地图补给网络、实时战斗和全面美术重制不进入第一轮。

## 3. 实施顺序与阶段出口

| 阶段 | 交付目标 | 工作项 | 完成后才能做什么 |

| 0：建立基线 | 能区分设计问题、实现问题和旧存档影响 | B01、B02 | 开始比较改动前后结果 |
| 1：切断付费优势 | 付费权益不能流入经济、战斗和恢复系统 | F01—F03 | 开展可信的公平体验测试 |
| 2：保障日常体验 | 能离线、能恢复、能正常上手和成长 | E01—E04 | 扩大对抗测试，验证核心策略 |

依赖顺序为 0 → 1 → 2 → 3 → 4 → 5。基础行为记录在阶段 0 建立，用户观察从阶段 2 开始；阶段 5 是完整验证，不是第一次看数据。阶段 1 的免费获取补位与旧状态处理必须一起设计，不能先删商城再让成长断档。

### 阶段 0：建立可比较的基线

**B01 · 规则与经济基线**

- 建立独立测试账号：新手、首败玩家、单城中期、多城中期、暂离玩家；不修改现有玩家资产。
- 记录资源产出/消耗、建造/训练/科研等待、军官与科技加成、军衔门槛、队列空转、仓库溢出、负债及忠诚变化。
- 对比每天 2—3 次安排、频繁上线、连续 24/48 小时不操作的进展与风险。区分主动战术收益与重复领取、反复点按钮带来的收益。
- 对比不同 tick 频率、调度延迟和服务重启；将时间结算缺陷与平衡调参分开修复。
- 交付：可重复场景、基线结果、确认问题清单。尚未测出的风险不标为已确认缺陷。

**B02 · 轻量体验记录**

- 记录首次进入、首次生产完成、侦察成功、首战、采集入库、首败、治疗、再次出征、加入军团、共同目标参与等服务端事件。
- 使用稳定事件标识去重，记录规则版本、测试批次和来源；时间统一，明确留存口径。
- 先用可导出的统计表即可，不先建设大型运营平台。只收集必要行为字段，不采集聊天正文或额外身份信息。
- 验收：同一结果因刷新或重试不会重复计数；能还原首次行动漏斗和首败后的恢复路径。

### 阶段 1：切断付费优势

**F01 · 付费影响清单与统一商品规则（首个公平性改动）**

- 对全部商品、礼包、会员、货币和道具画出“来源 → 兑换 → 使用 → 最终效果”，覆盖任务奖励、邮件附件和已有库存。
- 战力、资源、晋升材料、经验、技能、治疗、人口、保护、速度、队列及情报均归入竞争效果，不允许由付费直接或间接获得。
- 区分“停止售卖”和“删除玩法”：必要的成长道具可继续通过正常玩法获取；移除卖点前确认免费路径可持续且耗时合理。
- 建立服务端权威商品目录与效果分类，前端消费同一目录；拒绝旧商品 ID、别名或旧客户端绕过规则购买。
- 交付逐项处置表和服务端边界；外观商品尚未就绪时允许商城暂不销售，不用数值礼包填空。

**F02 · 货币、恢复与便利功能脱钩**

- 将商业货币限定于外观和展示权益；正常玩法资源用于经济与恢复。禁止两者兑换、付费物品转售换资源或赠送后套现为战力。
- 移除钻石治疗等竞争性消费入口，由统一的免费恢复机制承接；保护、侦察和行军规则对所有人一致。
- 队列预设、批量操作、基础战报分析与通知等减负功能免费提供，不能成为会员战术优势。
- 模拟发钻只存在于明确隔离的开发/测试环境，正式环境不能仅依赖防沉迷开关控制开放。
- 验收：同条件账号仅商业权益不同，生产、成长、侦察、行军、战斗和恢复完全一致；从 API 直接请求同样无法绕过。

**F03 · 旧资产与公平测试状态处理**

- 盘点余额、库存、已生效的护盾/速度/月卡等效果，以及已使用道具带来的等级、装备、晋升和多城优势。不能只删商品就宣布存量世界公平。
- 来源无法追溯的资产标为未知，不推测为付费所得。当前真实支付未接通，不虚构退款记录。
- 开发验证默认使用独立测试库的统一起点账号；现有世界保存原状，迁移另写明确映射、预演结果和恢复方案。
- 涉及现有世界资产回收、重置或永久削弱的操作，在实际实施前提供影响清单并单独确认；本大纲不授权删档。
- 验收：重复迁移不重复发放；旧客户端和旧效果不会重新打开付费优势；余额、资产变化可核对。未经存量处理的世界不计入公平测试结果。

阶段出口：所有竞争效果都能沿来源链证明不依赖付费，必要免费路径没有断档。该阶段不以“充值按钮隐藏了”作为完成标准。

### 阶段 2：让玩家能离线、能再战、能成长

**E01 · 战争窗口与基础保护**

- 首版推荐战区统一公布作战窗口，提前预告，窗口外禁止对玩家城市发起或结算新的敌对战斗；野地与 NPC 保留日常玩法。
- 为窗口外抵达、跨窗口返程、侦察、已在途攻击、服务器延迟明确一致的处理规则；以服务器记录的计划时刻和规则版本判定，不能让结算线程先后决定是否合法。
- 提供人人一致的新手和战后基础保护；明确主动攻击如何影响保护，避免保护内无限骚扰。取消护盾附带的产量奖励，战争减产另按公平性与恢复负担验证。
- 同一防守玩家的连续攻击与掠夺采用合并预算/冷却，防止轮换攻击者绕过；具体数值在基线测试后定。
- 首轮在单一时区战区测试，窗口长度、频率和预告提前量属于试验参数；以后多时区分区，不要求玩家配合作息外值守。
- 验收：出发和到达均校验；窗口外城市不会被结算新的战斗；跨城、多人轮攻和临界时间一致；玩家能看懂下一次风险时段。

**E02 · 首败保障与战后恢复**

- 保留玩家城市不被永久夺取的现有边界；城战争夺资源或阶段目标，第一轮不开放摧毁主城。
- 增加统一基础伤兵回收，医疗与军官只做有限改善；具体回收率先模拟资源消耗和连续战斗，再定数值。
- 提供不依赖付费的基础恢复路径。恢复“能参与一次合理难度行动”的兵力，不自动补回战前全部强度。
- 伤兵到期规则改为可理解、可预先安排的处理方式；优先试验免费恢复队列与到期自动处理，避免必须赶在某天上线点击；经济不足时明确降级处理规则。
- 恢复补助不能通过自杀、互刷战损、循环治疗产出净资源、声望或额外兵力。
- 初始体验目标：新手普通首败后能在下一次日常登录参与一场低难度行动；未达成就先调损失和恢复机制。
- 验收覆盖主动战败、防守失败、无黄金、连续失利、暂离七天、同批伤兵并发治疗与补助重复领取。

**E03 · 成长曲线与日常减负**

- 检查晋升随机材料是否导致长期卡关，提供稳定积累和明确保底；晋升名额与出兵能力的增长分阶段校准。
- 控制多城产量、科技、军官、装备与出兵上限的叠加效应。优先通过成长软上限、明确的战场投入上限和进度分区验证，避免隐藏补偿改变胜负。
- 基础建设/生产预设、批量安排、免费提醒对所有玩家开放，减少多城重复操作。
- 结算按真实经过时间处理；修复频率相关误差时保留合理资源守恒，不能以提高离线收益掩盖错误。
- 提供新人/回流追赶路径，奖励有边界，不允许反复离开、建小号领取后输送主号。暂不引入强制赛季删档。
- 初始目标：日常基础管理可在每天 2—3 次、合计约 20—30 分钟完成；额外在线主要获得战术与社交机会。这是待实测的设计目标，未验证前不用于宣传。
- 验收同时观察正常经营、仓库满、队列空转、破产、8 城管理和 48 小时无操作，不以单城顺风账号代表所有玩家。

**E04 · 首次体验与手机操作**

- 保留“建设 → 侦察 → 首战 → 运回补给 → 再建设”的真实闭环，把界面聚焦到当前目标、原因和预期结果。
- 首次出征前显示已知敌情、信息时间、预计往返时间及主要风险；不泄露未侦察数据，也不承诺必胜。
- 初始目标：前 10 分钟完成一次有意义的侦察/出征选择，首次会话尽量在 15—20 分钟内完成行动闭环；先记录实际耗时，再调整等待和奖励。
- 首战失败应有可理解原因和下一步，不能把付费作为解法；共享资源点被他人占用时能换目标。
- 验收：陌生玩家无口头指导能完成；手机窄屏可读可操作；暂停、换城、断线恢复不会丢进度。

阶段出口：公平获取和恢复可持续，正常生活作息能参与，首次体验无明显断点。未通过前不增加需要值守的军团战争。

### 阶段 3：让策略产生可解释的优势

**S01 · 战斗基线与成长倍率校准**

- 建立等资源预算、等生产时间、等出征容量的场景组，分别比较编成，不把“等单位数量”当成唯一公平标准。
- 覆盖纯兵种、混编、攻守双方、射程/移动、军官/科技梯度、城防及不同目标；固定种子复现，跨多个种子观察分布。
- 检查攻击平方、技能连乘、先手、余伤继承和取整是否放大优势；例如其他条件不变时，攻击增加 10% 会令公式中的攻击平方项增加 21%，需要和防御、成本一起评估。
- 先列失衡结果，再改公式或数值；不预设相克必须提高到某一倍，也不为追求五五开抹去兵种特点。
- 验收：测试覆盖范围内，无一套编成在各类等预算场景普遍占优；主要编成都有成本合理且玩家可理解的反制路径。

**S02 · 限制纵向碾压，增加编成取舍**

- 军官和装备从纯倍率堆叠转向有限的战术专长；专长存在成本、条件或互斥，不能把多个最优效果全部装满。
- 所有影响战术选择的内容可通过正常玩法稳定解锁；随机招募提供可预期的定向获取路径，不卖独占兵种或指挥官能力。
- 成长增加选择和经营效率时，同步检查是否又形成无限资源/兵力滚雪球；对照新老玩家差距与多城投入。
- 优先把现有侦察、射程、兵种、目标选择做好；地形战斗加成与复杂补给系统按实验结果逐项引入。
- 验收：至少形成三种适用场景不同的有效编成；侦察后调整编成或目标能在预先定义的场景中改善结果；弱势一方有撤退、绕行或换目标的选择。

**S03 · 战前判断与战后解释**

- 战前区分已知、过期和未知信息，展示大致风险与主要克制关系，不提供未经侦察的精确胜率。
- 战后先展示损失、收益、可救治数量和主要转折，再展开详细回合；解释射程、克制、指挥与兵力差的作用。
- 结果和解释来自服务端实际结算，保存规则版本与必要快照；基础分析免费，不能凭文案猜测胜败原因。
- 验收：玩家能说出至少一个可调整的决策；历史战报升级后仍可阅读；双方可见信息各有边界。

阶段出口：玩家能感受到决策差异，并能通过战报理解结果；积累优势没有完全吞没战术空间。

### 阶段 4：验证军团协作特色

**C01 · 一个小规模共同目标**

- 首个原型推荐“侦察并控制补给点，完成共同运输目标”。先选一块受控区域，不重建整个世界物流。
- 将侦察、控制、运输等任务分解为不同投入角色，低成长成员也能完成有意义的一环。允许异步接力，约定结算时段，避免全员长期同时在线。
- 首轮优先测试共同 PVE 目标；通过后再增加双方争夺，复用阶段 2 的时间和损失边界。
- 记录真实目标贡献，展示协作战报。奖励有限，主要用于阶段荣誉与正常进度；不授予无限叠加的永久生产/战斗增益。
- 初始目标：3—5 名活跃成员也能完成一个基础目标。人数是测试配置，不据此承诺所有规模都已平衡。
- 验收：人数少时仍可玩，运输角色不是无聊等待，临时缺员可调整计划，不能靠最后一击拿走所有贡献。

**C02 · 限制人数碾压与互刷**

- 每个目标采用公开的参战/运输投入预算与报名锁定规则，限制后援轮换和临时退团换团绕过。
- 审查允许存在的资源转移、掠夺、战损、声望和奖励路径，针对循环获利做上限及贡献校验。
- 对同一受害者的限制必须跨攻击者累计；不能只限一个账号每天打几次。
- 先修经济规则和服务端校验，再辅助记录异常；不把同 IP 直接等同小号作弊，不宣称能彻底消除场外联盟。
- 验收：互相放水、轮换小号、拆分运输、重复领取与跨军团切换不能无限制造收益；正常朋友协作不被误伤。

阶段出口：玩家有自发组织和复盘的理由，胜负与贡献不只由成员数量决定。

### 阶段 5：验证商业与市场

**M01 · 第一批纯展示商品**

- 先做少量高质量军旗、头像框、城市外观和战史展示，明确购买内容、展示位置和永久/期限属性。
- 外观不能遮挡单位、降低敌我识别或改变地图交互范围；敌方识别信息保持统一清晰。
- 支持者会员仅提供明确展示权益；不卖资源、成长、保护、情报、恢复、参战资格或基础便利。不以连续签到维持已付费权益。
- 第一轮暂不做抽取式商业内容和复杂通行证，减少定价与公平验证变量。
- 技术验收通过后才能宣传公平；真实购买意愿要靠实际合规销售验证，模拟充值和问卷喜欢均不能替代收入证据。

**V01 · 陌生玩家验证与投入决策**

- 先用 20—30 人观察操作和规则理解，再以累计 100—200 名目标玩家分两批验证；各批至少观察四周。按来源、规则版本、进入日期区分，避免把不同版本混算。
- 记录首次闭环完成率、次日/第 7 日/第 28 日留存、首败后 24/48 小时再参与、基础管理用时、自发组队、邀请及公平性反馈。
- 留存以同批首次进入玩家为分母，次日、第 7 日和第 28 日分别统计对应日有有效玩法行为的账号；排除开发账号和模拟购买，不能只统计完成新手的人。
- 初始观察线：首次会话闭环完成率 60%、次日留存 30%、第 7 日留存 15%。这些是内部假设，不是行业标准，也不是达到即可盈利；同时报告分母与人数，小样本只判断方向。
- 战败玩家需完整观察，包括没有回来治疗的人；访谈流失者，不能只问留下的核心玩家。
- 两批都在同一环节大量流失：停止增加推广，集中改该环节；出现稳定四周参与、自发组队和邀请：再扩大样本，验证真实付费及获客成本。
- 商业决策看留存、每新增玩家的生命周期净贡献、获客成本和持续开发/运营费用，不靠少数高消费个例判断成功。
- 正式销售前完成既有发行、支付、实名防沉迷及素材权利事项；当前原型测试与正式商业发行分别安排。

## 4. 迁移、验证和迭代完成标准

每个工作项完成时更新本文件状态，并附规则说明、实际改动、验证结果、已知限制和下一项。任务完成应体现玩家行为变化，不能仅以新增页面或接口数量衡量。

1. 先写清当前规则、目标规则及边界例子；精确数值在所属任务中定，不在大纲阶段伪装成已验证平衡。
2. 改动涉及资源、兵力、道具、治疗、奖励和购买时，验证服务端权限、事务、并发、重复请求与资源守恒；UI 隐藏不能代替后端限制。
3. 时间规则覆盖出发/到达、窗口开始/结束、重启、跨天、离线和跨城；经济同样受规则版本约束，不能让进行中的行动被新版本意外改判。
4. 先在独立测试状态验证。涉及存量数据时使用新增 Flyway 迁移并预演；不修改已应用迁移，不自动清空或覆盖现有世界。
5. 有必要的逻辑变化补针对性测试，运行相关前后端测试；发布候选按项目要求完成全量验证与必要的独立 MySQL 迁移验证。纯文档更新不运行游戏测试。
6. 涉及界面时检查手机/桌面、断线恢复与多人状态；只做针对性的只读检查，不运行自动格式化或 `eslint --fix`。
7. 回退方案区分代码和资产：已发放/已消耗的资源不能靠回退代码撤销，须保留变化记录并另行补偿或迁移。

尚待实验确定的参数：作战窗口时长与频率、战后保护期、基础伤兵回收率、恢复成本、掠夺预算、晋升保底周期、战场投入上限、成长软上限和外观价格。先坚持公平边界，再用场景与玩家数据定参数。
