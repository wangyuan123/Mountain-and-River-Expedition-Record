# 科研工期、城市双队列与终局项目设计

日期：2026-10-19；工期更新：2026-10-20。版本：`research-city-dual-20261020-v7`。状态：四项科技10级扩展、五条常规工期曲线已接入源码；城市双队列、终局项目仍待实施。

本方案保留资源研发独立并行、终局项目及现有科研加成，并区分五条常规工期曲线：普通科技首级3分钟、末级15天；资源科技首级2分钟、末级12天；三项机动科技首级均5分钟，燃烧引擎、舰船动力、喷气推进末级分别20、28、28天。这里的末级天数仅指9→10级。武器装备、仓储技术、侦察技术、雷达预警由5级扩至10级，统一使用完整普通曲线；仓储与装备保留原满级效果，侦察每级先手+5、满级+50点，雷达每级先手+2、满级+20点。城市队列目标规则为：**每座城市各有一个资源研发队列和一个普通研发队列，开工必须满足本城科研中心及目标科技的条件。**

详细数值见 [设计配置与工期测算](balance/research-queue-duration-design-20261019.json)。当前源码已接入四项科技10级扩展、68件装备分档、主动侦查与来袭情报十级权限、五条常规工期曲线，并移除24小时工期上限。城市双队列与终局项目仍为待实施设计，运行队列仍维持全帝国单任务。V103升级迁移与版本化导入已编写，尚未执行生产迁移或部署。

时间口径（2026-10-20）：本文秒、分钟、小时、天及累计工期均指服务器有效运行的游戏时长。当前科研任务已使用持久化游戏时钟，停服不消耗剩余工期，恢复后继续；未来城市双队列和终局项目也必须沿用此规则。前端倒计时只读服务器样本，不按本机时间外推；详见[停服暂停与恢复设计](SERVER_GAME_CLOCK.md)。本次时间口径同步不表示双队列或终局项目已经实施。

## 1. 科技共享与城市分工

科技等级及解锁成果继续全帝国共享；城市负责提供研究场所、支付资源和承担研发任务。完成后，各城按自身设施和原有效果范围享受成果。例如粮食产量研究完成后，全帝国城市采用该科技等级计算各自城内粮食产出，不增加野地采集收益。

| 规则 | 设计 |
| --- | --- |
| 每城资源队列 | 1条，仅研发粮食、钢铁、石油、稀矿产量 |
| 每城普通队列 | 1条，研发其余常规科技或终局项目 |
| 开启条件 | 本城科研中心已完成且可用，至少Lv.1 |
| 单个任务条件 | 继续检查目标等级对应的本城已完成建筑、已完成科技和资源条件 |
| 占用方式 | 一个队列同时只运行一项；本版不增加自动候补或自动连升 |
| 两组之间 | 可同时运行，不能互相借用空闲队列 |
| 城市之间 | 不同城市的同组可同时研发不同科技，各自使用本城条件与加成 |
| 同一科技 | 全帝国最多一个进行中的任务，暂停任务仍占用；不能重复研发同一级或提前并研后续等级 |
| 科研中心数量 | 每城固定提供两组各1条，不随中心等级或中心数量增加队列 |
| 城市状态 | 建设中、非本账号所有或归降移交冻结的城市不能新开工 |

队列归属与页面的四类科技分支分开：后勤分支中的训练加速、建筑加速、医疗技术、军需补给、负重、仓储、战俘收编仍使用普通队列。

主城研究“攻击科技Lv.6”期间，分城可以研究“防御科技Lv.6”，也可以同时研究“粮食产量Lv.6”；分城不能再研究攻击科技，也不能提前研究攻击科技Lv.7。

当前军衔规则最多支持8城，因此最多16条城市队列。四项资源科技决定全帝国最多同时运行4项不同的资源研发；普通科技也受到未满级项目数量和本城前置条件限制。队列数量不等于无条件开放的研发能力。

### 2.3 曲线生成公式

前五级使用上表中的体验锚点，满足“几分钟→十几分钟→几十分钟→几小时→十几小时”的节奏；资源组相应更短。6～10级从5级工期向指定的10级工期等比增长，基础工期四舍五入到整分钟：

```text
n = 目标科技等级
A = 本曲线4→5级基础秒数（普通及机动43200，资源21600）
E = 本曲线9→10级基础秒数
r = (E / A)^(1 / 5)

n ≤ 5：读取前五级固定工期
6 ≤ n ≤ 10：基础秒数 = 60 × round_half_up(A × (E / A)^((n - 5) / 5) / 60)
```

普通、资源、燃烧引擎、舰船动力、喷气推进的后段每级倍率分别约为1.974350486、2.168943542、2.091279105、2.236853829、2.236853829。例：普通5→6为`12小时 × 30^(1/5)`，取整后23小时42分钟；普通9→10恰为`12小时 × 30 = 15天`。

每一级都从原始A和E直接生成，不使用上一等级已取整的结果递推，也不使用已截短的展示倍率计算。生成后保存整数秒表供前后端共享，避免公式或取整方式不同。基础表先取整分钟；应用全部速度加成后再将实际工期取整到秒。

前期研发用分钟提供持续反馈；中期采用小时至一天的安排；高阶研发承载多日目标。资源组每一级均比普通曲线更快，并且独立占用资源队列；三项机动从6级开始按军种区分长期投入。

## 3. 加成公式及锁定时点

```text
L = 本城已完成且可用的科研中心等级，限定0～10
K = 本城市长有效学识，包含装备及套装；未任命市长时为0
S = 本城市长格物致知等级，限定0～5；未任命市长时为0

速度倍率 = (1 + 0.01 × L) × (1 + 0.001 × max(0, K)) × (1 + 0.04 × S)
新任务工期秒数 = max(5, round(目标等级基础秒数 ÷ 速度倍率))
```

科研中心每级+1%，满级+10%；学识每点+0.1%，100点为+10%，按点连续计算；格物致知每级+4%，满级+20%。三项独立相乘。建筑加速、训练加速、其他城市的市长或科研中心均不参与。

取消原24小时截断。新任务基础工期表的最大值为28天（2,419,200秒），启动时校验配置不超过该值；不要对暂停顺延后的结束时间或旧任务剩余时间重新套28天上限。

两条本城任务各自在开始时锁定费用、工期、使用的建筑等级、市长有效学识、技能等级、规则版本和前置快照。开工后的中心升级、装备调整、技能升级、更换市长及规则热更新只影响后续任务。同一市长可同时为本城两组提供加成；每座城只计算自己的市长。

## 4. 开工与跨城并发规则

一次开工按以下顺序在同一事务内完成：

1. 固定请求的城市上下文，确认玩家持有该城、城市可用且未冻结。
2. 锁定玩家记录，结算本账号各城已到期且未冻结的任务，释放任务对应的槽位和科技锁。
3. 查全帝国已完成科技等级，目标等级严格等于当前等级+1，检查上限与科技前置。
4. 检查全帝国没有该科技的其他运行或暂停任务；旧共享资源科研还需检查其覆盖的四项资源科技。
5. 判定资源/普通分组，检查本城对应组没有任务；另一组及其他城市的任务不构成阻塞。
6. 检查本城科研中心及目标等级要求的已完成建筑。正在升级的建筑按已完成等级；处于拆除、降级而不可用的建筑不作为新前置。其他城市不能替代本次任务的科研中心和配套建筑。
7. 检查并扣除本城资源，按本城加成生成工期，保存任务和快照。

保留现有科研中心自身升级链中的显式跨城条件（例如建设10级中心时所属沿海城市的军港条件）；这不等于研究舰船动力时可用另一城的军港。本方案新增终局项目的建筑前置全部要求在开工城市。

资源组前置示例：粮食产量目标N级需本城中心N级和农田N级；钢铁/石油/稀矿分别检查炼钢厂/石油基地/稀矿厂同级。四项扩级科技采用第2.4节的新10级前置，其余普通科技继续读取现有逐级前置配置；如前置增加科技节点，只承认全帝国已完成科技，不承认正在研发目标等级。

冻结与完成竞争、加速与完成竞争、双击开工均使用同一玩家锁及任务行状态，保证只扣费、授予成果、退款或消耗道具一次。

## 5. 取消、暂停、建筑与城市变更

- 取消：必须指明任务，按该任务保存的实付费用返还80%，向下取整，退回开工城市；同时释放队列和全帝国科技锁。不返还已消耗加速符。
- 加速：必须指明任务ID，校验所属玩家、所属城市及冻结状态；加速符只减少这一项任务剩余时间，不同时作用两组或其他城市。
- 到期：按游戏时间轴上的结束时间及ID顺序结算本账号所有可完成任务，科技等级与成果全帝国共享。服务器正常运行时玩家离线仍持续计时，回到页面补结算已到期成果；全服停服不推进工期，不因重启补算停机时长。
- 冻结：归降移交冻结本城两组任务，解冻按各自在游戏时间上经过的冻结时长顺延；其他城市在服务器正常运行时继续计时。全服停服由统一时钟暂停，不再重复叠加停机时长。冻结期间不允许开工、取消或加速。
- 建筑变更：开始后保留前置快照，拆除/降级若使本城任一运行任务不再满足已付费前置，拒绝该建筑操作。建筑升级不反向提高已开工速度。
- 城市接管或销毁：任务及未完成成果不转给新城主；沿用原城市资产处置流程原子撤销原主任务并释放全局科技锁。此事件不另发科研退款，避免退款与城市资源转移重复计算；普通主动取消仍适用80%退款。
- 主城迁移或城市序号重排：任务随真实城市迁移，不因旧citySlot被复用而挂到另一座城市。后台批量改归属须走同一任务清理流程。
