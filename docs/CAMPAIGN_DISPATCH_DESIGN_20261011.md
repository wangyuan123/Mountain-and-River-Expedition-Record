# 讨伐入口与战后占领配置设计

设计日期：2026-10-11。实施日期：2026-10-12。状态：已实现并完成定向验证。

地图和目标列表统一提供「讨伐」入口。玩家在出征准备中选择「是否占领」：开启采用现有征服结算，关闭采用现有掠夺结算。兵种、战斗规则、收益数值、接管条件与任务计数仍沿用当前实现。

## 1. 入口和出征界面

所有原来同时提供「征服」「掠夺」的目标卡片、列表及地图详情，合并为一个「讨伐」按钮。原来只提供征服的无资源野地，也改为「讨伐」。侦察、宣战、采集、派遣、运输、调遣和驻防入口按原条件显示。

玩家城市的讨伐按钮沿用当前战争窗口、军团外交、护盾与保护期检查。统一入口不会放宽攻击资格。

出征页保留「出征准备」标题，「行动」显示「讨伐」，提交按钮显示「出征讨伐」。在目标信息之后、兵力选择之前加入「战后处置」区域，玩家先确定目的，再配置部队。

```text
出征准备
行动：讨伐    目标：铁矿 Lv.5（120, 86）

战后处置
是否占领    [开启]
胜利后占领该野地，之后可驻军采集；本次战斗不直接带走野地资源。

占领成功后部队
● 自动返城    ○ 原地驻守

兵力选择 → 路线与补给 → 战斗方式 → 指挥官 → 携带资源
本次讨伐：尝试占领 · 自动返城
[出征讨伐] [返回]
```

「是否占领」使用一个明确标注开启／关闭状态的开关，不再出现两个并列的攻击入口。配置影响胜利后的处理，不能承诺一定接管玩家城市。

## 2. 选项、默认值及状态

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| 是否占领 | 开启 | 延续现有普通攻击入口默认采用征服结算的行为 |
| 占领成功后部队 | 自动返城 | 仅野地且开启占领时显示；原地驻守沿用现有留守功能 |
| 战斗方式 | 沿用当前规则 | 野地默认自动，其他非玩家目标默认手动；玩家城沿用当前战术会话 |

普通入口每次选择新目标时初始化默认值，不跨目标继承上次的占领开关。任务跳转可明确预选开启或关闭，引导要求占领野地时预选开启。

配置保存在本次出征准备状态中，修改兵力、指挥官、路线或战斗方式不会重置。切换开关只更新处置说明、相关部队选项、摘要与路线请求，不重建整张表单，避免丢失已填兵力及携带资源。

野地开启占领时，显示「占领成功后部队：自动返城／原地驻守」。这与地块归属是两件事：自动返城仍保留野地归属；原地驻守才会让幸存部队留在野地。现有名为「占领目标」的留守选项因此改名为「原地驻守」。

关闭占领时隐藏部队去向配置，胜利后自动返城。原先选择的驻守值可在当前草稿中暂存，再次开启时恢复；实际提交关闭状态必须使用自动返城，不能把隐藏的驻守选择提交为有效配置。

出征请求成功后清除草稿，行军期间不能修改本次结算方式。失败时保留原草稿与全部表单输入，展示服务器返回的原因。

## 3. 各类目标的实际行为与界面说明

| 目标 | 开启占领 | 关闭占领 |
| --- | --- | --- |
| 有资源野地 | 胜利后取得地块归属；不立即装载野地资源；部队返城或驻守 | 胜利后按幸存部队负重取得剩余资源，不改变归属，部队返城 |
| 无资源野地 | 胜利后占领地块，支持返城或驻守 | 不支持；与现有后端拒绝无资源野地掠夺的规则一致 |
| 真实玩家城市 | 使用原征服结算；战后民心为 0 且军衔名额充足才接管；忠诚为 0 的参战指挥官可被俘虏 | 使用原掠夺结算；不接管、不俘虏指挥官 |
| NPC、流寇 | 使用原征服资源及经验结算；胜利后仍按原规则清除或替换目标 | 使用原掠夺资源及经验结算；胜利后仍按原规则清除或替换目标 |

真实玩家城的开启状态显示：

> 胜利后尝试接管城市：需要敌城战后民心为 0，且我方城市数量未达军衔上限。成功时保留建筑、建设队列和普通资源，清除其余军事资产。未能接管时取得全部普通资源，含黄金。忠诚为 0 的敌方参战指挥官可被俘虏。

城市目标的关闭状态显示：

> 胜利后取得仓库保护外的非黄金资源，不接管城市，也不俘虏指挥官；胜利结算经验为占领模式的一半。

NPC／流寇的开启状态必须补充：

> 该目标无法保留为我方领地，胜利后会清除或刷新；开启后缴获全部普通资源，含黄金。

NPC 的「是否占领」在本次合并中仍按用户指定映射两套结算，但不能增加原系统没有的 NPC 接管能力，也不能向玩家显示「将获得一座 NPC 城市」。这是统一配置名在当前目标规则下的限制。

无资源野地固定开启，开关禁用，并显示「该地块没有可夺取资源，仅支持占领」。有资源但已耗尽的野地不等同于无资源类型：沿用当前校验，关闭时显示「剩余资源为 0，本次胜利不会取得野地资源」，不新增服务器限制。

玩家城市名额已满或当前民心大于 0 时，仍允许开启占领。前者仍可取得原征服资源并俘虏符合条件的指挥官；后者须以本场战后民心判定，不能在出征时断定不可能接管。若缺少可靠情报，展示条件说明，不推测敌方民心、库存或可取得的精确资源。

战败统一沿用现有败战结算，不占领、不发放胜利资源。开启占领也不自动变成更高伤害或更低战损。

## 4. 请求与后端兼容

本轮采用前端统一入口、请求映射复用现有动作的方案，无需新增数据库字段或重写战斗结算。

前端本次出征草稿新增语义：

```js
{
  action: 'campaign',          // 仅用于前端讨伐界面
  occupyTarget: true,          // 决定本次采用哪套结算
  conquerMode: 'withdraw'      // 仅野地开启占领时有效，原字段继续表示部队去向
}
```

建立统一的动作解析函数，路线预览和正式出征都使用它：

```text
campaign + occupyTarget=true  → action=conquer
campaign + occupyTarget=false → action=plunder
```

野地开启占领时提交所选 `conquerMode=withdraw/occupy`；关闭时归一为 `withdraw`。其他目标继续归一为 `withdraw`，不增加驻守玩家城或 NPC 的行为。

`campaign` 不直接发送给当前后端。当前 `DispatchRequest` 和服务端白名单仍识别 `conquer/plunder`。行军记录中的 `action` 已能持久保存实际模式，战术会话也沿用这个冻结值，服务器据此结算；无需重复保存一个可能与 `action` 冲突的占领布尔值。

历史或内部入口若仍传 `conquer/plunder`，进入新的讨伐页时分别初始化 `occupyTarget=true/false`。缺少占领值的普通讨伐入口采用开启默认值。非讨伐动作原样传递，不进入此映射。

路线预览不能仍发送 `campaign`，也不能只在正式提交时映射。切换配置后触发预览刷新，缓存／请求序列包含实际动作；旧的异步预览结果不能覆盖新配置。正式提交读取当前草稿与对应预览，沿用现有装备版本及服务端校验。

继续兼容旧客户端、已有行军、已有战术会话及 `/game/wild/conquer` 兼容接口；正在进行的战斗按原动作结算，不进行批量数据迁移。

## 5. 地图、行军、战报和任务文案

地图详情、目标列表以及目标弹层仅保留「讨伐」。行军动作标签将 `conquer/plunder` 均显示为「讨伐」，详情显示「战后处置：尝试占领／仅夺取资源」。返城、驻守等阶段标签仍按实际状态显示。

新的战报界面标题统一为「讨伐报告」，使用行动配置与实际结果分别展示：

- 行动配置：尝试占领／仅夺取资源。
- 野地结果：已占领／未占领；部队返城／原地驻守。
- 玩家城结果：已接管／未接管及实际原因；符合条件的指挥官俘虏结果继续显示。
- NPC／流寇结果：已击败；不能显示已占领或已接管。原征服分支中的 `cityConquered` 标记不能直接当成 NPC 获得领地的展示依据。
- 战利品、经验、民心、声望和普通战俘继续使用原结算快照。普通战俘与指挥官俘虏不同，前者两种模式均可产生。

已有战报 JSON 和已保存正文不改写。渲染层兼容历史动作，旧正文可保留「征服／掠夺」等原始词汇；不把历史征服胜利补算成真实城市接管。

任务仍区分原来的实际事件，只改变玩家看到的操作指引：

| 当前事件 | 新操作指引 | 计数条件 |
| --- | --- | --- |
| `WILD_PLUNDER` | 讨伐野地，关闭「是否占领」并取得资源 | 沿用原成功取得野地资源条件 |
| `WILD_CONQUER` | 讨伐野地，开启「是否占领」并占领成功 | 沿用原野地占领条件 |
| `PLAYER_PLUNDER` | 讨伐玩家城市，关闭「是否占领」并获胜 | 沿用原玩家掠夺胜利条件 |
| `PLAYER_CONQUER` | 讨伐玩家城市，开启「是否占领」并接管成功 | 沿用原真实玩家城接管条件 |

任务跳转预选对应模式。现有新手野地占领引导继续使用占领模式，不因统一按钮落入取资源模式。已有任务进度不合并或清零，单次战斗也不会同时满足占领与掠夺两个事件。

## 6. 实施范围和验收

主要实施位置：

- `frontend/js/world.js`：统一讨伐入口、目标列表、出征配置、动作解析、路线预览与正式提交。
- `frontend/js/world-map.js`：地图详情按钮及动作分发。
- `frontend/js/constants.js`、`frontend/js/battle.js`：行军及战报的显示文案，结果必须使用真实接管或占领条件。
- `frontend/js/onboarding.js`、任务跳转相关代码：占领预选及任务模式引导。
- 后端任务目录和相关文档：同步玩家可见的操作说明；计数事件、战斗结算和行军表结构无需改动。

实施时补充有意义的定向验证：

1. 所有原双按钮入口只显示一个讨伐按钮；友好军团、未宣战、护盾和保护期限制继续生效。
2. 开启／关闭分别发送 `conquer/plunder`；路线预览与出征提交一致，不发送 `campaign`。
3. 切换开关、修改兵力及路线时，兵力、指挥官、携带资源和战斗方式不丢失。
4. 野地开启并自动返城：地块归属保留，部队返城；原地驻守：沿用现有驻军和撤回路线。
5. 野地关闭：取得按幸存负重计算的资源、不改变归属；隐藏的驻守值不能生效。
6. 无资源野地仅可开启；耗尽资源野地说明与当前后端行为一致。
7. 玩家城开启仍以战后民心和城市名额判断；关闭时即使民心、指挥官忠诚均为 0，也不接管、不俘虏指挥官。
8. NPC／流寇两种模式仍按原规则刷新，战报不误报领地接管；资源及经验差异保持原规则。
9. 历史行军、战报、任务进度及新手引导兼容，任务按对应模式与真实结果累计。
10. 手动指挥与自动结算均按出征时冻结的动作处理，断线重连和重复请求不改变模式。

本设计只合并操作入口并显式表达战后目的，不调整两套收益的平衡。因此城市目标中开启模式收益通常仍更高；这属于后续可单独讨论的数值设计。

## 7. 实施与验证记录

实现了地图、野地列表、NPC／流寇列表、玩家城市卡片的单一「讨伐」入口。出征准备的「是否占领」位于兵力配置之前，默认开启；开关只更新处置区域、摘要与路线预览，保留兵力、指挥官、战斗方式和携带资源。野地开启后可选择「自动返城／原地驻守」，关闭后提交 `conquerMode=withdraw`。无资源类型固定开启，资源耗尽的地块仍允许关闭。

`World.resolveDispatchAction` 统一解析实际动作，路线预览和正式提交都只发送 `conquer/plunder`。切换配置立即使旧路线失效，旧异步响应不能覆盖当前模式；预览等待或失败时暂不提交。成功请求清除 API 状态替换前后的草稿，失败保留输入。四项模式任务增加「前往讨伐」，预选下一次匹配目标的处置模式；新手占领引导固定开启。

行军和两种动作的战报标题统一为「讨伐／讨伐报告」。战报分别显示行动配置与实际占领、接管结果；NPC／流寇只显示击败，新 NPC 战报标题也使用「已击败」。野地战报在原 JSON 内新增实际部队去向快照 `troopDisposition`，值为 `stationed/returning/destroyed`，没有新增数据库字段。历史战报缺失快照时不反推，已有数据及正文不批量改写。
