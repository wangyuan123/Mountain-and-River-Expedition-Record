# 当前项目设计

更新于 2026-10-23。本文描述当前实现，替代早期“纯前端单机、不做军团”的设计。

## 游戏边界

游戏以主城经营和文字战报为核心，包含四种生产资源、黄金税收、平民人口、建筑队列、陆海空兵种、军官装备与技能、城市司令部、战地医院与伤兵救治、科技、野地采集、讨伐取资与占领、玩家城市接管、敌将俘虏，以及同军团物资运输与派兵驻防。玩家通过共享世界进行交互，军团、聊天、邮件、排行榜和任务均已有后端模块。地图战斗支持自动结算和玩家手动逐回合指挥，实际机动与伤害由服务端统一结算。

商城钻石充值是模拟行为，继续对登录玩家开放；本次维护没有改变该功能。

## 城市地图护盾表现

玩家城市护盾使用蓝色半透明立体穹顶、经向曲线、三条纬向弧形光带和双层椭圆底圈，顶部抬高，底圈以包裹城市图标四角为目标。可见护盾以约 2.62 秒周期同步明暗呼吸，保留城市建筑细节与盾牌标识；动画仅更新护盾透明度，不每帧重绘地图。具体显示参数、状态判断和视觉验收范围见 [玩家城市地图素材](PLAYER_CITY_ART.md#2026-10-06-城市蓝色立体护盾)。

## 聊天与玩家私聊

主导航使用“聊天”名称。聊天页提供世界、军团和私聊三个频道，并提供“山河战友”好友页；论坛通过页内导航按需加载。世界频道历史对所有玩家开放，发言需要声望达到 10000；军团频道仅向本军团成员开放。私聊不要求声望或军团资格。

私聊频道默认显示多个玩家的会话列表，每项展示头像、对方名称、在线状态、最近消息摘要和未读数；点击进入独立对话界面，标题展示对方名称及在线／离线或账号不可用状态，并提供返回列表按钮。输入完整玩家名可发起会话，也可点击世界、军团消息中的玩家头像或昵称直接进入私聊。主动打开即持久保存到发起者列表，未发送消息时也保留空会话，不打扰对方。最多展示 50 个最近会话，每个会话展示双方最近 50 条消息。在线状态依据服务端 WebSocket 活跃连接判断，私聊面板可见时每 15 秒刷新。切换会话保留各自草稿，旧会话的异步历史响应不会覆盖当前会话。

私聊消息持久化，接收方离线时仍可发送，上线后通过会话和历史接口读取。在线消息以 `private_chat` WebSocket 事件在事务提交后仅推送给双方；在私聊未显示时收到消息会给出提示。重连后重新拉取会话和历史。仅当聊天页的消息面板及单人私聊对话可见时推进已读，停留私聊列表不清除未读，已读边界为客户端实际加载的最新消息 ID；隐藏频道、论坛和离开聊天页时不清除未读。

服务端从登录身份取得发送者及历史查询主体，客户端不能指定他人的会话主体。禁止向自己、不存在或非活跃账号发送消息，参与者仍可查看已有历史。消息最多 80 字，过滤控制字符及现有敏感词，每位发送者 5 秒冷却，切换收件人不能绕过冷却。查询和已读操作始终限定当前登录玩家参与的记录。

数据库迁移 `V70__private_chat.sql` 新增 `private_chat_messages`，保存发送者、接收者、内容、创建时间及接收方已读状态，并建立会话和未读查询索引；`V71__private_chat_conversations.sql` 增加主动打开的会话表，按所有者和对方 ID 去重；`V72__private_chat_delete.sql` 增加仅对会话所有者生效的删除边界。`V100__friends_and_chat_clear.sql` 增加好友、分组、好友申请、玩家隐私字段，以及私聊清空边界 `cleared_through`。私聊 API 使用 `/api/game/chat/private` 前缀，提供玩家名解析、打开会话、最近会话、历史、发送、删除、清空和已读接口；好友 API 使用 `/api/game/friends` 前缀，提供好友列表、搜索、资料、申请、分组、拉黑和隐私设置接口。具体协议、使用流程和验证范围见 [玩家私聊设计](PRIVATE_CHAT_DESIGN.md) 与 [好友与隐私设计](FRIENDS_AND_PRIVACY_DESIGN.md)。

### 山河战友、好友关系与隐私设置

“山河战友”默认显示固定的“我的好友”分组，好友可以移动到账号自己的自定义分组。自定义分组支持新建、重命名和删除，最多 20 个；删除分组时其中的好友移回“我的好友”。好友列表和分组按账号独立保存，默认分组不落库，以空 `group_id` 表示。

玩家可以用完整玩家名或玩家 ID 搜索其他玩家，点击结果打开资料弹窗。弹窗展示公开的等级、军衔、声望、城市、阵营、在线状态和账号可用状态，并提供添加好友、删除好友、发起聊天、清空当前账号可见的会话内容、拉黑或解除拉黑，以及移动好友分组等操作。删除好友只解除双方好友关系，不删除已有私聊历史。

好友申请遵循接收方的账号设置：`APPROVAL`（需要同意，默认）、`ANYONE`（允许直接添加）和 `NONE`（拒绝申请）。待处理申请可由接收方同意或拒绝，发送方可撤回；同意后双方各保存一条好友联系人记录。申请提交有按双方和按发送方计的冷却限制，防止反复申请骚扰。

好友关系、分组和黑名单按账号独立管理。拉黑不会立即删除好友关系，但会取消双方待处理申请，并阻止双方发送私聊；解除拉黑后，原好友关系可以继续使用。玩家还可以开启“屏蔽陌生人私信”，此时只有好友私聊可送达，世界聊天、军团聊天和系统消息不受影响。所有好友、私聊和隐私操作均由服务端按登录身份校验，不能通过客户端指定其他账号作为操作主体。

## 数据流

1. 浏览器通过 JWT 调用 API，服务端校验所属玩家和资源条件。
2. 一次业务操作在数据库事务内修改资源、人口、部队或任务等数据。
3. 可变游戏实体继承 `VersionedEntity`。并发写入同一条旧记录会产生版本冲突，整笔事务回滚；HTTP 返回 409，引导刷新后重试。
4. WebSocket 消息先序列化为快照，等事务提交成功后再发出；回滚不产生成功通知。
5. 前端合并状态并更新界面，核心余额不从浏览器存档恢复。

乐观锁防止丢失更新，不会让失败请求自动变成成功请求。余额与库存新增记录同时发生时，商城先刷新余额版本，再创建库存，避免库存唯一键错误掩盖余额冲突。

## 时间与结算

所有游戏活动统一以持久化游戏时间 `GameClock.now()` 计时。服务器正常运行时推进；停服、宕机或游戏时钟无法持久化期间暂停，恢复后从最后已提交检查点继续，不补算停机期间的真实时间。例如行军剩余10分钟时停服2小时，恢复后仍剩10分钟。玩家退出登录或没有玩家在线不等于停服，服务器正常运行时活动照常推进。

该规则覆盖野地出征、真实玩家战争、PvP演习、行军返程、运输援军、采集、建筑升级与拆除、科研、造兵城防、装备生产、资源人口及军饷维护、保护效果、冷却和游戏内限时活动。游戏自然日额度和野地三小时刷新也随停服顺延；鉴权、账号安全与合规日历、网络心跳、限流、缓存及运维审计仍按真实时间处理。

前端统一读取 HTTP `X-Game-Time`、状态 `serverTime` 和 WebSocket `gameTime` 样本，活动倒计时与进度条不按本机时间外推；失联停留在最后样本，重连同步服务器进度。预计真实完成时刻按剩余游戏时长换算，后续停服会顺延。持久化、故障边界、首次迁移限制及验收场景见[停服暂停与恢复设计](SERVER_GAME_CLOCK.md)。

### 倒计时展示规范（2026-10-22）

所有倒计时和预计耗时共用前端 `Game.formatDuration(seconds)`，服务端动态操作提示使用同规则的 `DurationText.seconds/millis`，按天、小时、分钟、秒拆分，仅省略前导零单位，最高有效单位之后的零单位必须保留：

| 剩余时长 | 展示示例 |
| --- | --- |
| 至少一天 | `2天3小时4分钟5秒`、`1天0小时0分钟0秒` |
| 不足一天、至少一小时 | `3小时4分钟5秒`、`1小时0分钟0秒` |
| 不足一小时、至少一分钟 | `4分钟5秒`、`1分钟0秒` |
| 不足一分钟 | `5秒` |
| 已归零 | `0秒`，或沿用该业务的已到达、已超时、结算中等结束状态 |

正数向上取整到秒，防止截止前提前显示0秒；分钟统一写作“分钟”，不使用“分”、英文 `d/h/m/s` 或 `HH:mm:ss`。初次渲染、每秒刷新、详情弹窗与分享快照遵守同一格式。覆盖建筑施工与拆除、科研、征兵城防、装备制造、行军路线与加速、采集、拦截与战争、护盾与新手保护、归降移交、伤兵留存、军官刷新与赏赐冷却、战斗回合与重试、PvP匹配与对战、晋升考试、聊天冷却及健康游戏剩余时间。

累计采集时长也复用上述格式，但按已完成的整秒向下取整，不改变原累计计时逻辑。只累计实际采集阶段，并在达到本次负重或可采资源上限时封顶；军情、大地图详情和列表地图按秒更新，野地资源进度条分母始终为野地总资源量。展示入口、汇总口径及避免重复展示的规则见[采集进度与累计时长设计](GATHERING.md#采集进度与实时展示2026-10-22)。

本次仅统一展示，不修改服务端截止时间、结算周期、实际工期、冷却规则或到期动作。绝对日期、发生/到达时刻、时间输入、每小时产出及静态规则说明保持原有语义，不作为倒计时转换。

`TickScheduler` 按 `game.tick-interval` 调度，查询 `last_tick` 已到期的玩家 ID，通过游标分页调用事务化 `TickService.tick`。默认每批 100 人、每轮最多 20 批，达到预算后下轮从游标继续，避免一次加载所有玩家和无限占用调度线程。并发冲突留待后续轮次处理。

在线与离线玩家都保留周期结算语义；没有为了性能改变经济结算频率。经济单次离线补结算时长由 `game.max-offline-hours` 限制，默认 8 小时，按服务器实际推进的游戏时间计算，不包含停服时长。大量玩家导致处理积压时，结算仍依据已推进的游戏时间补算；该实现并不等同于无限扩容，仍需按实际规模压测和配置批量预算。

民居每级提供 1200 人口容量。人口先按容量、民心与小数余量增长/流失，再以结算后的实际平民计算该周期黄金税收：`平民 × 税率比例 × (1 + 市长学识/100) × 2 × 小时数`，黄金按现有规则四舍五入并受容量和军饷影响。例如 100 平民、1 级民居、70 民心、30% 税率，无军饷，一小时后为 136 平民和 82 黄金。

### 建筑分组卡槽（2026-10-22）

每座城市的资源Tab和军工Tab各提供35个共享卡槽。资源建筑在资源区内共用35个卡槽，军工建筑在军工区内共用35个卡槽；新建施工会立即预占卡槽，升级现有建筑不新增占用，拆除完成或取消新建后释放卡槽。卡槽容量固定为35个，不再随市政厅等级扩容；市政厅仍限制建筑最高等级，单类可重复建筑的数量上限与所属分组卡槽共同生效。

### 资源建筑产出与生产容量（2026-10-22）

粮食、钢铁、石油、稀矿建筑均为10级。一级基础产出分别为粮食600、钢铁600、石油500、稀矿500；稀矿与石油基础产出保持一致，粮食与钢铁基础产出保持一致。对应资源生产容量按该类建筑等级独立计算，每级增加200,000，即`资源生产容量 = 对应资源建筑等级 × 200,000`；因此1至10级分别为200,000、400,000、600,000、800,000、1,000,000、1,200,000、1,400,000、1,600,000、1,800,000、2,000,000。生产容量只限制自然产出，不限制运输、礼包、任务、邮件、市场或战利品入账。粮食、钢铁、石油、稀矿、黄金的巡检阈值统一为1,000,000,000；入账不即时截断，库存字段使用64位整数保存周期检查前的超额库存。与野地刷新共用北京时间0、3、6……点的游戏时间周期，停服不推进，在线与离线玩家的主城和已建成分城都会检查；首次启用只记录周期基线，不处罚既有库存。每座城市的每类资源独立记录超限阶段：首次检查损失`ceil((当前库存−10亿)/2)`，也就是损失超额部分的50%并向上取整；下一次三小时检查时若仍超限，则损失全部剩余超额并回到10亿，若已不超限则清除待复查状态。回到阈值后再次超限按首次检查处理。每城每次检查合并为一份未读「资源损耗报告」，列明城市名、坐标、原因「仓库溢出」、资源及损失数量；报告进入战报列表，离线后可读，在线玩家在事务提交后实时收到。钻石不纳入检查。黄金的生产容量与停税、恢复规则见下一节。

商城资源道具定价与数量于 2026-10-27 重新分档：黄金箱 80 钻得 5 万黄金；资源箱 80 钻得四项各 5 万；钢铁大礼包 200 钻得 60 万钢铁；战备补给包 500 钻得四项各 40 万；资源大礼包维持 5000 钻得四项各 500 万。旧库存按开启时的新规则结算，受影响的 VIP 日常补给及经济风险见[资源商城定价设计](RESOURCE_SHOP_PRICING_20261027.md)。

同日增加粮食、石油、稀矿单资源大礼包，与钢铁包一致均为 200 钻、60 万；四项资源均分礼包增加各 100 万、200 万、350 万三档，分别售价 1150、2200、3700 钻，衔接各 40 万和各 500 万档。

### 黄金税收与生产容量（2026-10-22）

- 每座城市的黄金生产容量由999,999调整为固定20,000,000（2,000万），主城和分城分别判断各自库存。
- 结算税收时，黄金库存低于2,000万则正常计税，单次税收结算最多补至2,000万；库存达到或超过2,000万时暂停税收，不截断已有库存。
- 军官薪资仍按原规则扣除，不因停税而暂停。库存因薪资或其他消耗降到2,000万以下后，在下一次税收结算时恢复征税；人口、税率、市长学识和理财技能的税收计算规则不变。
- 运输、礼包、任务、邮件、市场和战利品等非税收入不受生产容量限制，仍可使黄金库存超过2,000万。10亿库存巡检阈值、三小时巡检周期及分阶段损耗规则保持不变，不能将生产容量当作库存硬上限。

边界示例（均忽略军官薪资）：库存19,999,900、当次应收税720时，仅入账100，结算后为20,000,000；库存正好20,000,000时税收为0；库存20,000,100时税收同样为0，原库存保持20,000,100，不因超过生产容量而扣损。

### 建筑升级工期（2026-10-20）

工期按升级后的目标等级计算。普通建筑（含资源建筑和其他军工建筑）使用 `min(24小时, ceil(30秒 × 2.4^(目标等级−1) × 加速倍率))`；市政厅 `command` 使用 `60秒 × 2.5^(目标等级−1)`、上限72小时，研发中心 `lab` 使用 `45秒 × 2.6^(目标等级−1)`、上限72小时，司令部 `headquarters` 使用 `45秒 × 2.5^(目标等级−1)`、上限48小时。封顶作用于应用加速倍率并向上取整后的工期。以上为基础曲线与固定上限；三个关键建筑的前期起步略高、后期增长更快，使其最高常规等级的升级可以超过24小时：9→10级市政厅约63小时34分42秒、研发中心约67小时52分08秒、司令部约47小时41分02秒（均为未加速基础工期）。

建筑科技 `log_build` 每级使工期倍率减少5%；任命市长的“工程营造”每级再乘以0.96，最多5级。两项倍率相乘后以0.35为下限，即 `加速倍率 = max(0.35, (1 − 0.05 × log_build等级) × (1 − 0.04 × 工程营造等级))`；没有市长该技能时第二项按1计算。升级与拆除使用同一建筑曲线，拆除按被拆除的当前等级计时。工期在开工时写入施工任务，后续科技或市长技能变化不重算已有任务。具体曲线在服务端与前端保持一致。

## 战斗伤害分配

侦查每次只选择一种方式：侦察机执行空中侦查，可直飞跨海；侦查装甲车 `recon_car` 执行地面侦查，目标必须为陆地且存在连通陆路。两者分别只与同方式侦查兵种交火，普通守军和工事不参与独立侦查遭遇。攻方幸存即可按出征方侦察技术等级开放情报，十回合战平也可传回情报。城市情报依次开放城防类型（Lv.1）、城防数量与等级（Lv.2）、精确守军（Lv.3）、守城将领（Lv.4）、建筑等级（Lv.5）、驻城将领人数（Lv.6）、账号科技（Lv.7）、可掠夺测算（Lv.8）、驻城将领档案（Lv.9）、战力评估（Lv.10）；野地在 Lv.1 开放精确守军。历史报告保留生成时的情报快照。

侦查第1回合直接交火，沿用独立的攻击÷（防御+生命）伤害、伤害余量、每方每回合一次额外击杀及最多10回合，不进入普通战斗的射程、机动或攻击次数流程。所有交战统一按先手与当前存活兵力逐回合结算，战力估值仅供报告展示，不按兵力或战力比例直接结算；被全歼的一方不能继续攻击或反击，弱方先手时仍按实际攻击造成伤害。攻方使用实际随队将领，守方使用目标城市守将或对应NPC将领；军事、防御包含装备与套装，每点分别增加1%攻击、防御，与八项战斗技能共同在第1、4、7、10回合生效，之间空过两个回合。普通攻防生命科技、引擎科技及火力密度不进入独立侦查，配装与司令官四属性常驻。

侦查先手使用独立版本`recon-initiative-v6-20261019`：双方均为`round(当回合有效速度) + 5 × 自身侦察技术等级`，取消出征方固定+2；守方仅第1回合增加`雷达预警等级×2`，后续技能窗口不重新触发雷达。有效速度使用兵种速度档位，包含配装、司令官学识及生效回合的闪电突击，每回合重新计算。最终先手值相同，奇数回合攻方先手、偶数回合守方先手；阵亡配装组不参加后续排序。侦察技术对双方先手的收益对称，情报深度仍只按出征方侦察等级开放。

侦查真实玩家城市时，双方各保存一份未读报告并在事务提交后推送。守方的“敌军侦查报告”记录来袭玩家、出发坐标、被侦查城市、侦查方式、双方对应侦查兵种损失及拦截结果；没有同方式拦截单位时同样生成。守方报告不包含出征方获取的内部情报。报告持久保存，离线后可从战报列表读取。旧报告缺少方式及按兵种快照时仍按侦察机的原有数量字段展示。

新报告保存真实攻守双方将领、属性与技能周期`[1,4,7,10]`及`reconInitiative`科技快照。顶层先手值与`firstStrike`仅代表第1回合，逐回合顺序与实际数值见`combatLog`；界面按收件人视角展示。缺少先手快照或版本不匹配的历史报告不显示新先手说明、不重算战损。2026-10-21取消侦查战力悬殊时的直接结算，统一逐回合按先手和存活兵力推演；先手首轮全歼时，对方不再攻击或反击，弱方先手仍按实际攻击造成伤害。专项后端测试`ReconArmoredCarTest` 41项、`ReconCommanderRulesTest` 18项、`ReconInitiativeRulesTest` 22项通过，使用H2测试库；未部署，历史战报不自动重算。完整公式、示例与验收见[侦查设计](RECON_ARMORED_CAR_DESIGN_20261008.md)。

同军团援军计入被侦查城市的有效驻军总数，其侦察机参与空中拦截、侦查装甲车参与地面拦截；情报与拦截兵力不受城主战术迎战预设限制。损失按城主与各派兵人分摊，援军伤兵回原派兵城市，城主仅承担本城部队的损失。

侦查装甲车可参与普通讨伐、自有城市调遣和驻防，防御、生命、机动及造价与防空装甲车一致，对空攻击为 5 且没有防空专项倍率。反坦克火箭车对其专项倍率为 3；普通作战中的陆军空运规则继续适用。具体属性与侦查规则见 [侦查装甲车设计](RECON_ARMORED_CAR_DESIGN_20261008.md)。

途中撤回会保留行军并转为返城，返程耗时按已行进时间计算（至少 1 秒）。军情页和地图继续显示返城部队，抵达出发城后才归还部队、携带资源并释放随行军官。撤回不生成侦查或战斗报告，也不发放尚未进行的采集奖励。

当前世界战斗源码使用 `balance-v20-naval-capital-ships-20261019`：兵种和城防分别定义对地、对空、对海、对工事攻击，按目标领域选择攻击值，全部四项攻击至少为1，弱项仅提供低效火力，仍受射程与行动规则限制。伤害为 `当前目标有效攻击 × 剩余攻击份额 × 专项克制 × 100 / (100 + 5 × 有效防御) × 贴脸系数 × 装备减伤系数 × 行动火力倍率`，有效攻击先计算自身攻击加成及火力压制，再追加师夷长技参考攻击。行动火力为 `1 + 0.05 × 火力密度等级`，伤害封顶、击杀和余伤消耗前只乘一次；反击使用反击方自身倍率。攻击不平方；机动结束后与当前目标距离为0时，步兵主动攻击与余伤攻击获得贴脸×2.0，轻坦、重坦、特种兵获得×1.5，其余情况贴脸系数为1，反击没有贴脸加成。余伤切换目标时重新判断距离，双方主动行动适用同一规则。反坦克火箭车对轻坦、重坦、装甲车、突击炮的专项克制倍率均为 3，其余目标不享受反坦克火箭车额外克制；装甲车对战斗机、轰炸机的专项倍率为 2.5。其余交战按基础属性结算，不叠加通用空地海系数。

本轮下调专项倍率以延长消耗过程；同条件下反坦克火箭车专项伤害下降约45.5%，防空装甲车专项伤害下降50%。调整依据、对战回合对比与验证范围见 [专项倍率消耗战调整](BALANCE_ATTRITION_20261008.md)。

一次主动行动的攻击份额为当前兵数。目标全灭后扣除已消耗的份额，剩余额度切换目标时重新选择领域攻击、防御和专项克制，不能为每个领域重新生成完整攻击。无法全灭时仍采用整数击杀加小数概率结算，消耗剩余额度。当前结算没有随机连击翻倍。

各兵种分别记录位置。每回合先按前进、后退或待命指令统一结算双方机动，再用更新后的坐标结算交火。默认前进的所有兵种（包括空军）向最近存活敌军推进，即使暂时无法攻击该兵种；任何存活敌方兵种均会阻挡推进，必须消灭前排后才能继续向后推进。射程只限制开火，不限制前进；前进或后退后的存活单位若有合法目标处于有效射程内，可在同一回合开火。默认不主动前进的单位保持原位，也可通过战术指令改变机动方式。

双方开局位于各自阵地底线，没有兵种前置偏移；初始距离为 `双方实际参战单位最大有效射程 + 场景缓冲`：真实玩家之间及演习+1850，玩家与NPC+1000，玩家与野地+500。工事、援军配置组计入最大有效射程；空城墙体射程0，仍取攻方射程；不另加城防距离。射程包含科技，速度、学识、装备速度和闪电突击均不参与距离。每回合先统一机动，再判断交火；距离等于射程即可开火，不再保证前三回合安全。自动与手动入口使用同一场景判定，模拟玩家城归NPC。进行中会话沿用已保存的距离与坐标。

交火先按有效射程降序，再按当回合有效速度降序；射程和速度均相同时，按战斗总回合数轮换，奇数回合进攻方先手、偶数回合防守方先手，首次交战不重新计数。司令官学识与闪电突击影响同射程单位的速度排序，不保证全军最先开火；同兵种、同科技、同司令官学识且都能开火时，技能生效回合闪电突击等级较高的一方先行动，同等级则仍按回合奇偶轮换。指定且合法的射程内集火目标优先，否则先选射程内同兵种，再选最近的可攻击目标（等距离按兵种 ID）。掠夺战最多25回合，征服战最多35回合，自动结算、手动指挥和离线超时推进按同一出征类型上限执行；最后一回合完成交火后再判胜负，未全歼敌军或真实玩家城征服未破墙则攻方撤退，双方保留实际幸存者。独立演习仍为24回合，源码规则版本为 `balance-v19-technology-20261016`。

攻击、防御、生命、射程和火力密度科技持续生效；司令官四属性倍率全回合生效，带兵将领军事、防御属性与全军冲锋、坚守阵地、借甲御敌、闪电突击、火力压制、破甲打击、师夷长技、绝境反击统一从首次实际交战回合起，每隔 2 回合生效一次（如第 4 回合首次交战，则第 4、7、10、13…回合生效；侦查首回合交火，对应第 1、4、7、10 回合）；双方共用且持久化首次交战回合，脱离射程不重置周期。首次交战在机动结束后确认，闪电突击即时影响该回合交火先手，后续生效回合同时影响机动与先手；开局距离与交战前机动按引擎科技和司令官学识计算。火力压制和破甲只在技能生效回合参与双方攻击、余伤与反击；师夷长技不复制专项倍率，反击重新使用反击兵种对原攻击者的倍率。三军统帅、战地急救与市长内政技能沿用原用途，司令官技能不参与这些效果；城防等级增加工事容量和墙体自身生命、防御，不提供任何部队或工事防御倍率。真实玩家城市征服战须清除守军和工事并将墙体生命耗尽才胜利；清军后射程内余伤共享同一份攻击额度继续攻墙，35回合总上限不变。墙体每级基础生命250,000、防御20，满级10级；新增10级「城墙加固」，每级使本城墙体生命、防御各+5%，满级各+50%。10级墙体无加固为2,500,000生命/200防御，满级加固为3,750,000生命/300防御；开战冻结，不强化驻军与工事。完整规则见 [破墙设计](CONQUEST_WALL_BREACH_DESIGN_20261013.md)。战报记录规则版本、攻击领域与有效攻击、专项倍率、实际伤害、击毁数及剩余攻击额度。当前属性与倍率见 [兵种属性记录](../output/unit-attributes-design-record.md)、[专项倍率规范](../output/combat-multipliers-design-record.md)，技能边界见 [军官技能池记录](../output/officer-skills-design-record.md)。

司令官有效属性为自身成长、已穿戴装备及激活套装之和，每点对应属性增加0.1%，倍率为 `1 + 有效属性 × 0.001`，不受带兵将领属性/技能回合限制。原始属性上限219不限制装备后的综合值。司令部升级不放大倍率，不增加带兵上限；司令官不能兼任或带队出征。市长和城市指挥官的原功能保留。

```text
自身攻击 = 领域基础攻击 × 攻击科技 × 司令官军事 × 本回合将领军事 × 全军冲锋 × 敌方压制
有效攻击 = 自身攻击 + 师夷长技参考攻击
行动火力倍率 = 1 + 0.05 × 火力密度等级（主动、余伤、反击均在伤害结算前乘一次）
自身防御 = 基础防御 × 防御科技 × 司令官防御 × 本回合将领防御 × 坚守阵地
有效防御 = (自身防御 + 借甲御敌临时防御) × (1 - 破甲比例)
有效生命 = 基础生命 × 生命科技 × 司令官后勤
有效速度 = 基础速度 × 引擎科技 × 司令官学识 × 本回合闪电突击
```

上述属性和技能名称均表示倍率，未生效时取1。师夷长技参考敌方同名兵种的永久攻击，包含敌方司令官军事及带兵将领综合军事，不复制技能；追加值不再乘己方司令官，学习不复制敌方火力密度；整个有效攻击最终使用己方行动火力倍率。借甲只参考基础防御和敌方防御科技，不复制双方司令官或将领倍率。

攻方读取行军来源城市，守方读取实际被攻击城市；切城不改变归属，援军共享守城城市司令官，不叠加援军来源城市岗位。自动、手动、野地、城战和独立侦察均接入，侦察继续沿用原拦截模型与科技情报深度。开战保存双方司令官身份和四属性快照，战中换任、换装或拆楼不改本场战斗；拆除司令部只暂停新战斗加成，重建恢复任职记录。

司令部最高10级，基础造价钢铁300、粮食150、黄金150，成本成长1.6。目标等级L要求本城市政厅 `max(3,L)`、军校 `max(1,L-1)`、作战参谋部 `max(1,L-2)`。完整任命规则、界面、快照接口、前置表与实施验证见 [司令部与司令官设计](HEADQUARTERS_COMMANDER_DESIGN_20261010.md)。

## 讨伐与野地战后驻军（2026-10-12）

每座城市独立拥有野地，`野地上限＝基础5块＋本城市政厅已完成等级`，市政厅1级为6块、10级为15块。参谋部不再增加野地名额，其他城市的等级和领地不参与本城计算。征服成功后归属行军出发城市，切城不改变在途行军的归属；当前城市的“我的领地”和野地页只统计该城领地，地图仍标识同账号各城的占领状态。

出征占领前与自动/手动战斗胜利后均校验本城名额；在途征服不预扣名额，最后一块名额由先完成占领的部队取得。结算时已满仍保留战斗胜利，但不占领、不触发占领任务、不转为驻军，幸存部队返城，战报保存具体原因。掠夺、侦察和既有领地采集不受占领限额阻止。

V93为`wild_tiles`添加`occupied_city_slot`，历史领地归入主城序号0，不推测驻军或采集城市作为所属城市，不重置归属和驻军。历史超额领地保留，名额不足时停止新增占领。城市易主时领地随城转交新城主及其新城市序号，按既有规则移除失守城编队，其他来源幸存驻军先按原路线返城；分城提升为主城时同步重编号所属领地，放弃野地释放该城名额。

地图和目标列表将“征服／掠夺”入口合并为“讨伐”。出征准备在兵力配置之前提供“出征方式”下拉框，依次为征服、掠夺、佯攻、袭扰、游击，默认征服；三种短战模式分别最多 10、15、5 回合，获胜也不获取资源或占领目标。路线预览与正式提交共用同一映射，`campaign` 仅是前端草稿动作。任务可预选模式，普通新目标恢复征服默认值。攻击权限和原结算规则继续生效，完整规则见 [讨伐入口与战后占领配置设计](CAMPAIGN_DISPATCH_DESIGN_20261011.md)。

野地选择征服时显示“占领成功后部队”，默认选择“自动返城”；手动指挥和自动结算共用相同的战后处理规则。其他出征方式隐藏该配置并提交 `conquerMode=withdraw`；当前草稿中暂存的“原地驻守”不能生效。无资源类型禁用掠夺，允许征服及三种短战模式；资源耗尽的野地仍可掠夺。

| 选项 | 请求值 `conquerMode` | 占领成功后的行为 |
| --- | --- | --- |
| 自动返城 | `withdraw` | 野地归玩家所有，清空原守军；幸存部队自动按原路线返城，抵达出发城市后归队 |
| 原地驻守 | `occupy` | 野地归玩家所有，幸存部队转为该野地驻军，结束原占领讨伐行军；之后由玩家下达撤军或驻军采集命令 |

开启占领后，两种部队去向选项都会保留野地归属。战败时仍按现有逻辑更新敌方剩余守军，并让己方幸存部队返程，不转为驻军。“原地驻守”只写入战后实际幸存兵力，不恢复阵亡兵力，也不自动开始采集。战报及 `WILD_CLAIM`、`WILD_CONQUER` 任务按实际占领成功结算，部队是否留守不影响占领结果。关闭占领时按幸存负重取得剩余资源，不改变归属，沿用 `WILD_PLUNDER` 计数。

留守部队写入 `wild_tiles.garrison`，并通过 `garrison_routes` 保存所属玩家、出发城市序号、出发坐标、单程距离与时长、路线模式、路线节点和幸存兵力。原占领讨伐行军记录删除，随军军官按既有野地进驻规则恢复 `idle`；当前没有野地驻守军官的独立状态。该流程与同军团城市驻防不同，不使用 `marches.stationed` 保留占领行军。

野地详情和“我的领地”沿用现有驻军操作。手动撤军调用 `POST /api/game/wild/recall`，请求体为 `{"wildTileId": 野地ID}`；服务端创建返程行军，逆序使用保存的路线和原单程时长（至少 1 秒），部队抵达各自出发城市后才归队。撤军不改变野地归属。驻军采集由玩家另行开启，仅支持手动收获并另行下令回城，规则见 [资源野地采集模式](GATHERING.md)。

### 接口与兼容

`POST /api/game/world/dispatch` 增加可选字段 `conquerMode`，兼容接口 `POST /api/game/wild/conquer` 同样透传该字段。允许值为 `withdraw`、`occupy`；未传或为 `null` 时使用 `withdraw`，非法值在扣除兵力和资源前拒绝。有效值用于其他目标或非占领讨伐动作时，服务端归一为 `withdraw`。游戏状态中的行军对象返回该字段，历史 `null` 按 `withdraw` 展示。

`MarchService.settleWildBattle` 同时承接自动野地战斗和战术会话的结算。选择 `occupy` 且胜利后仍有幸存部队时，调用 `stationConqueredArmy` 转为野地驻军；其余情况沿用 `startReturnMarch`。出征油耗仍预扣往返量，不因选择留守改为单程。

## 地图查询

普通游戏状态只返回玩家当前位置附近的默认视野，并保留玩家已占领的野地。`GET /api/game/world/view?x=...&y=...&radius=...` 可读取指定视野；`radius=0` 是用户主动请求全图，避免购买、建造等无关操作反复读取全世界。

地图查询使用世界与坐标索引，玩家城市所属人采用批量读取。前端 `world-view.js` 合并地图数组，不覆盖较新的资源或行军状态；同视野请求合并，坐标或账号切换后旧响应不会生效。最近目标跳转会显式读取全图，坐标搜索和全图模式继续保留。

### 行军路线表现与视觉规范

行军路线按当前起终点绘制直线，分层低透明度描边组成光带，宽度随地图缩放调整，保留底层地形可见。路线色彩区分去程行动与返程：

- **进攻去程（红色 `0xe66f79`）**：讨伐玩家城市、NPC、日寇据点或野地的去程使用红色；前端统一入口，提交时仍按占领配置映射为 `conquer` 或 `plunder`。
- **运输、调遣与驻防（蓝色 `0x69b7ee`）**：自有城市间的运输／调遣（`transport` / `rebase`），以及向同军团成员城市运输／驻防（`transport` / `reinforce`）使用蓝色。外交友好的不同军团不能进行支援。
- **辅助行军与返程（蓝色 `0x69b7ee`）**：侦查、采集等辅助行军以及所有返程均使用蓝色，返程不再按战斗胜负改变颜色。
- **敌军来袭（红色 `0xe66f79`）**：包括敌方侦查，读取 `world.incoming`，在雷达预警至少 2 级、接口已公开出发坐标时绘制；移动标记使用服务端 `startAt`、`arriveAt` 插值。未公开的兵力不显示数量，历史来袭缺少时间时仅画静态路线；抵达或来袭记录移除时清除路线及模型，不触发己方抵达提醒。
- **护盾拦截返程（蓝色 `0x69b7ee`）**：敌军到达受保护城市后原路返程，守方地图通过 `world.returningEnemyMarches` 继续展示其返回出发城的路线、方向和行进进度，不要求额外升级雷达。该叠层只公开路线所需字段，不包含敌军数量、装备或将领；不计入来袭列表，不提供迎战入口。仅标记 `return_reason=shield` 的行军可见，其他撤军不会因此公开。完整状态和 Tick 都同步该字段，返程到达时即收起路线。
- **流动方向箭头**：箭头与路线同色，沿实际行进方向以约 38px/s 流动、间距 38px；撤回后反向指向出发城。系统开启“减少动态效果”时箭头保持静态指向。
- **行军兵种图标尺寸与比例放大**：大地图行军标记（`marchMarker`）的主兵种模型图标尺寸由原先的 `[36px, 56px]`（公式 `Math.max(36, Math.min(56, cameraScale * .7))`）扩大至 **`[48px, 72px]`**（公式 `Math.max(48, Math.min(72, Math.round(cameraScale * .9)))`），视觉整体放大约 30%。次要护航兵种图标（`iconSize * .56`）与编队数量角标、文字阴影等按比例自动缩放，使得玩家在俯瞰大地图或快速滑动时能够清晰分辨行军主力兵种及编队组成。

地图根据服务端返回的当前起终点、出发时间和抵达时间，在客户端插值计算行军编队的位置及朝向；动画帧不向服务端请求新坐标。在途部队由 `requestAnimationFrame` 连续更新路线和行军标记，帧循环不重新构造地形、据点与缩略图。镜头移动、地图数据变化等仍按需触发完整绘制；部队抵达后改为目标状态标记，同军团驻防以服务端 `stationed` 状态保持驻扎标记，返城抵达后清除标记，没有在途部队时停止连续帧循环。

页面隐藏时暂停绘制，恢复可见后重新检查地图状态。启用系统“减少动态效果”时不运行连续行军动画，改为每秒更新位置；海面波纹也以每秒一次的低频节奏刷新，减少动态效果模式下保持静止。动画只改变地图表现，不改变服务端行军时间、路线或结算；实际设备帧率仍以浏览器性能为准。

### 军情行军快速定位与联动

军情（情报）界面的“我军行军”列表，为每支拥有有效目标坐标的行军条目提供快捷操作支持：
1. **快捷定位按钮**：行军条目操作行提供 `[定位]` 快捷按钮，与 `[撤回]`、`[进入战斗]` 等操作并列排布；同时行军条目上的目标坐标 `(fromX,fromY->toX,toY)` 亦作为快捷下划线链接支持点击直接定位。

4. **部队到达战场与情报Tab闪烁提示**：当我军进攻行军抵达敌城、待攻野地、NPC舰队、日寇据点等作战目标，或进入交战、待战状态时，无论玩家正在大地图沙盘俯瞰行军还是在其他页面，导航栏【情报】Tab（`data-route="alerts"`）均会立即触发红色双层波纹扩散闪烁（`#navbar .navitem.alert`）并附带红点感叹号徽章（`<span class="nav-badge alert-dot">!</span>`），提示玩家当前已到达战场并有最新的战况进展或等待战术指挥。玩家点击进入军情界面（或调用 `acknowledgeAlerts`）后闪烁提示自动解除；后续若有新的作战部队抵达或收到最新战斗事件，将再次动态触发闪烁。
5. **己方野地采集不触发警报（2026-10-22）**：前往已占领野地的普通采集任务，在去程、抵达、采集中、停采待命及返程阶段，均不触发情报Tab闪红或感叹号，不计入顶栏“军情”与首页“军情警讯”的数量。只有普通采集时不显示这两处横幅；与作战行军或敌袭并存时，横幅仅统计其余军情。采集行军仍完整保留在军情列表和地图中，查看进度、定位、撤回及原有普通通知不变。该规则只影响提醒，不修改行军、采集、收益或资源入库；一旦采集部队出现真实交战、战斗会话、待战状态，或收到真实战斗推送，仍正常警报。前端统一通过 `Core.isRoutineGatherMarch` 判断，服务端只携带 `marchId` 的抵达事件先按当前行军快照识别任务；若本地尚无对应快照且消息未携带任务类型或交战状态，则等待随后的完整状态同步再判定，不凭“抵达”二字独立触发警报，避免地图、定时检查和WebSocket推送采用不同口径。

2. **战术出城拦截系统与交汇点战斗机制**：
   - **设计理念**：彻底打破“敌方来侦查、守方只能干看”的被动困局。只要玩家在线，便可主动调度防空力量出城截击高空侦察机，在城外空域瓦解敌军情报企图。

### 建城选址


NPC 城市（含模拟 NPC）、流寇、日寇据点及海上编队的地图模型与点击范围统一为 1×1 格，服务端生成、占位和迁移按单格检查；玩家城市为 2×2 格。NPC 布点外围保留一格间隔，构成 3×3 布点禁区，该间隔不属于实际占地。规则及验证见 [城市与据点占地规则](MAP_CITY_FOOTPRINT.md)（2026-10-11 更新）。

玩家可在地图点击空地，以所选格为左上角建立占用 2×2 格的分城。四格必须都在世界边界内、均为陆地，且不得与现有玩家城市、NPC 据点、日寇据点或野地重叠；是否临海不影响建城资格。地图选址接口返回可建状态和具体原因，提交时服务端再次校验占地、军衔城市名额及当前城市资源，避免预览后地图占用变化造成冲突。选中格显示为“丘陵”，不等于该处有已占领的丘陵野地。

玩家也可从城市列表选择自己已占领的丘陵野地建城。该入口将目标野地转换为城市，要求其没有未完成行军，并对完整 2×2 占地执行相同的海陆和冲突校验。新城仍按原费用和工期建设。临海属性保留用于港口资格：新建港口须位于沿海城市，内陆新城不能新建港口；旧城的海军通行兼容规则不受影响。详细费用、名额和切城规则见 [多城市经营](MULTI_CITY.md)。

#### 草坪与黑土地地表（2026-10-06）

陆地默认铺设浅色稀疏草坪，随机分布大小不一、边缘渐变的不规则黑土地斑块；目标覆盖比例为黑土地约 30%、草坪约 70%。该比例指陆地地表分布，海洋仍按海陆算法渲染。资源点密集区不再清空基础草坪，避免地图左侧出现大片缺草；资源模型周围仍保留装饰避让。

`frontend/js/map-terrain.js` 使用固定世界坐标的两种尺度噪声生成斑块，刷新、拖动、缩放和目标占领状态变化不会重新随机地表。地表仅影响视觉，不改变资源类型、储量、占领或通行规则。`frontend/tests/meadow-layout.test.cjs` 以草量 0.5 为草坪／黑土地分界，对 400×400 范围均匀采样，验证黑土地比例在 27%～33% 之间，同时检查资源点基础草坪和装饰避让。

四个地图区域统一命名为：左上「西北战场」、右上「东北战场」、左下「西南战场」、右下「东南战场」。世界缩略图在各区域中心以 9px 小文字显示名称，标签不影响点击或拖动定位。

世界大地图为 800×800，四大战场各占 400×400，全部开放浏览、建城、传送及海陆空行军。西北坐标为 X/Y 0～399，东北为 X 400～799、Y 0～399，西南为 X 0～399、Y 400～799，东南为 X/Y 400～799。海陆存档保留原 400×400 底图并镜像采样到全图，已有城市和野地坐标保持不变；区块与细地形按当前视口加载，外围继续保留 6 格天穹。旧存档通过世界内容版本 4、岛屿内容版本 2 一次性补齐新增战场的资源与据点，重复启动不重复撒点。详见 [四大战场开放与传送](FOUR_QUADRANTS_MAP_DESIGN.md#2026-10-13-四大战场开放与城市传送)。

城市管理、仓库及地图空地详情均提供传送入口。普通传送消耗 1 个普通传送道具，在选定战场的所有合法落点中等概率随机选择；高级传送消耗 1 个高级传送道具，使用玩家指定的左上角整数坐标。两类都必须选择战场，目的地连续 2×2 四格须完整位于该战场内、全部为陆地且没有城市、据点或野地占用。预览不扣道具，提交时再次校验，失败不扣道具；无合法落点时不回退至其他战场。传送保持城市 ID、建筑、军队、资源及城市名额，主城与分城分别更新坐标。建设中、归降移交中、交战中或有关联未完成行军（含返程、采集和驻防）的城市不能传送。成功后刷新地图并同步同账号其他页面的城市位置。

普通／高级传送的道具 ID 分别为 `teleportNormal`、`teleportAdvanced`，当前商城单价分别为 100、500 钻石，库存账号共享。操作城市由 `X-City-Id` 固定，传送不受新增城市名额限制，不支付建城费用。高级传送修改战场、道具或坐标后原预览失效；预览不预留位置。坐标更新与扣道具在同一事务中完成，提交成功后广播 `city_teleport`。详细坐标边界、城市状态限制和接口见 [四大战场地图与城市传送](FOUR_QUADRANTS_MAP_DESIGN.md)，资产隔离见 [多城市传送](MULTI_CITY.md#城市传送)。

地图地形先于城市、NPC 和野地分块加载，目标暂时未出现不等于数据丢失。分块为 16×16，四战场均按视口请求，编号为 0～49；可见区域未返回时显示“正在探索新区域…”，请求失败显示刷新提示并保留已有缓存。分块请求超时 10 秒，缓存有效期和可见页面刷新周期为 15 秒；失败块经过 10 秒重试间隔后由后续请求重试，手动刷新可立即清除重试限制。2026-10-13 本机接口、数据库和独立浏览器检查均确认目标存在且可显示，用户随后确认恢复，未执行数据恢复或重置。加载状态与排查记录见 [地图目标加载与暂时空白](FOUR_QUADRANTS_MAP_DESIGN.md#地图目标加载与暂时空白)。

陆地流寇／日寇据点按四类资源野地合计的等级配额维护：1～20 级每级 120 个，21～25 级每级 100 个，26～30 级每级 80 个，共 3,300 个（全世界陆地合计，不按名称分组，海域守军与 NPC 城市不计入）。世界生成完成、旧地图启动及游戏时间每三小时刷新后检查配额，保留现有等级内目标及其战损／击败状态，缺额在 NPC 密度较低分块生成标准守军；超过配额的记录仅在没有相关行军时移除，存在行军时暂时允许超额，下轮继续检查。等待刷新的已击败记录计入配额，避免重复增殖；没有空闲陆地时延后补足。

资源野地与 NPC／流寇分别统计可见目标，陆地与海域独立均衡；16×16 分块选点比较 `(本块可见同类目标数 + 1) / 本块同类地形总格数`，避免沿海小块过密。地形总格数包含已占用格，合法空位单独校验；密度相同随机选块，块内随机取点。每次成功放置立即更新本批计数与占位。隐藏待刷新目标不计密度，已占领可见野地仍计入；密度按地图点数量统计，类型、等级和储量不作为权重。各入口沿用原供给预算和允许范围，正常目标通过后续刷新逐步改善分布。

#### 陆地寇大地图微缩方阵模型设计（2026-10-19 方案一）

大地图陆地寇据点图标彻底废弃旧版带切角或固定背景贴纸的设计，采用**方案一：纯透明背景 + 真实地表接触投影**的写实战棋微缩模型体系：

1. **零截断写实模型与纯透明嵌入**：
   - 画布统一采用 384×384 规范尺寸，背景保持 100% 纯透明（RGBA `0, 0, 0, 0`），彻底移除非透明的人造固定彩色底板。

2. **13 种随机编队模型精准映射**：
   - 严格对应 [陆地 NPC 守军设计](NPC_GARRISON_DESIGN_20261005.md#2-随机编队生成规则) 中实际生成的 13 种兵种编队组合（如 `infantry`、`armored+infantry`、`armored+fighter+infantry+ltank`、`ltank+rocket`、`armored+htank+rocket` 等），大地图直接根据目标军队组成 `t.army` 或世界坐标哈希种子 `Math.abs(t.x * 31 + t.y)` 精确渲染对应的兵种方阵图，实现“所见即所得”。

### 首页模块排序

首页城市信息和军情提醒固定在顶部，其下的军官将领、军队总览、资源、世界聊天四个模块可自定义上下顺序。默认顺序为军官将领、军队总览、资源、世界聊天。每个模块标题栏提供独立把手，鼠标或触屏可拖拽；把手获得焦点后也可用上下方向键移动。拖动卡片内部或点击原有操作入口不会触发排序。横屏滚动容器内拖至边缘时会自动滚动。

城防总览位于 `army` 模块内，紧随军队总览，调整该模块时两者一起移动；城防区域没有独立排序把手，保存的模块 ID 仍为上述四项。

顺序属于玩家账号，不属于当前城市。`players.home_module_order` 保存四个模块 ID 的 JSON 数组，Flyway V60 增加该可空字段；`null` 表示尚未自定义。`GET /api/game/state` 在 `player.homeModuleOrder` 返回已保存顺序，登录和重新进入首页时按服务端数据渲染，未设置时使用默认顺序。`POST /api/game/settings/home-modules` 接收 `{"order":["officers","army","resources","chat"]}`，仅对当前已认证玩家写入，并校验恰好包含四个已知 ID、没有缺项或重复项；成功响应包含 `success` 和 `homeModuleOrder`。

前端调整后立即更新当前页面，再按操作顺序串行提交，避免连续拖动时旧请求覆盖新顺序。若保存失败，页面提示玩家重新调整；未成功写入的顺序不会成为下次登录的服务端设置。旧版曾将顺序放在按用户名命名的浏览器本地存储中：只有服务端字段为 `null` 时才读取并上传一次，成功后删除旧键；已有服务端顺序始终优先，因此跨设备登录使用同一账号设置。

只有 GET/HEAD 可以自动重试网络错误。POST/PUT/DELETE 即使显式要求重试也只发送一次；响应丢失时提示结果未确认，先刷新确认再操作。侦查 `scoutReport` 消息通过 WebSocket 分发到现有战报处理器，按报告 ID 去重。

## 军衔晋升与军事笔试（2026-10-08）

## 同军团物资运输与驻防（2026-10-08）

军团「成员」页对其他成员提供「运输」「驻防」，可选择其已建成主城或分城；战略地图和世界列表的同军团城市也提供直接支援入口。支援要求双方当前属于同一军团，外交友好的不同军团不能支援。兵力、资源、行军油耗与随行军官均使用当前出发城市；运输和驻防在出发时预扣往返油耗。

运输只派卡车或运输机，运送粮食、钢铁、石油、稀矿、黄金。物资抵达后全额入目标城，后勤部队与随行军官返原城。驻防可派符合现有路线规则的兵种，也可携带运力范围内的物资；物资送达后部队作为独立编队驻扎，仍归派兵人所有。自有城市间的「调遣」会转移部队和军官驻地，与同军团驻防区分。

防守时本城兵力与有效援军合并，按城主迎战预设和上限选择参战编队，由城主统一指挥，战斗属性使用守城方科技、守城指挥官和实际被攻击城市的司令官快照，不叠加援军来源城市司令官。开战保存各来源的实际参战数量，按兵种分摊损失，未参战兵力及战中迟到援军不承担本场损失。伤兵分别回到各自派兵城市；守方战报汇总本城与援军损失、伤兵数量及按损失加权的回收率。侦查情报及同方式侦查兵种的拦截同样计入有效援军。

派兵人在原出发城「军情」中撤回，城主在目标城「本城军团驻军」中遣返。已驻防编队所在城市存在活动战斗时禁止撤回和遣返。出发和抵达均检查军团身份与原接收城主；抵达时权限失效，部队携带未交付物资返程，已驻防部队则由后台检查并自动返程，交战中的编队先完成该场结算。撤军不收回已交付物资。援军不生成敌军来袭告警，也不能通过支援行军进入进攻战术会话。

详细动作对照、状态转换、接口和验证范围见 [同军团物资运输与驻防](GUILD_SUPPORT.md)。

## 玩家城市接管与敌将俘虏（2026-10-08）

### 接管条件与资产归属

真实玩家城征服战须在35回合内清除本场守军、援军及工事，耗尽墙体生命且攻方存活才获胜。无参战守军及工事但有墙时直接进入攻墙阶段；0级墙在清军后可胜利。最后一组守方被清除时，射程内余伤继续攻墙，本回合尚未行动兵种使用自身原额度；不重置坐标或技能周期，不追加攻击或机动。破墙不拆楼、不降低等级；只有最终胜利才进行下述接管与俘虏结算，规则见 [破墙设计](CONQUEST_WALL_BREACH_DESIGN_20261013.md)。

对真实玩家城市进行开启占领的讨伐并获胜后，先完成伤兵、声望和民心结算，再判断接管：敌城民心为 0，且我方现有城市数小于当前军衔城市上限时，立即将该城转为我方分城。主城、分城和建设中的城市均计入我方名额；声望达标但尚未晋升不增加名额。守方败战民心减 2、最低为 0，因此战前民心为 2 的城市可在本次胜利结算后接管。关闭占领和败战不触发接管。

| 资产 | 接管后的处理 |
| --- | --- |
| 城市 ID、坐标、名称、建筑等级、建设队列、人口及经济设置 | 随城保留，城市状态重置为和平 |
| 普通资源及黄金 | 留在接管城内，不重复计入返城战利品；未售出的市场委托下架，托管资源归还该城 |
| 原城军官及其装备、驻军、城防、伤兵、征兵和科研队列、军校候选、出发行军及其战斗会话、该城派出的野地驻军 | 清除；符合俘虏条件的参战指挥官先转籍后再清理 |
| 钻石、已完成的账号科技、道具、账号资料及原玩家其他城市资产 | 仍属于原玩家 |

不满足接管条件时，城市归属保留，按开启占领的讨伐规则夺取普通资源，并在双方战报中记录未接管原因。接管、俘虏和主城恢复与本场战斗共用事务，事务提交成功后才推送结果。

### 俘虏与参谋部

开启占领的讨伐获胜时，实际参战的玩家守城指挥官忠诚为 0，则连同装备转入我方出发城市的参谋部待命。俘虏条件独立于接管资格，城市名额已满或敌城民心未归零时仍可俘虏；NPC、野地、关闭占领和败战不触发玩家敌将转籍。

俘虏保留原 ID、姓名、星级、等级、经验、全部属性、技能、装备及装备属性、培养点、履历、俸禄和时间记录，仅改变所属玩家、城市序号及职务（`idle`）。忠诚仍为 0，可通过赏赐培养；我方现任指挥官不会被自动替换。开战时固定参战军官 ID，战中更换任命不会改为俘虏新任军官。原玩家失去该军官及装备的操作权限。

### 主城失守与恢复

失守分城正在被选择时，原玩家切回主城。主城失守且仍有其他城市时，优先提升一座已建成分城为主城；只有建设中的分城时，选第一座并使其可用。提升时将该城资产、行军、野地驻军和市场委托引用迁移到主城序号 0，原账号钻石钱包保留。

最后一座城市失守时，在未占用的完整 2×2 陆地生成“重建主城”：市政厅、民居、农场、冶炼厂各 1 级，平民 150，粮食 2,000、钢铁 3,000、石油 1,000、稀矿 200、黄金 1,000。新城无军队和军官；原账号军衔、声望、科技、钻石和道具保留。主城恢复时结束原玩家的个人战争状态。

### 战报与城市上下文

攻守双方均保存本场战报，接管结果与实际被俘将领分别记录；玩家接管和俘虏任务仅按真实结果累计。`city_ownership` 事件使客户端清除旧城市请求上下文，刷新地图与游戏状态；断线重连先清除旧 `X-City-Id` 再读取账号当前城市，避免失守城的鉴权失败阻断刷新。

2026-10-11 起，新战报的「战果结算」增加「敌军城市民心变化」，显示带正负号的实际变化值及战后民心，例如 `-2，战后 68`。攻方看到守方被攻击城市，守方看到攻方出发城市；本方民心继续独立展示。胜方民心加 1、守城失败减 2、进攻失败不变，战后数值限制在 0～100，战报变化值为实际战后值减战前值。双方民心随本场战报保存，后续自然恢复、切城、接管或主城重建不改写快照；旧战报及没有敌军城市民心数据的 NPC、野地或未知来源来袭战报不显示该项，也不补算为 0。字段协议和边界示例见 [战报中的城市民心](PLAYER_CITY_CONQUEST.md#战报中的城市民心)。

其他城市已派出但尚未送达失守城的运输、调遣或军团驻防，携带原部队与物资返程；其他玩家已驻防的援军先按开战快照结算损失，幸存者随后自动返回原派兵城市，不转籍给新城主。排队攻击在开战及手动打开战场时重新校验归属和战争资格，不能攻击刚被己方接管的城市。实现细节见 [玩家城市接管与敌将俘虏](PLAYER_CITY_CONQUEST.md)。

## 带兵上限与出城迎战（2026-09-27）

新玩家默认列兵（第 1 阶），基础出兵上限为 25,000，上尉及以下每阶增加 25,000。少校为 300,000，此后每晋升一阶增加 50,000：中校 350,000、上校 400,000、大校 450,000、少将 500,000、中将 550,000、上将 600,000。保留现有 17 阶军衔及城市解锁规则，基础上限最高为 600,000。已有玩家按当前军衔实时重算，不修改军衔或驻军数量。

主动攻击上限为 floor(军衔基础上限 × (1 + 0.04 × 三军统帅等级))。2026-10-12 删除城防满级额外带兵100,000；指挥官三军统帅最高 Lv.5，旧 supply 技能仍兼容。城防、市政厅、参谋部和指挥官等级不直接增加容量。最高军衔和满级技能的攻击上限为720,000。

出城迎战上限等价于「攻击上限 + 军衔基础上限 / 2」；1.5倍不放大统帅技能加成，同样满加成时迎战上限为1,020,000。无加成列兵攻击上限25,000、迎战上限37,500。前端展示与服务端校验使用相同公式。城防射程与容量改造提案见[城防武器设计](CITY_FORTIFICATION_DESIGN_20261012.md)。

战术页面可按兵种保存迎战数量，配置随账号持久化，在线指挥和离线防守共用。默认自动选兵，按被攻击城市驻军比例分配至迎战上限；手动配置的缺省兵种视为 0，全部为 0 时仅工事参战。保存时拒绝负数、小数、未知兵种及超过当前城市上限的编队。开战时按被攻击城市实际驻军截断，若因换城或加成变化超限，则按比例缩减并按兵种 ID 顺序分配整数余数。工事不占迎战名额，战术预设沿用守城行动；普通战损只扣实际参战损失，未参战驻军与新增驻军保留。城市被接管时按接管规则清除原城全部军事资产。

军团驻防计入开战时可用的迎战兵力，本城与援军合计共用同一个迎战上限，不能按派兵人数叠加上限。参战数量先按兵种选定，再在城主和各驻防编队间按数量比例分配；损失沿用这份快照分摊，外来援军的归属及返程按军团支援规则处理。

战术页将迎战数量与攻守默认行动合并到同一兵种条目，顶部统一显示上限、选兵模式和数量汇总，详细规则可折叠查看。关闭自动选兵后，每个兵种通过滑动条或数字输入设置出城迎战数量，两者即时同步。单兵种可选上限取「本兵种驻军」与「迎战总上限减去其他已选兵种数量」中的较小值；每次调整即时更新其他兵种上限、已选总量及剩余额度，超额输入自动截断。因此即使驻军有 1,000,000，防守上限为 400,000 时，所有兵种合计也不能超过 400,000。打开共享预设或驻军、容量变化时，仅将本地草稿按实际驻军和上限调整并提示保存，不自动覆盖账号预设；若变化发生在保存前，则同步调整表单并在本次点击中保存。

Flyway V55 新增账号级 sortie_army，null 表示自动选兵，不重置已有驻军及攻守战术。既有战斗会话沿用开战快照，新配置从下一场战斗生效。

## 地图渲染与地表瓦片优化（2026-10-01）

针对初次进入世界地图或跳转指定坐标时出现的地表镂空方块、渲染闪烁和帧率卡顿问题进行了深度优化：
1. **阻断区块加载连锁重绘风暴**：过去区块数据返回触发 `MapTerrain.updateChunk` 时，误在 `draw()` 中同步重绘 2048×2048 像素的全球微观底图（单次冻结主线程约 200ms）并销毁清空全视口所有已生成的地表瓦片（`groundTiles`），导致多个区块并发返回时连续雪崩重置。优化后，大地图静态全局底图与小地图底图仅在初始化或世界尺寸变更时构建一次，禁止在普通区块到达时销毁已渲染地表。
2. **中心扩散优先级渲染（Center-Outward Priority）**：地表瓦片生成由过去固定从左上到右下的行优先遍历，改为按与当前相机焦点 `(camera.x, camera.y)` 的距离升序排列。定位跳转或首屏打开时，正中央视野核心瓦片在首帧第一批生成，杜绝玩家视线中心出现镂空。
3. **自适应时间预算与容量扩容**：瓦片单帧生成预算由硬编码 2 个改为自适应调度（静止状态单帧生成上限提升至 6 个，拖拽中限制为 2 个保持流畅度，同时增加 12ms 帧时间硬阈值截断），视口瓦片缓存上限由 48 个提升至 128 个以上，有效避免短距离往返滑动时的频繁销毁与重复计算。
4. **地表着色与海陆采样零 GC 优化**：在 `map-ocean.js` 与 `map-terrain.js` 中将高频调用的沙滩、浅海、深海及雪地调色板提取到模块作用域，消除单瓦片数十万次像素循环中的瞬时数组对象创建，大幅降低垃圾回收（GC）暂停开销。

## 地图边界越界滑动与边境野地覆盖（2026-10-01）

针对玩家城市位于世界地图边缘时无法将其拖拽居中、视野受限的问题，实现了边界延伸机制：
1. **相机越界滑动（Camera Overflow）**：视口相机支持最多向外滑动 4 格（`Camera.overflow = 4`）。当拖拽到世界边界边缘时，相机中心允许继续外滑，使得位于地图四周边境上的城市（包括 `(0, 0)`、`(199, 199)` 等极限边角）均可平滑拖动至视口屏幕正中心。
2. **非资源野地确定性随机排列与海岛专属森林（Non-Resource Wild Permutation & Island Forests）**：
   - **海岛区域（Islands）**：离岸海岛越界部分仅生成**森林模型**（`wild-forest`），排除沼泽、丘陵、草地和岩石，保持狭长海岛地貌整洁与纯净，视口地形指示器显示“边境森林 · 无法通行”。
3. **海洋海域与北方雪原自然留空（Ocean & Snow Exclusion）**：
   - **海洋海域**：在 `map-ocean.js` 中新增 `G.MapOcean.isOcean(x, y)` 边界海域探测算法：超出世界范围但邻接深海/浅海的格子判定为海面。在海面区域**不放置任何野地模型**，保留纯净连绵的海水底色，视口指示器显示“边境海域 · 无法通行”。
   - **北方雪原**：北纬雪线以上越界区域（`northernSnow > 0.15`，包括 `y < 0` 的整个北边界）**同样不放置任何野地图标**，保持一望无际的极地纯净白雪底色，视口指示器显示“边境雪原 · 无法通行”。
4. **交互与图层安全隔离**：
   - 边境模型统一挂载于 `this.terrain` 下的独立层 `borderForestLayer`，保持 `app.stage.addChild(...)` 10 个主图层签名不变，且位于 `markerLayer`（玩家城池与实体据点）之下，确保边缘城市始终自然叠在野地模型上方不被遮挡。
   - 图层设置 `eventMode = 'none'` 且 `sortableChildren = true`（按 `x + y` 深度升序排布），点击边境不触发任何交互或宣战弹窗，陆地视口地形指示器明确提示“边境野地 · 无法通行”。

针对战术战争沙盘体验与沉浸感，游戏建立了基于 Web Audio API 与高品质无损实录音频（PCM WAV）的双模态音效架构，彻底取代早期 8-bit/16-bit 芯片合成音（避免卡通与街机廉价感），全面确立严肃、写实的军事与机械工业声学风格：

### 1. 全局设置联动与静音控制
- **设置入口**：设置面板提供【音效开关】（开启/关闭）与【反馈音量】滑动条（0%～100%），偏好自动持久化于客户端。
