# 战争动员令（2026-10-28 更新）

动员令改为仓库确认启用的账号限时增益，覆盖全部城市的新出征行军和本城防守。旧版“单次进攻超过普通上限时消耗1张”的规则已取消。

| 道具 | 带兵上限增幅 | 每张时长 | 单价（钻石） |
| --- | ---: | ---: | ---: |
| 战争动员令 | 10% | 24小时 | 80 |
| 高级战争动员令 | 25% | 24小时 | 220 |
| 极速战争动员令 | 50% | 24小时 | 500 |

极速表示最高动员等级，不额外提高行军速度。保留现有价格及库存，道具不自动激活或折算。

## 时长、容量与范围

- 同档到期时间 = max(当前服务端游戏时间, 原到期时间) + 使用张数 × 24小时。可批量使用1～10000张，不能超过库存。
- 三档分别计时，当前只取未到期的最高加成；被覆盖档位仍正常计时。低档不会为高档续时，增幅不相加。
- 最终上限 = floor(普通上限 × (100 + 当前最高动员百分比) / 100)。普通上限 = floor(军衔基础 × (1 + 0.04 × 本城三军统帅等级))。每城保留自己的指挥官加成。
- 生效范围包括进攻、侦查、拦截、采集、进驻、运输、调遣、援军等新行军以及本城迎战；仍需满足兵种、库存、路线、负重和补给限制。工事不占本城迎战容量，外来援军不受城主动员二次放大。
- 已出征部队不因增益到期而减兵或强制返城。防守以开战时选兵结果冻结快照；已开始战斗不因动员开启、降档或结束而增减兵。
- 增益存于账号，离线期间按服务端游戏时钟计时。重启后持久化状态保留；服务器全局活动时钟的停服补偿规则与其他活动一致。

## 默认与动员防守编队

`sortie_army` 为长期默认迎战数量；`mobilization_sortie_army` 为本轮动员迎战数量，二者均保留 null（自动选兵）与空对象（零兵力）的区别。

首次启用且此前所有动员均已结束时，复制默认编队作为新的动员编队并增加周期号；同档续期及高低档切换不重新复制。动员期间保存只更新动员编队。全部到期后直接读取原默认编队，不能把临时编队按比例缩减后写入默认配置。下一轮动员重新从默认编队复制。

攻守兵种默认行动为两套编队共用，临时隔离的是迎战数量。有效配置仍受实际驻军和当前容量约束。降档后超额配置在选兵时缩减，不改数据库中保存的原数量。

战术保存携带 `formationKey`（default 或 mobilization:周期号）。服务端在账号锁下核对当前配置，拒绝跨周期、过期或尚未加载动员状态的草稿，避免跨设备和到期瞬间误覆盖。进攻行军或战斗期间保留既有战术锁定规则。

## 玩家操作与倒计时

仓库点击道具后展示确认弹窗：加成、数量、每张24小时、当前本档剩余、新增时长、使用后剩余及预计结束时间、当前城容量变化、生效范围，以及低档被覆盖提醒。取消不扣道具；确认后立即生效，库存、时长和复制编队在同一事务提交。

指挥官档案、战术配置、仓库均显示最高档位、加成、分钟级剩余时间及北京时间结束时间。多档并存时可展开查看其他档位并标注被覆盖。倒计时不足一分钟时显示“不足1分钟”；到期状态精确判断，不等待下一分钟。页面重新可见时刷新服务端状态。

战术界面明确展示当前编辑默认或动员防守编队，并提示全部到期自动恢复默认编队。到期或新周期时丢弃旧临时草稿并重新加载对应配置。出征页面移除选道具入口，显示账号状态和最终容量，出征不扣令。

跨设备启用或动员到期时，如果战术接口返回的配置周期与本地账号状态不一致，先强制刷新账号状态，再重读一次战术配置；仍不一致则提示重试，不展示或保存旧草稿。切换账号或城市后丢弃此前尚未完成的战术加载响应。

## 持久化与兼容

V138 为 players 增加动员到期时间、临时编队与周期字段，并新增使用回执表。旧账号默认无增益，原防守编队保持不变。重复确认使用相同 requestId 只扣一次；不同操作不能复用同一标识；账号锁保证并发续时无丢失。旧页面携带 mobilizationOrderItem 的出征请求明确拒绝并提示刷新。

当前编队战力估算计入动员后的潜在容量；综合实力仍按实际军事和培养资产估值，不凭空增加库存。对战保存与新入队使用统一容量校验，已入队快照沿用既有冻结规则。
