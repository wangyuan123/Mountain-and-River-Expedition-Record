# 战争动员令（2026-10-30 更新）

动员令改为仓库确认启用的账号限时增益，覆盖全部城市的新出征行军；守城全员参战，不受带兵上限限制。旧版“单次进攻超过普通上限时消耗1张”的规则已取消。

| 道具 | 带兵上限增幅 | 每张时长 | 单价（钻石） |
| --- | ---: | ---: | ---: |
| 战争动员令 | 10% | 24小时 | 80 |
| 高级战争动员令 | 25% | 24小时 | 220 |
| 极速战争动员令 | 50% | 24小时 | 500 |

极速表示最高动员等级，不额外提高行军速度。保留现有价格及库存，道具不自动激活或折算。

## 时长、容量与范围

- 同档到期时间 = max(当前服务端游戏时间, 原到期时间) + 使用张数 × 24小时。可批量使用1～10000张，不能超过库存。
- 三档分别计时，当前只取未到期的最高加成；被覆盖档位仍正常计时。低档不会为高档续时，增幅不相加。
- 最终上限 = floor(普通上限 × (100 + 当前最高动员百分比) / 100)。普通上限 = floor(军衔基础 × (1 + 0.04 × 本城三军统帅等级))。每城保留自己的指挥官加成。
- 生效范围包括进攻、侦查、拦截、采集、进驻、运输、调遣、援军等新行军；仍需满足兵种、库存、路线、负重和补给限制。本城和已抵达的有效援军守城时均全量参战，不受城主动员二次放大或裁剪。
- 已出征部队不因增益到期而减兵或强制返城。防守以开战时选兵结果冻结快照；已开始战斗不因动员开启、降档或结束而增减兵。
- 增益存于账号，离线期间按服务端游戏时钟计时。重启后持久化状态保留；服务器全局活动时钟的停服补偿规则与其他活动一致。

## 守城全员与默认行动

2026-10-30取消默认和动员迎战数量配置。守城时冻结本城全部可战兵力与已到达的有效援军，忽略旧 `sortie_army`、`mobilization_sortie_army`；动员不再复制或切换这些预设。守城快照不因后续增益启停或新兵抵达而增减兵。

攻守兵种默认行动仍保存为账号两套指令，动员启停不会清除未保存的行动草稿。新客户端只提交两套行动；服务端兼容但忽略旧请求的数量与周期字段，不再因动员到期拒绝保存行动。进攻行军或战斗期间保留既有战术锁定规则。

## 玩家操作与倒计时

仓库点击道具后展示确认弹窗：加成、数量、每张24小时、当前本档剩余、新增时长、使用后剩余及预计结束时间、当前城容量变化、生效范围，以及低档被覆盖提醒。取消不扣道具；确认后立即生效，库存、时长和周期在同一事务提交。

指挥官档案、仓库显示最高档位、加成、分钟级剩余时间及北京时间结束时间。多档并存时可展开查看其他档位并标注被覆盖。倒计时不足一分钟时显示“不足1分钟”；到期状态精确判断，不等待下一分钟。页面重新可见时刷新服务端状态。

战术界面直接展示“守城不受带兵上限限制，出征受带兵上限限制”及当前出征容量。动员启停只更新容量说明；切换账号或城市时丢弃旧请求响应。出征页面显示账号增益和最终出征容量，出征不扣令。

## 持久化与兼容

V138 为 players 增加动员到期时间、临时编队与周期字段，并新增使用回执表。旧账号默认无增益，历史防守数量预设字段保留但不再生效。重复确认使用相同 requestId 只扣一次；不同操作不能复用同一标识；账号锁保证并发续时无丢失。旧页面携带 mobilizationOrderItem 的出征请求明确拒绝并提示刷新。

当前编队战力估算计入动员后的潜在容量；综合实力仍按实际军事和培养资产估值，不凭空增加库存。对战保存与新入队使用统一容量校验，已入队快照沿用既有冻结规则。
