# 实名与防沉迷实施说明

更新：2026-09-17。当前是可运行、可测试的核心控制实现，尚未完成国家实名平台接入及公众运营验收。法规依据和完整目标见 [设计文档](ANTI_ADDICTION_DESIGN.md)。

## 暂停与恢复

按当前产品安排，防沉迷默认关闭。注册、登录不再要求实名或受游戏时段限制；游戏内入口、倒计时与心跳停用，登录页说明已注释。HTTP/WebSocket 仍保留原有账号鉴权。此前尚未初始化角色的账号会在进入游戏时补建角色。

原有实现、测试及 V36 数据结构保留，未删除身份和存档。暂停期间不执行防沉迷会话维护，新伤兵使用普通期限；已有伤兵期限不回写。模拟充值沿用原有关闭防沉迷时的行为，真实支付尚未接通。

临时验收可设置 `WARGAME_COMPLIANCE_ENABLED=true` 并重启后端。产品完善后正式恢复时：

1. 将 `ComplianceProperties.enabled`、`application.yml`、`.env.example` 和 `docker-compose.yml` 中的默认值恢复为 `true`，同步实际部署环境变量。
2. 取消 `ComplianceConfig.complianceStartupCheck` 中禁止关闭的两行注释。
3. 取消 `frontend/js/main-view.js` 登录页说明与入口的注释，恢复 `frontend/js/core.js` 登录副标题。游戏内入口和计时会自动跟随服务端开关。
4. 配置核验服务、身份密钥及开放日历，运行前后端测试并重新部署。

## 启用后的行为

- 新注册账号先获得账号凭据，通过可信身份核验与游戏许可后才创建角色、城市和资产。旧存档保留，但再次进入也须核验。游客入口关闭。
- 未满 18 周岁按北京时间的开放日 20:00（含）至 21:00（不含）准入。审核日历未覆盖、身份过期、账本故障均不放行；18 岁转换按可信生日计算。
- 同一身份的多账号共享每日用时，只能有一个活动游戏会话；同账号标签页复用会话。显式进入可替换旧设备，心跳失效不会自动抢回。20 秒心跳、60 秒租约；断网最多计到租约末尾。换设备、进程重启、注销后同日再注册均不重置当日用时。
- 游戏 HTTP 操作在玩家锁后取得主体锁，操作前和提交前检查许可。WebSocket 握手、心跳、推送和定时检查均校验许可；4003 表示游戏许可结束，401/4001 表示账号登录失效。
- 休息页清除游戏状态并拒绝旧请求结果，保留实名、申诉、家长监护、注销和退出等账号服务。浏览器倒计时基于服务端时间与单调时钟。
- 已核验成年监护人可以管理已确认关系的儿童：暂停、每日 0–60 分钟、20:00–21:00 内的更早截止、聊天/消息发送限制。未满 14 岁缺少可信监护授权不绑定身份。客户端不能自行建立监护关系。
- 正常 PvE、PvP、宣战、攻城、军团和第四章任务保留。到点停止玩家服务，后台行军与战争按原规则继续；没有新增 PvE 专属限制或离线免战保护。
- 真实支付保持关闭；防沉迷开启时模拟充值接口也返回 `PAYMENT_DISABLED`。游戏正常产出的免费钻石仍可按原玩法使用。
- 新生成的未成年人伤兵：在已有审核日历覆盖时，将 7 天原期限延至其后首个开放窗口末尾，并保存最终期限。查询、救治、到期清理共用该字段。**尚未补算核验前的旧批次、缺少未来日历时生成的批次**，运营日历必须提前覆盖留存期限；这部分不能视为完整期限保护验收。

## 配置与开发

当前默认 `game.compliance.enabled=false`，可通过 `WARGAME_COMPLIANCE_ENABLED` 覆盖。禁止关闭的启动检查已暂时注释；`prod` 仍禁止虚构测试身份。

| 环境变量 | 含义 |
| --- | --- |
| `WARGAME_COMPLIANCE_ENABLED` | 当前默认 `false`；设为 `true` 恢复控制 |
| `WARGAME_COMPLIANCE_DATA_KEY` | Base64 编码的 32 字节随机密钥，用于身份 HMAC 和生日 AES-GCM；所有实例一致 |
| `WARGAME_PLAY_CALENDAR_FROM` / `THROUGH` | 已审核日期覆盖区间，`YYYY-MM-DD` |
| `WARGAME_PLAY_CALENDAR_SOURCE` | 审核依据或内部审核记录编号 |
| `WARGAME_PLAY_EXTRA_OPEN_DATES` | 逗号分隔的额外开放日期 |
| `WARGAME_PLAY_CLOSED_DATES` | 逗号分隔的关闭日期，优先于周末与额外开放日 |
| `WARGAME_SUPPORT_URL` | 运营方 HTTPS 客服地址 |

覆盖区间内周五、六、日为基础开放日，法定节假日及特殊排期须通过审核后的增减日期配置。寒暑假不自动开放。当前日历通过部署配置发布；没有自动节假日抓取、审批后台或覆盖期告警。空配置默认关闭未成年人准入。各实例配置和系统时间必须一致。

密钥生成：`openssl rand -base64 32`。密钥不提交仓库，使用密钥管理系统注入；直接更换将导致旧数据无法解密、身份摘要改变，轮换必须先设计数据迁移。测试身份的固定开发密钥不能用于真实数据。

使用独立开发数据库，然后运行：

```sh
WARGAME_COMPLIANCE_ENABLED=true JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8 mvn -f backend/pom.xml spring-boot:run -Dspring-boot.run.profiles=local
python3 -m http.server 8081 --bind 127.0.0.1 --directory frontend
```

`local` 后端仅监听 `127.0.0.1`；禁止通过反向代理向公网提供该配置。注册后输入 `DEMO-ADULT`（成年人）、`DEMO-PARENT`（家长）、`DEMO-TEEN`（2010 年出生）、`DEMO-CHILD`（2016 年出生）。后两者的虚构监护人均为 `DEMO-PARENT`。测试结果有效期 24 小时；同一个测试身份会共享时长与监护设置。测试日历只有周五六日基础规则，不能作为真实运营排期。

## 正式核验适配

实现 Spring Bean `RealNameProvider` 替换默认不可用提供者。本接口是项目内的适配边界，**不是臆造的国家平台 HTTP 协议**。没有正式文档和接入凭据时，核验返回 503，不把身份证格式验证、年龄输入或测试凭据当作成功。

适配器须负责正式系统鉴权、结果验签、短期凭据与账号绑定、防重放、幂等查单、特殊证件路径、可信主体标识/生日/有效期及监护证据。原始证件信息应在完成必要告知的核验流程中处理；游戏页面只提交核验服务凭据。本版本没有异步 `PENDING` 流水查询、监管上下线报送及失败补偿，也没有正式的监护材料审核服务；这些需要依实际平台契约实现并联调后才能发布。

## API 与存储

账号 API 使用现有 JWT；游戏 HTTP 另需 `X-Play-Session`，WebSocket 使用 `playSession` 查询参数。代理日志必须去掉 WebSocket 查询参数与凭据请求体。

| API | 用途 |
| --- | --- |
| `GET /api/anti-addiction/status`、`/api/identity/status` | 脱敏身份、许可及服务端时间 |
| `POST /api/identity/verify` | `{proof}` 兑换可信结果 |
| `POST /api/play-sessions` | `{sessionSecret}` 开始；客户端生成 32–80 字符随机秘密 |
| `POST /api/play-sessions/heartbeat`、`/end` | 续租或结束；只认该账号自己的秘密 |
| `GET /api/guardian/children` | 已确认关系的账号与必要用时汇总 |
| `POST /api/guardian/restrictions` | `{playerId,dailyLimitSeconds,endMinute,paused,chatAllowed}` |
| `GET/POST /api/protection/requests` | 最近 20 条申请/按 UUID 幂等登记 `{kind,requestId}` |

申请类型：`IDENTITY`、`GUARDIAN`、`REFUND`、`PRIVACY`、`REPORT`。登记仅产生 `RECEIVED` 工单，不会自动更正身份、绑定关系或退钱；目前没有处理后台、审核通知和时效保障。运营接入时应由受限服务读取待办队列，按申请编号通过安全客服渠道核验材料，保存处理审计后标记 `RESOLVED`。身份更正需事务性迁移关联、保留应计用时并撤销旧会话，不能让客服直接改生日字段。

Flyway `V36` 新增六张表及 `players.game_initialized`；旧玩家默认已初始化，不重建存档。真实姓名/身份证号不入表，生日加密、主体 ID 带密钥摘要、会话秘密只存哈希。审计仅记录账号、事件、时间和策略版本。

每分钟维护失联会话，默认清理 30 天前会话/日用时和 180 天前事件/已解决申请。账号最终注销清除关联与会话，审计去掉玩家 ID；无剩余账号关联的主体与账本次日清理，防止同日重注册清零。仍有其他绑定账号时主体继续保留。以上是开发默认期限，正式期限、法律留存及备份清除须由运营政策确定。

## 验证与发布边界

```sh
node --test frontend/tests/*.test.cjs
JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8 mvn -f backend/pom.xml test
```

启用实现时的历史全量结果：前端 142 项通过；后端 232 项中 231 项通过、1 项 MySQL 专用迁移测试未配置独立库而跳过。包含未实名 HTTP 准入、出生年龄/时间等号、监护收紧、同主体并发换会话、退出计时、旧 JWT 版本、儿童授权、正式提供者不可用、prod 虚构身份拒绝、WebSocket 截断/聊天限制、存档迁移保留和前端迟到请求隔离。H2 迁移测试通过不替代 MySQL 迁移测试；多实例运行仍须在真实部署拓扑压测与演练。

另在独立 H2 内存库与本机浏览器验证：新注册停留实名页、成年人核验后初始化城市并建立 WebSocket、主动离开清除游戏画面、儿童在周四被拒绝且显示周五 20:00 的下次窗口。验收未连接用户的游戏数据库。

发布前仍须落实正式核验/报送接口、运营与出版主体/资质、审核后的适龄提示、完整隐私与儿童政策、监护审核与投诉退款流程、聊天举报/屏蔽处置、实名异常复核、日历审批与告警、审计和年度报告。`privacy.html` 明确是开发说明，不能替代正式隐私政策；没有将这些未完成事项标记为已合规。
