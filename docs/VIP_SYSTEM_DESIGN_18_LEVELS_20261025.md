## 一、产品定位与边界

充值购买钻石，钻石按商城规则购买加速符等商品；VIP奖励支持者身份、个性化、外观收藏和每日补给。不重复出售永久效率倍率。

VIP会员不是实际军衔、指挥权限或战绩，不以向真实军队、历史组织捐款为包装，也不暗示款项用于公益或真实军备。

### 1.1 保留与取消

| 保留 | 不设置 |
| --- | --- |
| 专属头像、头像框、气泡、名片、称号、军旗外观 | 建筑／科研永久提速、资源永久增产 |
| 指挥官与军官改名卡、外观兑换券 | VIP专属并行建筑／科研／征兵／出征队列 |
| 自定义头像、外观搭配、个人收藏展示 | 攻防血、射程、先手、技能、装备属性加成 |
| 每日定量粮食、钢铁、石油、稀矿、黄金 | 行军速度、额外侦察、预警提前、地图情报权限 |
| 同等级可预览、可追溯的固定奖励 | 治疗提速、床位扩充、伤亡减免、招募概率提升 |

### 1.2 对公平的准确表述

- 同兵力、科技、军官、装备及战术条件下，VIP身份不改变战斗计算，也不突破免费玩家的玩法和成长上限。
- 每日资源和黄金会间接加快征兵、养成和战后恢复，因此不能宣传为“完全不影响战争胜负”。
- 当前黄金已用于伤兵治疗和装备培养，不能把黄金认定为纯内政货币。数量需要纳入军事恢复与养成测算。
- 充值购加速符已有进度优势；新VIP资源补给、升级礼、活动、商城和未来订阅必须合并测算，不能各自孤立判断平衡。
- 外观不改变城市占地、阵营颜色、兵种识别、雷达覆盖、敌我标识或告警；战场保持中立轮廓。

### 4.2 领取规则

1. 按Asia/Shanghai自然日，每日00:00刷新。主城主页与VIP中心均显示完整当日礼包和领取状态。
2. 账号每日仅有一份资格，不按城市、军团、登录次数或充值订单数倍增；每日福利无需再次充值激活。
3. 默认主城收取，领取前允许选择一座自己已建成且可用的城市；五种经济资源必须发到同一城市，不能重复分发，外观券记账号。
4. 发奖前先按既有机制结算目标城资源；资格校验、收取城市归属校验、发奖和领取记录在同一事务内完成。
5. 入城后均为普通资源：沿用实际存储上限、溢出、掠夺、运输、征服和消费规则，不增加VIP保仓或特殊受保护钱包；界面提前提示可能的溢出处理。外观券不可交易不代表经济资源不可转移。
6. 基础方案为手动领取，当日未领取不累计、不消耗钻石补签、不要求连续签到。停服导致整日无法领取的补偿统一处理，不制造付费补领。
7. 当日已领取后升级，只允许补领本日已领取向量与新等级礼包向量的逐项正差额；不能重新领整包。记录当日已发实际数量，重复／并发补领不能重复发。
8. 领取记录以账号和自然日唯一；升级礼以账号和等级唯一。跨级达到VIP6时，可领取未领的1至6级升级礼，每日只按VIP6一包。
9. 配置更新不追溯扩大已领礼包；同日升级沿用该日首次领取锁定的奖励配置版本，次日使用新版本。首日未领取者在首次领取时锁定当日适用版本。
10. VIP中心区分“升级礼”“今日补给”“永久外观”；不能把一次性奖励包装成每日奖励，也不能将累计充值门槛写成再次付费购买礼包。

## 五、经济验收与防滥用

- 比较VIP0／1／6／12／18在7、30、90天的奖励总量、净资源收益、科技进度、征兵量、军官／装备培养与战损恢复。
- 黄金重点对照伤兵治疗、装备培养、军官薪饷和黄金税收，不能只看建筑费用。
- 测试新手与成熟账号、单城与多城、相同活跃度及高活跃度；不允许用多城数量乘每日包。
- 将商城购买与VIP每日包叠加测算，评估新手阶段固定奖励是否压过正常生产；若偏大优先下调初值，不临时引入付费战斗修正。
- 以当前源码的实际生产、税收、消费和可用队列为基线；未实施的城市双科研队列不能作为现状。
- 每日奖励和转移后资源可能被多账号集中，需测试军团运输／掠夺汇聚，纳入现有反滥用机制；不以此悄悄改变全体玩家资源流转规则。
- 外观券单独核算投放和兑换，检查30／90天的可兑换内容，避免高等级投放远超可用内容。
- 不宣称存在已经验证的“安全日收益比例”。具体可接受差距、各等级金额和奖励量经测算评审后再冻结。

## 六、后续实现要求（本次不实施代码）

### 6.1 支付、金额与资格

- 当前模拟发钻不是实付订单，不能计入正式VIP账本。测试VIP只允许隔离测试数据，不能转为正式充值记录。
- 正式VIP只接收经过验签、订单核对及金额校验的成功支付事件；订单唯一键和事务保证钻石、有效实付金额及VIP资格不因重复回调重复增加。
- 模拟接口开关、正式支付开放条件、退款与拒付策略单独评审；本稿不授权开放真实支付或修改现有准入限制。
- 退款事件幂等冲减有效金额并重算等级，待领礼包及未来每日包按调整后等级；已消费资源、已领卡券与已解锁外观的追偿／保留政策须在上线前明确并对用户公开，不能用“终身VIP”承诺掩盖例外。
- 不预占固定Flyway迁移编号，实施时检查当前迁移目录并使用未占用的下一个编号。

### 6.2 配置与数据

- 服务端唯一权威配置包含18级门槛、升级礼、六项每日奖励、永久外观与功能权限，以及配置版本。
- 客户端读取服务端等级、可领数量、主题资产和领取状态，不自行决定资格、门槛、奖励数量或外观授权。
- 持久化支付事件、升级礼领取、每日已发向量和配置版本、外观库存与当前佩戴；不以单个最后领取日期替代差额发奖记录。
- 每日金额使用整数，避免资源溢出与整数越界；事务回滚时不遗留“已领取但未发奖”或“已发奖但可再次领取”。
- VIP模块不接入战斗、军事侦察、生产速度、并行队列、概率或治疗倍率计算；正常资源消费仍按既有玩法执行。
