# 军官十二件套与整套装备箱扩充设计

日期：2026-10-23。状态：已完成代码实现与自动化验证，尚未部署到运行服。当前生效配置源为 `backend/src/main/resources/officer-equipment.json`；本文保留数值设计依据，实施记录见第 13 节。

## 1. 核心规则

**一箱给齐一套。每个装备箱打开后，一次发放对应档次、对应分支的十二个不同部位，各一件。** 不拆成随机单件箱，不要求再次付费补齐，不用重复件合成整套。

已将三件套扩成十二件套，成长档次由三档扩成六档，保留军事、防御、后勤、学识四个分支：

- 每名军官最多同时穿戴十二件装备，每个部位一件。
- 六档 × 四分支 = 二十四套；二十四套 × 十二件 = 二百八十八件装备。
- 商城展示二十四个整套装备箱，不铺开二百八十八件散件商品。
- 同档同分支按实际穿戴件数，激活三、六、九、十二件四档共鸣。
- 装备开箱即齐；长期目标来自军官等级、部位整备、分支搭配、多军官配装及成就展示。

必须承认：保留一箱给齐后，“拥有整套”仍是即时目标，不能同时宣称它需要长期逐件收集。三、六、九件共鸣是混搭和过渡配装的选择，不是开箱进度。

| 档次 | 十二件单件合计主属性 | 共鸣计入后的主属性 | 另外三项各自合计 |
| --- | --- | --- | --- |
| 列兵 | 24 | 30 | 3 |
| 士官 | 36 | 50 | 6 |
| 校官 | 63 | 87 | 9 |
| 准将 | 78 | 110 | 12 |
| 上将 | 102 | 142 | 12 |
| 元帅 | 117 | 172 | 22 |

例：元帅军事十二件提供军事 `3×30 + 3×4 + 3×2 + 3×3 + 48 + 7 = 172`；其余各项 `3×5 + 7 = 22`。当前元帅三件为军事 +125、其余各项 +20，因此直接补全九个新部位后的主属性增幅为 37.6%，其余各项为 10%。这是装备增益对比，不等于最终战斗伤害同比增加。

以上只是可计算的初始平衡预算，尚未经过实际战斗或经济模拟。上线前必须同时验证带兵将领、司令官及市长：尤其司令官的四维常驻收益，以及学识对研究速度、后勤对经济的影响。

## 6. 混搭的真实选择

十二个部位允许跨分支、跨档次混搭；每个“档次 + 分支”单独计数并结算。推荐界面提供以下模板，但不强制限制玩家自由组合：

| 穿戴组合 | 可激活共鸣 | 用途 |
| --- | --- | --- |
| 12 军事 | 军事 3/6/9/12 | 主攻专精 |
| 9 军事 + 3 防御 | 军事 3/6/9、防御 3 | 主攻兼顾防御 |
| 6 军事 + 6 防御 | 双分支各 3/6 | 攻守均衡 |
| 9 后勤 + 3 学识 | 后勤 3/6/9、学识 3 | 经济发展兼顾科研 |
| 6 后勤 + 6 学识 | 双分支各 3/6 | 内政复合配置 |
| 四分支各 3 | 四分支各 3 | 司令官四维配置 |

这些是配置示例，不预先宣称某种模板在所有场景最优。核心部位预算较高，混搭必须明确选哪些部位；只比较“6+6”字样不足以判断强弱。

同一套装备可以卸下后转给另一名军官，但一件实物不能同时供多名军官穿戴。不加战斗中换装收益，不改变当前军官任职、出征和开战快照规则。

## 7. 长期培养：部位整备 +0～+5

整套开箱负责装备完整性，整备负责持续成长。采用确定性成长，消耗明确、每次成功、不降级、不损毁。

### 7.1 绑定与属性

- 整备等级绑定“账号 + 军官 + 部位”，不绑定某一件可堆叠装备。
- 更换同部位装备、跨分支混搭或升级套装档次时，整备等级保留；不需要从头培养。
- 空部位不提供任何整备属性。有效整备每级为当前装备的分支主属性额外 +1，其余三项不增加；不放大基础属性、共鸣或技能。
- 每档装备有效上限依次为 +1、+2、+3、+4、+5、+5。换低档装备时仅限制实际生效等级，不删除已培养进度。
- 提升至 +1/+2/+3/+4/+5 分别要求该军官等级达到 1/20/40/60/80。可提前培养高于当前装备生效上限的等级，但确认界面必须说明暂未生效的部分。
- 十二个部位全部有效 +5，合计只增加 60 点分支主属性；混搭则按各部位当前分支分别分配。
- 元帅纯分支十二件全 +5 为主属性 +232、其余各项 +22，不另叠加“整备共鸣”或百分比放大。军官自身 219 点上限仍只限制自身加点。
- 卸装不重置整备。解雇已经培养的军官时明确提示将永久失去其整备等级；不通过解雇返还材料，避免刷返还套利。

### 7.2 消耗

仅新增一种材料“军备零件”，使用账号级库存；不按档次或分支再拆多种货币。黄金使用主城黄金账户，与账号级材料一起原子扣减，不随当前查看城市切换。

| 提升 | 本次军备零件 | 本次黄金 | 单部位累计零件 | 单部位累计黄金 |
| --- | --- | --- | --- | --- |
| +0 → +1 | 20 | 1,000 | 20 | 1,000 |
| +1 → +2 | 40 | 2,000 | 60 | 3,000 |
| +2 → +3 | 60 | 3,000 | 120 | 6,000 |
| +3 → +4 | 80 | 4,000 | 200 | 10,000 |
| +4 → +5 | 100 | 5,000 | 300 | 15,000 |

一名军官十二部位从零到全 +5，共需 **3,600 军备零件 + 180,000 黄金**。部位可自由优先培养，不强制按固定顺序点满。

### 7.3 稳定材料来源与节奏

首版已新增“军备日常”任务组：每日下列四项任选三项完成，每项给 40 零件，账号每日最多 120。按已有事件结算，不依靠前端点击次数。

| 日常条件 | 有效事件 |
| --- | --- |
| 完成训练累计 100 名兵员 | 实际训练完成；取消订单不计 |
| 完成一次野地战斗胜利 | 真实出征结算胜利；演习、预览不计 |
| 完成一次有资源实际入账的采集返城 | 返城入账一次计数；派遣、途中撤回不计 |
| 完成一次建筑升级或科技研究 | 队列实际完成；取消、单纯下单不计 |

周常：当周累计领取 15 项军备日常奖励，额外领取 240 零件，每账号每周一次。只有已经领取的日常奖励推进周常，每天最多推进三次。日界线为北京时间 00:00，周界线为周一 00:00；切城、重登、换军官都不重置额度。同一事件不能重复推进同一任务。每项日常每天只能领取一次，最多领取三项；零件不设过期与持有上限。

首版不在商城售卖零件，不允许用买来的完整套装拆解换零件；否则便宜列兵箱会绕过整备节奏。重复箱仍固定给十二件，可分配其他军官，不能自动吞掉重复物品。

在每天三项日常、每七天领取一份周常、黄金和军官等级充足的假设下，单军官全套达到各整备等级的参考活跃日约为：全 +1 两天、全 +2 六天、全 +3 十天、全 +4 十六天、全 +5 二十四天。四名军官全部 +5 共需 14,400 零件和 720,000 黄金，在同一供给假设下约九十四个活跃日；进度可自由分配，并不要求先养满一人。这是上述供给模型的计算示例，不是实测留存，也不是所有玩家的保证工期。主城黄金、任务难度与实际活跃应在试玩后校准。

## 9. 商城、仓库与军官详情交互

### 商城

- 购买即入仓，开箱即给齐；没有开奖、保底、部位自选或碎片补齐流程。

### 仓库

- 整套箱保留在军官道具分类；打开成功后合并展示“获得十二件”，可展开查看每件数量。
- 装备分类支持档次、分支、部位筛选，默认同套聚合，防止二百八十八种装备刷屏。
- 重复装备保留真实库存数量，显示可供多少名军官配装。
- 增加历史获得图鉴，并明确区别于当前持有数和当前穿戴数。

### 军官详情

- 按核心装备、防护穿着、随身军具三组显示十二个部位；使用原主题和组件公开能力，首版不改 CSS 或组件内间距。
- 显示每个“档次 + 分支”的当前件数、已生效共鸣、下档阈值及具体增益。
- 提供单件替换、整套穿戴、整套卸下、配装预览；替换前显示四维净变化。
- 一键穿戴默认从玩家选定的套装取十二件，保留已经穿着的同款，缺件时列出缺件清单并整体失败；不默默穿一半。

### 开箱结果与广播

成功结果返回完整十二件清单，每件都能在库存核对。复用当前开箱广播规则，只在真实成功时产生一次；详情保留完整十二件，不用“等装备”省略奖励。现有广播其他行为按项目当前口径执行。

## 10. 老玩家与旧箱兼容

1. 三十六个旧装备键、三个旧档次 ID、十二个旧箱 ID、旧核心三件属性和旧三件共鸣均保留。
2. 未开旧箱升级为对应十二件整箱，打开固定得到十二件；不补差价，也不要求兑换新箱。
3. 对已经持有旧装备的账号，按“旧档次 + 分支”，分别统计 weapon/badge/coat 在库存及所有军官已穿戴中的总件数，取三者最小值 `n`，补发九个新部位各 `n` 件。单买散件凑齐三件的玩家同样享受补齐。
4. 不要求三个旧部位恰好穿在同一军官身上；数量按账号汇总，但每件旧装备只统计一次。不能证明的已丢失物品不推测恢复；零数量不计。
5. 补发只进库存，不自动穿戴，避免登录即改变军官属性。迁移幂等标记及补发记录按“账号 + 旧套装 + 升级版本”唯一。
6. 迁移在停写窗口内先固定旧持有快照，再发九件并记成功；新箱开箱逻辑与迁移同版本启用，避免新十二件被再次识别为旧套补发。迁移前生成每账号每套 `n` 的预演清单，核对后再执行。
7. 新整备初始均为 +0。图鉴回填旧持有快照和迁移实际奖励；历史已拥有完整旧套装会被认定为对应新版十二件已获得。
8. 新增士官、准将、上将箱不强制兑换旧档装备。二十四箱全部保持一箱十二件契约。

部署前先停写并备份数据库，用下列只读 SQL 导出旧套装补发预演清单；核对后启动新版后端执行 V121。前后端应作为同一版本发布。未对运行服执行迁移或重启。

```sql
WITH owned AS (
    SELECT player_id, item_key, count AS qty FROM player_items WHERE count > 0
    UNION ALL
    SELECT player_id, item_key, 1 AS qty FROM officer_equipment WHERE officer_id IS NOT NULL
), totals AS (
    SELECT player_id, SUBSTRING_INDEX(item_key, '_', 2) AS set_key,
           SUM(CASE WHEN item_key LIKE '%_weapon' THEN qty ELSE 0 END) AS weapons,
           SUM(CASE WHEN item_key LIKE '%_badge' THEN qty ELSE 0 END) AS badges,
           SUM(CASE WHEN item_key LIKE '%_coat' THEN qty ELSE 0 END) AS coats
    FROM owned
    WHERE item_key REGEXP '^(recruit|officer|marshal)_(military|defense|logistics|knowledge)_(weapon|badge|coat)$'
    GROUP BY player_id, SUBSTRING_INDEX(item_key, '_', 2)
)
SELECT player_id, set_key, weapons, badges, coats,
       LEAST(weapons, badges, coats) AS each_new_slot_count,
       9 * LEAST(weapons, badges, coats) AS total_new_items
FROM totals
ORDER BY player_id, set_key;
```
